# 会话内容视图的端到端自检

`test/` 那套断言跑在 node 里、只钉结构与产物；这一页的毛病几乎都出在真实排版上——某一节折起来之
后内容还溢在下面、页头那个"第几条"跟着折叠一起跑偏，都是这样漏过去的。这个 skill 驱动真实 dev GUI
走一遍完整流程，把量到的值打出来。

## 怎么跑

```sh
bash .agents/skills/transcript-e2e/scripts/run.sh [实例地址] [会话行号]
# 默认：http://127.0.0.1:3081、第 5 行（dev 夹具里那份 941 条的会话）
```

前置：dev 实例在跑（`systemctl --user status dsh-web-dev`，`DSH_HOME=~/.dsh-dev`）、`agent-browser` 可
用、容器里要 `AGENT_BROWSER_ARGS=--no-sandbox`（脚本默认已带上）。脚本自己开一个命名会话、跑完关掉；
它**只读**会话库，不碰任何写操作。

脚本做四件事，任何一条不通过就以非零退出：

1. 打开「设置 → 会话管理」，点开指定行那份会话；
2. 反复滚到底，直到卡片数不再增长（内容视图一次 80 条自己往下接）；
3. 跑 `scripts/collect.js`：位次严格递增、`0..总条数-1` 各一次、每节卡片连续、各节加节外等于总数；
4. 跑 `scripts/probe.js`：页头那个数必须等于用 `elementFromPoint` 独立算出的那张卡的位次（滚到中间、
   再折起中心线所在的那一节，各一次）。中心线正好落在两张卡之间时这一态记为 `skipped`。

## dev 夹具的基线（941 条那份会话）

| 量 | 值 |
| --- | --- |
| 总事件 / 卡片 | 941（位次 0..940，每个一次） |
| 第 1 轮 | 92 条，位次 4..95 |
| 第 2 轮 | 320 条，位次 98..417 |
| 第 3 轮 | 521 条，位次 419..939（末条 `turn/end`） |
| 节外（不属于任何一轮） | 8 张：位次 0,1,2,3,96,97,418,940 |

这些值来自日志本身（`turn/start` 到 `turn/end` 就是节的边界），不是界面上的观感；换一份会话时
`collect.js` 打印的就是那一份的实际值，判据仍然成立。

## 脚本没覆盖、要手工量的

- **贴顶偏移随宽度重算**：1280px 宽时筛选那一行 37px（轮次标题 `top: 37px`），420px 宽时它折成两行、
  61px（标题 `top: 61px`）；量 `--dsm-turn-top` 与两个盒子的 `getBoundingClientRect`。
- **浅深两套主题的取色**：筛选那一行与轮次标题都取卡片同一层（浅 `rgb(255,255,255)`、深
  `rgb(44,44,46)`），贴顶时滚过去的条目不能从它背后透出来（取像素核）。
- **`prefers-reduced-motion`**：折叠标记的过渡要停掉。

## 踩过的坑（跑之前先看这几条）

- **折起来必须自己收正文**：`.dsm-turnBody` 声明了 `display: flex`，作者样式会压过浏览器替 `<details>`
  收内容的默认规则——不收就是"标记折起了、九千多像素的正文还溢在下面"。
- **折叠不触发 `scroll`**：读数要听 `toggle`（它不冒泡，得在列表上捕获着听），否则它会停在折叠前的值。
- **`src/client/styles.ts` 的 CSS 正文不许出现反引号**：模板字面量会当场截断，`pnpm build` 报出的位置
  离真凶很远；`test/client.test.mjs` 有一条守卫断言专门说这件事。
- **别把 `pnpm build` 的输出丢掉**：构建失败时静默重定向会让人拿旧产物量出一堆假结论；量之前先确认
  `lib/client.js` 的时间戳是新的。
