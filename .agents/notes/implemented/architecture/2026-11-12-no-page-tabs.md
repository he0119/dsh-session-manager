# Agent Note: 去掉页签，四件事各是一处入口 + 一个宽弹窗

Status: implemented

## Problem

「会话管理」页从侧栏进来占整块主栏，页头一排四个页签：会话 / 传输 / 同步 / 备份。用户截图报的就是
这排控件。它带来三个具体的损失：

1. **勾选只在「会话」那一页有效。** 勾了 6 条再切到「传输」导出，得在那一页重新勾一遍——两页各有
   一套勾选态与筛选条，同一个库在两处各算一次。「迁移」早就因为这个原因搬进了勾选动作行（见
   [迁移的源就是你勾的那些会话](2026-10-13-source-is-what-you-tick.md)），其余两件没跟上。
2. **同步是四件事里唯一不用你点也会自己跑的**（自动推送、关掉窗口继续落地），却藏在页签里：跑完关掉
   窗口，回来默认停在「会话」，不进那一页就不知道昨晚那趟成没成。
3. **备份是迁移 / 删除 / 同步覆盖本机那份三件事共同的后悔面**，却排在动作页后面，于是三处文案要替它
   指路（`manage.delete.backupTo`、`sync.appliedReplaced`、`sync.progress.note`）。一处入口要三处
   指路，说明它不在人去找的地方。

页签还多一层成本：进来先认"我在哪一页"，再认"这页能干什么"。

## Decision

> 后续：导出与导入后来拆成两处入口——导出是动作行上一枚按下去就下载的按钮，导入是状态栏那枚 640 的
> 窄弹窗，见 [导出与导入是两处入口](2026-11-12-export-and-import-are-two-doors.md)。本文里
> 「导出 / 导入…」那一枚、传输弹窗的 1080×798 与两栏测量，都已随那次改动作废。

页面只剩列表，另外三件事各是一处入口 + 一个 1080 宽的弹窗：

- **导出 / 导入**：列表卡片底部动作行上的「导出 / 导入…」。它是这条行上唯一不要求勾选的一枚（包里带
  什么与勾了什么无关），开同一个弹窗：左导出、右导入，勾中的那几条已经带在导出栏里。（这一枚已按上面
  那条后续拆成两处；"它不要求勾选"正是拆开的起因：导入与勾选无关，导出却强相关。）
- **同步**：页头标题右边那枚状态（官方 `Button` + `StateDot`）。平时只说本地知道的事——配没配、自动
  推送开没开、这一趟的结论；点开才是远端、计划、差异与确认。为了它联网算"待拉几条"不值得，宿主目前
  也没记上一次同步的时间，所以不编一个。
- **备份与回滚**：底部状态栏那枚入口（带份数）。三种写操作共同的后悔面不属于任何一件动作，所以它跟
  "库在哪"这一档信息待在一起；删除 / 迁移成功后的提示里另有一枚「撤销」直接指着那份备份，见
  [勾选整页一份，备份能一键撤回去](2026-11-12-one-selection-for-the-whole-page.md)。
- **说明**仍旧从页头的「?」开弹窗；那一节从「每页做什么」改成「哪里做什么」，词条就是入口按钮上的字
  （`place.*`）。

列表**不卸载**：开关弹窗只是挂载 / 卸载另一面，勾选与滚动位置留在原处（实测：勾一条 → 开导出 / 导入
→ 关掉，行仍是勾上的，「已选 1」不变）。

外壳是 [WorkDialog](../../../../src/client/components/WorkDialog.tsx)（`.dsm-dialog.dsm-workDialog`，
1080 宽；正文层 `.dsm-workBody` 自带 16px 节奏）。宽度沿用这三面原来在页面上的可读宽度，搬进弹窗一个字
不用重排；窄窗口下 `min(1080px, 100%)` 自己收。

## 量到的

在真实 dev GUI（1600×1000 与 1024×900，深浅两套主题）量 `getBoundingClientRect` /
`getComputedStyle`：

- 1600 窗口、页面 **1272** 宽：页头 **28px**、同步状态 **131×28**、工作台 **1272×867**、列表卡 **692**
  宽。
- **底部状态栏从 29px 涨到 39px**：那枚入口按钮 28px 高，加 10px 上留白。列表因此少 10px。
- 1080 宽的弹窗：传输 **1080×798**，正文层 `gap: 16px`，两栏 **600.4 + 415.6**（导出卡 600×676、
  导入卡 416×324，都在首屏内）；同步 **1080×332**（卡 1032×210）；备份与回滚 **1080×500**（3 份备份，
  正文不滚）。
- 1024 窗口、页面 **696** 宽：页头仍是一行（28px）；传输弹窗 **976** 宽，两栏 **538.9 + 373.1**——
  容器 928 还没到 900 那一档，所以没叠成一列。
- 说明弹窗不变：**760×952**。
- 深浅两套：同步状态与「刷新」同一套观感（`box-shadow: inset 0 0 0 1px rgba(255,255,255,.16)`）；
  状态栏文字深色 `rgb(173,178,184)`、浅色 `rgb(129,133,140)`，发丝线 `rgba(255,255,255,.06)` /
  `rgba(0,0,0,.04)`，都来自 token，没有新字面量。

## Alternatives considered

- **保留页签，把「会话」设成默认并记住上次那一页**：仍然是"切一次丢一次勾选"，三个损失一个没解决。
- **页签换成左侧竖导航**：[全宽工作台那篇](2026-11-12-session-page-is-a-full-width-workbench.md) 已经否决过
  （宿主自己有左侧栏，再贴一条会读成"应用里套应用"），而且左栏已经被项目树占着。
- **单页纵向分区**（工作台在上，下面三张可折叠卡）：不挡列表，但三张卡与工作台抢高度，工作台得缩矮；
  同步卡要滚到列表底才看得见。
- **下钻页 + 返回**（内容区整块换掉）：保留全宽与滚动位置，但多一次返回，"我在哪"换个说法又回来了，
  而且确认弹窗仍要单独一套。
- **只把备份挪出来，传输与同步留页签**：剩下两个页签仍然摆成同级，等于只拆掉一半。
- **同步入口做成下拉菜单**：状态（配没配、跑完没有）就没地方常驻了，而它恰恰是唯一会自己变的东西。
- **把备份入口也放页头**：页头已经有同步状态 + 三枚动作，窄窗口下会换行。

## Consequences

- 弹窗会挡住列表：同步计划里想对照"被拉下来的这条是什么"只能看差异弹窗，看不到背后的列表。这是这一版
  接受的取舍。
- 同步状态说不出"待拉几条"：那要联网算一份计划，一个页头按钮不该为它连远端。"上次同步在几点、成没成"
  已经落盘（见[下一篇](2026-11-12-one-selection-for-the-whole-page.md)）。
- 底部状态栏高了 10px（29 → 39）。嫌贵的话下一步可以把它挪进页头那排或做成菜单项。
- 传输弹窗在 1024 窗口下仍是两栏（容器 928 > 900 那档），要更窄才叠。
- 代码面：`.dsm-tabs` 与 `.dsm-panel` 那层限宽删掉；`SegmentedControl` 不再被 require；
  `PanelShare` 多一个 `openTransfer`；字典删掉 `page.tab.*`，加上 `place.*` / `sync.chip.*` /
  `transfer.dialogTitle` / `manage.transfer.action` / `page.help.title` / `help.entry.*`。
- 测试夹具：列表一直挂着，开了弹窗的用例里它不展开（`ManagePanel` 那条元素仍在 `recorded` 里），否则
  同一批「全选 / 清空」会被数两遍；列表自己的表现由 `panel: 'manage'` 那批用例覆盖。
