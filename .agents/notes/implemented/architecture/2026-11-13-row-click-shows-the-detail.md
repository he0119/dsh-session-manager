# Agent Note: 点整行看详情，行尾那枚「详情」留给键盘

Status: implemented

## Problem

「会话」页上一行会话能做的事，一半藏在悬停里：要看这一条的详情，得先把鼠标移上去、等行尾浮出
「详情」再点那枚小字。用户对一行最直接的动作就是"点它"，可当时点整行是勾选框的事——这一行是个
`<label>`，点它等于把点击转给勾选框。于是"点会话看详情"这条最自然的路径不存在，反而会不小心勾上
一条会话。

## Decision

- **点整行 = 把这一条交给右栏**（`SessionInspector`），与点行尾那枚「详情」是同一个动作。
- 行仍然是 `<label>`（勾选框的无障碍名字靠它），但行上的点击在 `preventDefault()` 之后不再转给
  勾选框：点标题、点项目、点字节、点空白都只做"看详情"这一件事，勾选状态不变。
- 勾选框自己、行尾那枚动作各自处理自己的点击（`openDetailOf()` 先看
  `closest('button, input, a')`，命中就放手）：勾选框照旧只管勾选，行尾那枚「详情」照旧打开右栏
  （完整时间线后来不在行上了，见
  [行尾只留一枚给键盘的「详情」](../simplification/2026-11-13-row-actions-leave-the-hover-slot.md)）。
- 键盘那条路不变：行不是可聚焦元素，Tab 落到这一行的勾选框时 `.dsm-slotActions` 凭 `:focus-within`
  出场，那时 Tab 够得着「详情」。
- 只有给得出 `onOpenDetail` 的列表有这一下（会话页）。导出 / 迁移挑选 / 计划清单那些行照旧整行勾选
  ——那里没有右栏可开。

## Alternatives considered

**只留行尾那枚「详情」。** 就是改之前的样子：悬停才出现的动作适合"顺手做个次要动作"，不适合
"看这一条"这种主诉求；而且悬停本身在触屏上根本不存在。

**把整行做成一枚按钮（`role="button"` + `tabIndex`）替代那枚「详情」。** 行里还嵌着勾选框与两枚
按钮，按钮里再套交互控件是非法嵌套；给 `<div>` 加 role 再把键盘事件抄一遍，等于把原生按钮的行为
重写一遍给屏幕阅读器，而现成的那枚「详情」已经是对的语义。

**点一下看详情、再点一下收起（切成 toggle）。** 与外面那层空白（点空白收起）撞车：窄屏下右栏一开，
列表就被那层空白盖住，第二下根本到不了行上；宽屏下右栏一直摆着，"收起"又没有可见的变化，同一个
手势于是有两种结果。

**双击才看详情。** 列表上手感更钝，还得给单击另找一个含义（现在是勾选），用户更难猜。

## Consequences

- **点整行不再勾选这一条**：勾选只剩勾选框（它一直在第一列、悬停也显形）。挑一批会话是"点勾选框"，
  看一条是"点这一行"——两件事各归各的控件。
- 窄屏下点一行 = 右栏滑进来 + 外面那层空白上岗（见
  [浮动面板进出用滑动](../bug-fix/2026-11-13-overlay-motion-slides-with-visibility.md)），
  点空白收起。
- 结构由 `test/client.test.mjs` 钉住：整行挂着点击；点在勾选框 / 行上动作上时不接；点在别处时
  `preventDefault()` 被叫过一次，且只写一处状态（`detail` 换成这一条的 id）。
- 真实 dev GUI 里走过：工作台 1272px 点第三行 → 右栏换成「AI助手能做什么」、该行 `data-opened`
  为 true、八个勾选框一个都没动；点同一行的勾选框 → 只勾上这一条，右栏不动；工作台 796px 点行
  标题 → 右栏从 876 滑到 536（约 160ms）、外层空白跟着上岗，勾选仍然没变。
