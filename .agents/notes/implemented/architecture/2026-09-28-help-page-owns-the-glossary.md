# Agent Note: 动作页只留当下要做的决定

Status: implemented

## Problem

会话管理要解释的东西天然多：会话有六种状态（可见 / 子代理 / 空白 / 已归档 / 活动中 / 未分组），动作
又各带代价（删除先备份、迁移改写 header 的 cwd、回滚与恢复的差别）。

这些内容一开始都写在动作页的说明段里，于是每加一个功能就顺手在按钮边上多解释一句，攒到后来动作页
正文 187 / 382 / 144 字（实测，最长的一段 192 字）——读者每动一下都要先扫一遍散文。更别扭的是分类的
含义只活在五枚标签的悬浮提示里（44 / 42 / 39 / 69 字），不悬浮就一个字都看不到。

## Decision

按「用到的时刻」分成两处：

- **动作页只写当下那个决定**：点下去会开一个确认弹窗（清单在弹窗里）、会先备份、多选＝任一命中。
  读者正要按按钮，这几句是最后一道提醒，留在原地（实测收紧后 114 / 210 / 113 字）。
- **词条与边界条件进「说明」页**（`src/client/components/HelpPanel.tsx`）：分类各是什么意思、谁
  判的、删完侧边栏为什么还在、回滚与恢复差在哪、两条路径分别是什么。读者只会查一次，集中在第四
  个页签上，形状也从散文改成**词条**（`dt` 词 + `dd` 解释），一扫就能定位。

词条文案**复用行上那几枚标签的键**（`tagSubagent` / `tagSubagentTip` …）：同一件事在悬浮提示与说明页
里必须是同一句话。

2026-10-05 又收了一遍：单独那张「会碰什么盘」与常见疑问逐条重复（回滚与恢复、删完侧边栏为什么还在、
活动中的会话删不掉），于是只剩四张卡片，边界条件里独有那三条（备份时机与回滚 / 恢复的分工、子代理跟
着父会话走、包里有什么）并进常见疑问；文案同一遍改成不带行话的一版。

## Alternatives considered

**都留在动作页。** 上面的字数就是结果：按钮旁边是散文，而分类的含义藏在需要悬浮才出现的地方。

**都搬进说明页。** 「会先备份」这类提醒的价值就在于它在按钮旁边；搬走之后动作页只剩按钮。

**靠评审保持「动作页别太长」。** 这条分工靠自觉会漂回去——「再补一句就清楚了」永远很有道理。

## Consequences

- 钉了一条机械面：动作页上那几段说明**每段不超过两行**（中文 ≤76 字、英文 ≤175 字，按卡片正文宽约
  480px、13px 字体折算；见 `test/client.test.mjs`）。超上限不是「字太多」，是「这段该搬去「说明」页」。
- 说明页只补标签没说到的部分（「可见」这一类、每页做什么、数据从哪来、常见疑问）。
