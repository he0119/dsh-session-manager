# Agent Note: 写盘动作是一个按钮开一个确认弹窗

Status: implemented

## Problem

原来每个会写盘的动作都是两步：先点「预演」，把计划渲染到页面里，再点「确认」。两个按钮分居卡片两头，
而预演会**改写按下去的那块地方**——按钮从「预演迁移」变成「确认迁移」，结果卡片插在字段下面把下面的
内容推走。用户按第二下时，眼前的东西已经不在他刚才看的位置上。三个分页（会话 / 迁移 / 传输 / 同步）
再加上「备份与回滚」里的回滚，一共五处都是这个形状。

计划本身是**只读、便宜、可重复**的一次计算（`src/migrate.ts` 的 `apply:false`、`src/remove.ts` 的
`mode: 'plan'`、`src/sync.ts` 的 `options.apply === false`）。用户真正要做的决定只有一个：「这份清单，
做不做」。把"看清单"与"做决定"拆成两次点击、两个位置，就是把一个决定拆成了两件事。

## Decision

**每个写盘动作只有一个入口按钮**（「删除所选」/「迁移」/「导入」/「同步」/「回滚」）。点下去立刻开
确认弹窗，同时取回那份只读计划；弹窗里就是计划本身——清单（删除与迁移逐条列出会话）、摘要、问题、
备份位置，底部是「取消」与「确认 X」。

- **取消不做任何写入**：计划是只读的，关掉弹窗不会留下半个动作。
- **计划取不到**（网络、未配置）时关掉弹窗，把原话摆到页面横幅上——那类错不是"这份计划有什么问题"，
  留在弹窗里只会让人以为还能按确认。
- **计划算出来了但 `ok === false`** 时弹窗照开、清单与问题照摆，只把确认按钮禁用：用户要看的是
  "哪一条不成"，不是一句"失败了"。
- **取消或落地成功之后弹窗关掉**，页面回到按之前的样子；落地之后的结论（复核、备份位置、生效方式）
  留在页面上。
- **归档与导出不问**：归档走宿主能力、即时且可逆，导出只把已有字节打成包——分界线是"这一步会不会
  写盘、写了以后要不要后悔"。

弹窗外壳是 `src/client/ConfirmDialog.tsx`（四个分页共用）：它走官方控件库的 `Modal`，管遮罩、Escape、
焦点归还与菜单叠层；计划由**调用方**取、正文由调用方画——"取哪一份计划"是那个动作自己的事，端点类型
与清单结构也只在各页里。初始焦点给「取消」而不是主按钮（`data-modal-autofocus`）：确认键是这个弹窗里
最重的动作，键盘用户不该因为对话框一出现就抢了焦点而误删。

## Alternatives considered

**保留两步，只把预演结果搬进弹窗。** 多一次点击，而且「预演」这个词本身是要解释的概念——用户点它的
意思是"我要删这几个"，不是"给我一份报告"。名字叫预演的按钮点完什么也不发生，是这五处别扭的根源。

**页面上弹一句"你确定吗"（不带清单）。** 清单才是这个弹窗存在的理由：删除会级联子代理、迁移会连着
搬迁产物、导入会改写 `cwd`、同步会真拉真推。一个不含清单的确认框只是多一次点击。

**自己写遮罩层，不引官方 `Modal`。** 要让弹窗不被设置外壳的 overflow 裁掉就得 portal 到
`document.body`，而 `react-dom` **不是**平台基线模块（基线只有 `react`、`react/jsx-runtime` 与官方控件
库，见 [浏览器半侧的产物是经典脚本，只 require 基线模块](./2026-09-27-client-artifact-is-a-classic-script.md)）：
自己写要额外申请一个非基线模块，还会丢掉官方的焦点归还与叠层管理。

**计划留在页面上（像以前那样取消预演不清空）。** 它说的是按下去那一刻的库；留着只会让人以为它还算数。

## Consequences

- 四个分页把"那份计划"与"弹窗开没开"合成**一个**状态（删除 / 迁移 / 导入是 `pending`）：取消即丢，
  页面上不会留一份没人看的计划。
- 计划在弹窗打开之后才回来，用户可能已经取消：各页都用 `current === null ? current : …` 原地作废，
  否则一份晚到的计划会把已经关掉的弹窗**重新打开**。
- 同步页的 `sync`（最后一次计划或结果）仍然留着：映射表的远端候选读它，关掉弹窗之后候选还得在。
- 页面上的动作按钮只剩一个入口，`test/client.test.mjs` 钉住"关着弹窗时页面上没有『预演中…』"，
  并逐个核弹窗的标题、正文与底部按钮。
- 弹窗宽度按清单量（640px）：官方那张卡是 `min(380px, 100%)`，按"一句话 + 两个按钮"量的，装不下会话
  行与预演表。宽度用重复类名提一档特异性，免得跟宿主注入的官方样式比先后顺序。
- 动作页上的说法跟着改了：那几段说明不再提"先预演"（见
  [动作页只留当下要做的决定](./2026-09-28-help-page-owns-the-glossary.md)）。模型工具那一路不动——
  它本来就是 `plan` / `apply` 两次调用，模型自己先看清楚再落盘。
