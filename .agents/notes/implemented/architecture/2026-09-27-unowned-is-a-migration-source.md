# Agent Note: 迁移页把「未分组」当独立来源

Status: implemented

## Problem

「传输」页不能给「未分组」造一组，理由是**组头的语义**：勾一个组头 = 带走那个目录，组头必须是一个
可以整批带走的实体，而外壳那一组可以横跨多个目录。

但迁移页的源是一个值控件（下拉框自己就是那个值），旁边还有「只迁其中几条」的子集模式——那层约束不
成立。反过来说，那批会话**恰恰需要**一个独立来源：它们可以横跨多个目录，一个目录一个目录地勾，
谁也说不清「这两个目录里没在册的那两条」是一件事。

## Decision

迁移页把「未分组」做成一个独立来源。四种口径被钉在一起，少一条就会出现「界面说 2 条、宿主说 3 条」：

- **候选**：`unowned` + `ungrouped` + **有 `cwd`**（`planRows.unownedSessions()` 与 `src/plan.ts`
  的发现阶段是同一条判据）；
- **请求**：界面上的哨兵值 `UNOWNED_SOURCE`（`@unowned`）在发请求那一刻被翻译成 `unowned: true` +
  `from: ''`；哨兵既不下线也不当文案露出来；
- **计划**：`from` / `sourceProjectDir` 是空串（源不是一个目录），每条会话各自的源在
  `sessions[].from` 里；`describePlan()` 于是报「横跨 N 个源项目目录」而不是一个假路径；
- **两个被关掉的开关**：「连同未分组的会话」（那批本来就全都没在册）与「搬迁会话产物」（产物定位是
  相对于源目录的，跨目录的源给不出这个基准——显式报 problem，而不是悄悄不搬）。

执行阶段按 `sessions[].sourceDir` 的父目录去重后逐个检查空不空；**目标项目目录永远跳过不删**。

## Alternatives considered

**不给它独立来源，让使用者按目录分别勾。** 跨目录的那批没在册会话就没有任何一处能整批带走。

**给它一个假的源目录路径。** 备份清单里的 `from` 只是给人看的一句摘要，写一个假路径不如不写——
这次迁移的 `from` 因此是缺席的（界面显示成「—」），真正的源头在清单每条会话的 `sourceDir` 里。

**允许它搬产物。** 产物定位相对源目录，跨目录的源没有这个基准；含糊地搬等于把文件搬到猜出来的位置。

## Consequences

- 回滚对跨目录是透明的：它只认清单里每条会话的 `sourceDir` / `dirName`。
- `test/unowned.test.ts` 用一个「三个目录 + 一条无 cwd 老会话」的沙箱把这条钉住：只搬空的那两个项目
  目录被删，还留着在册会话的那个项目目录必须保住，并且跑到 apply → verify → rollback。
