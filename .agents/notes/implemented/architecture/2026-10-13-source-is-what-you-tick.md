# Agent Note: 迁移的源就是你勾的那些会话

Status: implemented

取代了[源永远是一个目录（「未分组」只是一枚标签）](../../rejected/simplification/2026-10-13-ungrouped-is-only-a-label.md)。
「未分组」仍然只是一枚标签，那一条没有变（判据仍在 `src/visibility.ts`）；变的是"源"这件事：
它不再被限制成一个目录。

## Problem

迁移页原来有两个目录字段：源目录、目标目录。源只有**一个**值，所以"把刚删掉的那个项目里那几条会话
迁到重建后的位置"这件事必须先回答"它们属于哪个源目录"——本机实测的一个 770 条会话的库里，这类会话
共 8 条、分散在 4 个目录里（其中 1 条的项目目录已经被删掉）。一次迁移只有一个目标，于是这件事在界面上
的落点被劈成四份：按目录各来一次，四次里还要各自确认一遍计划。

源的**值**是个目录这件事本身也在往界面上漏：候选必须是目录（`migrationSourceRows()` 得把会话按 `cwd`
数成一行行）、勾选面必须按源过滤（`migrationMatching()` 只列 `cwd === 源` 的那些）、清单上面还得摆一个
「全部 / 只选其中几条」的单选框来决定"勾选算不算数"——**勾选与源是两套并列的输入**，用户得先想明白
"我要不要用勾选"，才能勾。

## Decision

迁移的源是**你点名的那些会话**（`sessionIds`，必填非空），目标目录只有一个：

- **勾选就是源**：复选框勾中的那些会话就是这次要搬的全部，一次请求带上它们的 id。所以勾选可以跨目录
  ——每条会话的源目录是它**自己的** `cwd`（`SessionMove.from`），计划层不再收"源目录"这个参数
  （`BuildPlanOptions` / `MigrateRequest` / `migrate_sessions` 的 `from` 全删）。「未分组」不再有任何
  特殊地位：它的成员照旧按自己的 `cwd` 参与，"勾上那几条"与"勾上别的目录里那几条"是同一种动作。
- **没有独立的迁移分页**：那枚「迁移」就挂在「会话」页的动作行上（归档所选 / 取消归档 / 重新生成名称 /
  迁移 ┃ 删除所选），点开弹窗才选目标、看预演、确认。源还是"选一个目录"的时候，那一页有自己的列表
  （按源过滤的候选）与自己的勾选语法；源改成勾选之后，它剩下的只有一张与「会话」页逐字同形的列表
  （分组 / 标签 / 筛选 / 勾选都是 `sessionList.tsx` 那一份）加一枚按钮，再留一个分页就是让"勾几条
  会话"与"拿它们做什么"分两步走。预演随目标变化重取
  （目录字段只在"选中候选 / 手输回车"时改值，每次都是明确的用户动作），所以弹窗正文永远是"将要发生的
  那一份"，不另摆「预演」按钮。计划本身过不去时（`ok === false`，确认按钮同时禁用）正文不摆"将迁移 N
  条会话"：那句话是承诺，一条都搬不动时它只会与下面那张问题清单互相打脸。三个目录字段的分页协议仍然
  只有一处实现（`DirectoryField.tsx`）。
- **"能勾"与"搬得走"分开管**：并进「会话」页之后，勾选集是**五件事共用**的（归档 / 取消归档 / 改名 /
  迁移 / 删除），所以它不能为迁移单独变窄——侧边栏不显示的会话（已归档 / 空白）在这一页照旧能勾，
  归档与删除正是照着它们来的。迁移那一侧因此自己把 `hidden`（`/state` 上那份结论，`src/visibility.ts`
  算的）的摘出去：请求体只带看得见的那些，弹窗里用一句「另有 N 条勾中的会话这次不搬」把差额说清。
  行上唯一灰着的仍是"父会话也在库里"的子智能体（提示点名该勾哪条父会话）。宿主那条契约没动：在
  `src/plan.ts` 里对**点名**的隐藏会话逐条拒绝，工具与脚本照旧会拿到那条拒绝——界面不送它们，是为了
  不让"混进一条隐藏会话"把整次落地变成一次没有出口的报错。
- **产物按每条会话自己的来源目录定位**：`planArtifactMoves()` 把 `fromDir` 当"日志里那些相对路径的
  基准"（`extractArtifactsFromLog({ cwd })`），所以计划层按 `SessionMove.from` 分组、每组各算一次再
  合并（顺序按来源目录排序，越界问题清单才是可比的）。拿一个目录当唯一基准的话，别的来源目录里那几条
  的产物会被拼到别人家去——`test/artifacts.test.ts` 的"勾选跨目录"那条钉住它。
- **`includeUnowned` 开关删掉**：它存在的理由是"源的目录里那几条没在册的会话"，现在没有"源目录"了，
  没在册的那几条只要被勾上就跟着走（注册表变更照旧报"从不属于任何工作区的会话里收编 N 条"）。

## Alternatives considered

**保留源目录字段，只把候选改成"整个库按目录分组 + 每组一个勾选框"**：等于在界面上放两套勾选语法
（组的勾选与行的勾选）来表达同一件事，还得再立一条"组头勾选与行勾选谁说了算"的规矩。

**保留 `from`，允许多个源目录**（数组字段）：请求体里就有两处说"搬什么"（`from[]` 与 `sessionIds`），
二者不一致时以谁为准说不清；而"整目录一起搬"本来就能用"把这个目录下的会话全勾上"表达，全选工具
（`SessionPickTools`）已经在那一行上。

**源目录字段照旧放在页面上、只把勾选面改成整库**：页面上会同时有"源目录"与"勾中的那些"，用户得自己
推"源目录其实只是给候选用的"。目标目录搬进弹窗之后，字段那一行只剩"目标"一件事，弹窗里顺理成章。

**保留迁移分页，只把源换成勾选。** 那一页剩下的是一张与「会话」页逐字同形的列表、一枚按钮与一个
弹窗，两页之间只差一个动作；而"勾几条会话、再决定拿它们做什么"本来是同一件事。多一个分页读起来是
先选页、再选做什么，页签也多一枚。

**让宿主跳过点名的隐藏会话，而不是拒绝整次请求。** 那会改掉宿主的判据（"我选了它但你没动"变成无声
的），而工具那条路正需要这条拒绝；同一个 PR 里再动一次对外契约也不该顺手。

**界面照旧把隐藏的那些锁上（迁移那一页的老规矩）。** 这一页的勾选还服务归档、取消归档与删除，隐藏
的那几类正是它们要处理的对象：锁上就等于"已归档的会话无法在这里被取消归档"。

**给没在册的会话单开一条来源**（历史方案）：见[否决记录](../../rejected/architecture/2026-09-27-unowned-is-a-migration-source.md)。

## Consequences

- **对外契约变了**：`plan_session_migration` 与 `migrate_sessions` 的两个 `from` 参数删掉，
  `sessionIds` 成为必填（数组、非空）；`/migrate` 请求体同样只认 `sessionIds` + `to`，缺了回 400
  「缺少要迁移的会话（sessionIds）」。装过旧版、脚本里传 `from` 的调用方要改成传 id。
- `MigrationPreview` 里 `from` / `sourceProjectDir` 换成 `sourceProjectDirs`（去重排序的**来源项目
  目录**数组，即会话日志那一层所在的项目目录）与 `sessionIds`；备份清单里"全部同源时那个来源目录"
  （`from`）只在真的同源时才写，跨目录那次改报来源目录的条数（`sourceDirs`），「备份」页据此显示
  「N 个来源目录 → 目标」。
- 计划层少了"源项目目录不存在"这一类问题（源是会话，不是目录：日志所在的目录当然在），多了"点名的
  会话已经在目标里了"这条；`src/plan.ts` 里两次整库扫描并成一次（不再有"扫源目录 + 扫全库认族"两趟）。
- 界面文案少了 `migrate.from.*` / `migrate.scope.*` / `migrate.includeUnowned` / `migrate.source.*`
  这些键，多了「迁移到的目录」与两条说明（先选目标目录、勾中的隐藏会话这次不搬）。
- 页签从 6 枚减到 5 枚（会话 / 传输 / 同步 / 备份 / 说明）：`page.tab.migrate` 与 `help.tabs.migrate`
  一并删掉，它们的内容并进 `help.tabs.manage`；`MigrationPanel.tsx` 整个文件并进 `ManagePanel.tsx`。
