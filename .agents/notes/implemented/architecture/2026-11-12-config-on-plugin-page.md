# Agent Note: 配置挂插件页，侧栏那一页做事

Status: implemented

## Problem

「会话管理」原来只有设置里一个落点，一页里塞着两件事：上面是操作（会话清单、迁移、导出导入、同步
预演、备份），下面是十来个字段的 WebDAV 配置卡。两件事的读者状态完全不一样——配置一年改两次、改完就
走，操作天天用。挤在一页里的代价是双向的：每次同步要先滚过配置卡；改配置又要先滚到底，还得在一堆操作
按钮里找到那张卡。

## Decision

拆成两个落点，内容各管一件事：

- **侧栏那一页做事**：`main` 放页面（`SessionManagerPage` → `ManagerPanel`，五个分页），
  `sidebar.panellist` 放侧栏那一行图标，两者用同一个 id（`session-manager`）配对——宿主按 id 把侧栏
  那条指到主栏那一页。标题右边一枚「插件设置」，跳插件页。
- **配置放插件页**：`plugins.bundle.config`（按包名作键，`view: 'page'`）挂 `PluginConfigCard`，里面
  按功能分组（现在是一组「同步」：一行一件事，标签与说明在左、控件靠右，组标题 16px/600，组间一条
  发丝线——形状照 `dsh-context` 的 `settingsCard.tsx`）。**设置页里不留本包的
  入口**——那边是官方那几页（通用 / 模型 / 插件 / 账户 / Agent 预设）的位置，插件自己的东西归插件页。
  这一格读一次 `/meta`（不扫库）只为拿到机器名那一栏的灰字。

两页共用同一份配置来源（宿主设置接缝 `configForms`），改完保存时顺手 `panelEvents.refresh()`，侧栏那
一页下一次读宿主事实看到的就是新值——不另存第二份。

分法照官方的 `dsh-context`：它的偏好卡挂在 `plugins.bundle.config` 上（设置里只放官方那几页），
数据视图在侧栏那页，标题右边一枚「插件设置」跳过去。本包照抄这个形状。

## Alternatives considered

- **两个落点同一份内容**（先试过的那一版）：侧栏点开的是整页操作 + 配置卡，设置里也是同一页。省事，
  但把上面那个问题原样搬到两个入口，而且"设置里那页"从此只是侧栏那页的复制品，读者要自己分辨。
- **配置只留一句"请在插件配置里改"**：宿主已经没有别的配置入口（配置页写的就是同一份 patch），
  去掉表单等于把"能在界面里改"这条退回去。
- **还挂在 `settings.section`**（先试过的那一版）：设置页多出一页本包的东西，与官方那几页并列；而
  插件页本来就是"这个包有哪些可调的东西"的地方，官方的邻居也是这么放的。
- **把配置拆成侧栏页里的一个分页**：那还是"做事的地方带配置"，只是把卡搬到另一个分页，问题没变。

## Consequences

- 找东西的成本跟着意图走：要改连接去插件页（侧栏那页标题右边那枚按钮一步到位），要做事情去侧栏那页。
- 侧栏那一页多一层壳（`.dsm-globalPage`）：主栏容器是定高 flex 列且 `overflow: hidden`，滚动视口得
  由占位方给，内容列最宽 960px 居中。
- 插件页那一格按小节排（现在是「同步」一节），以后加第二组就在同一格往下排，不必再动注册。
- 两处 `label` 各是一份 thunk（侧栏一行、设置一行），切语言时各自由外壳重新投影。
