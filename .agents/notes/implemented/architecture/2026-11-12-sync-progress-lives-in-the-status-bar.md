# Agent Note: 同步的进度在状态栏那一格，不在列表上方

Status: implemented

## Problem

一轮同步（手动应用、后台自动推送、插件工具栏那枚「立即推送一次」）原来在列表**上方**摆一条进度横幅：
一枚转圈 + 这是哪一趟 + 进度条 + 正在处理的那一条 + 「中断了怎么办」。跑完那条横幅换成一行结论，带
「打开」与「关掉」两枚按钮，等人来关。

三条都不对：

1. 位置错。列表是这一页的主体，一条 100px 高的横幅把它压下去；而"这次跑到第几条"跟列表里勾了什么、
   正在看哪个项目毫无关系——它是一件**库级**的事。
2. 重复。页头那枚同步状态已经说了"跑着 / 刚跑完 / 上次多久以前"，横幅把同一件事又说一遍，还更占地方。
3. 结论没人收。跑完的那一行会一直挂着，除非用户点「关掉」——一条已经不新鲜的消息占着一整行。

## Decision

进度按"信息有多细"分三处放，各放各的：

- **状态 → 页头那枚同步状态**（`sync.chip.*`）：跑着、刚跑完、磁盘上记着上一次（多久以前）、失败（多久
  以前）、未配置。它短、不折行、已经在那儿。
- **一句话 → 底部状态栏**（`.dsm-statusAction.dsm-statusJob`，39px 那一行）：跑着时报**会话**搬到了第
  几条「同步中 · 3/7 条会话」，这一趟真要搬附件对象时再加一段「· 附件 1/2」；跑完 12 秒内「同步完成 ·
  2 条」或「同步失败」，点一下开同步那一面；长的那些（字节、正在处理哪条、失败原因）挂在它的悬浮提示
  上。这一格与「导入…」「备份与回滚（N）」同排——都是"对整库做的事"，与勾选无关。
- **细节 → 同步那一面**：进度块（四行）留在弹窗里；跑完之后那一面自己换成结果页（一句结论、没做到的
  逐条、「撤销」），认领来的那趟也落在同一页上（只有"搬了几条"），所以失败原因不会因为横幅没了就消失
  ——见 [写入磁盘动作共用一扇执行窗](./2026-11-15-actions-share-one-run-dialog.md)。

列表上方的横幅整块删掉（`.dsm-progressBanner` 随之没有调用方）。状态栏那一格说哪一句由一个纯函数判
（`operations/sync/syncJobLabel.ts` 的 `syncBarLabel()`）：跑着且有会话数 → `同步中 · done/total 条会话`；
会话与附件对象都在动 → 再加一段 `· 附件 done/total`；只有附件对象在动（补对象那一趟，整库尺度）→
`同步中 · 附件 done/total`；跑着但还没有这两串数（算计划那几段、认领来的那趟）→ `同步中…`；跑完成功 →
`同步完成 · N 条`（`result` 是两条数组，`adopted` 是两个数，都没有就说 `同步完成`，不编一个 0）；失败
→ `同步失败`；没有那一趟 → 这一格不出现。

**那串数只认会搬东西的那三段**（`syncBarTally.ts` 折出来）：`pull` / `push` 数的是会话，`attach` 数的
是附件对象。宿主报的另外几段各有各的分母——`repo` 是本机仓库目录、`tidy` 是远端包、`scan` 是库里的
会话——原先那一格直接拿**最后一条事件**画，于是屏幕上出现「同步中 20/21」时，那个 21 可能是 21 个
目录：数与用户在等的进度无关，也读不出单位。会话那两段之间也不相加 `done`：一次整库同步实测是"先拉
3 条、再推 84 条"，换段时把上一段的**总数**并进 `carried`，分母才是 87。附件对象是按会话一批一批来
的，一批跑完（`done + 1 === total`）整批并进 `objectsBase`，所以分母会边跑边补齐——39px 只有一串字，
就按"到目前为止"说，不假装一上来就知道总数。

## Alternatives considered

- **把字节、正在处理的那条也塞进状态栏**：39px 的单行放不下；1024 窗口下这一行本来就只剩几像素余量，
  再宽就得把库路径整段吞掉。
- **跑着时直接画最后一条事件的分母**（原样，`同步中 done/total`）：那是实现最省的一种，但四个动作共用
  一套段名，`repo` / `tidy` / `scan` 也走同一条路，屏幕上的 20/21 常常是目录数或远端包数——说了等于
  没说，还容易让人以为"只差一条会话就完了"。分单位报要多一个折事件的小模块，值。
- **附件对象只报"已经搬了几个"（不报分母）**：分母要等每条会话把自己的引用摊开才知道，报出来会一直
  变大；但只有分子的话，用户看不出"还剩多少"，而在传几十兆图片时那正是他要知道的。折中成"到目前为止
  已知的总数"，并且只在这一趟真搬过对象时才出现。
- **横幅留着但压成一行 48px**：仍然压在列表上方，仍然要说"这是哪一趟"，而页头那枚已经在说。省 50px
  换不来新信息。
- **全部收进弹窗，页面上一个字不提**：同步跑在后台（可能从别的页发起，也可能是空闲时自己跑的），关掉
  弹窗之后页面上没有任何东西说"它还在跑"，用户只能等——这正是 `operations/sync/syncJob.ts` 当初存在的理由。
- **放 toast**：toast 会自己消失、不能点开、也不该承载"这一趟成没成"这种要回头看的事实。

## Consequences

- 状态栏多一格，两串数都在、数字到三位时那一格 234.1px（实测，1280 宽；只有会话那一句 145.4px）：
  1024 窗口下库路径让到 198px，仍是一行、不折、不溢出；悬浮提示里有全文。39px 那一行不变高。状态与
  数之间也留一个 `·`（与「同步完成 · 2 条」同一个写法）：代价是那 15px，换来四种状态一个形状。
- 失败原因不再一眼可见：要么悬浮状态栏那一格，要么点开同步那一面。39px 里只能放"同步失败"三个字。
- 结论 12 秒后自己收掉（`syncJob.dismiss()`）：页头那枚状态仍然常驻"多久以前"，所以收掉不丢事实；想
  再看得点开那一面，那一面有那一趟的账。同步那一面开着时这条定时器不走（那里的结果页正拿着这份结论，
  读到一半被抽走比"留在状态栏上"更糟）。
