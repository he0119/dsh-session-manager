# Agent Note: 同步的进度在状态栏那一格，不在列表上方

Status: implemented

## Problem

一轮同步（手动落地、后台自动推送、插件工具栏那枚「立即推送一次」）原来在列表**上方**摆一条进度横幅：
一枚转圈 + 这是哪一趟 + 进度条 + 正在处理的那一条 + 「中断了怎么办」。跑完那条横幅换成一行结论，带
「打开」与「关掉」两枚按钮，等人来关。

三条都不对：

1. 位置错。列表是这一页的主体，一条 100px 高的横幅把它压下去；而"这次跑到第几条"跟列表里勾了什么、
   正在看哪个项目毫无关系——它是一件**库级**的事。
2. 重复。页头那枚同步状态已经说了"跑着 / 刚跑完 / 上次多久以前"，横幅把同一件事又说一遍，还更占地方。
3. 结论没人收。跑完的那一行会一直挂着，除非用户点「关掉」——一条已经不新鲜的消息占着一整行。

## Decision

进度按"信息有多细"分三处放，各放各的：

- **状态 → 页头那枚同步状态**（`sync.chip.*`）：跑着、刚跑完、磁盘上记着上一次（多久以前）、失败（多久
  以前）、未配置。它短、不折行、已经在那儿。
- **一句话 → 底部状态栏**（`.dsm-statusAction.dsm-statusJob`，39px 那一行）：跑着时「同步中 3/7」，跑完
  12 秒内「同步完成 · 2 条」或「同步失败」，点一下开同步那一面；长的那些（字节、正在处理哪条、失败原因）
  挂在它的悬浮提示上。这一格与「导入…」「备份与回滚（N）」同排——都是"对整库做的事"，与勾选无关。
- **细节 → 同步那一面**：进度块（四行）留在弹窗里，认领来的那趟结论（别处发起、页面自己那份内存已经
  没了）由页面把那一句递进去（`backgroundLine`），所以失败原因不会因为横幅没了就消失。

列表上方的横幅整块删掉（`.dsm-progressBanner` 随之没有调用方）。状态栏那一格说哪一句由一个纯函数判
（`logic/syncJobLabel.ts` 的 `syncBarLabel()`）：跑着且有分母 → `同步中 done/total`；跑着但没有分母
（认领来的那趟，宿主只留"跑没跑"）→ `同步中…`；跑完成功 → `同步完成 · N 条`（`result` 是两条数组，
`adopted` 是两个数，都没有就说 `同步完成`，不编一个 0）；失败 → `同步失败`；没有那一趟 → 这一格不出现。

## Alternatives considered

- **把字节、正在处理的那条也塞进状态栏**：39px 的单行放不下；1024 窗口下这一行本来就只剩几像素余量，
  再宽就得把库路径整段吞掉。
- **横幅留着但压成一行 48px**：仍然压在列表上方，仍然要说"这是哪一趟"，而页头那枚已经在说。省 50px
  换不来新信息。
- **全部收进弹窗，页面上一个字不提**：同步跑在后台（可能从别的页发起，也可能是空闲时自己跑的），关掉
  弹窗之后页面上没有任何东西说"它还在跑"，用户只能等——这正是 `logic/syncJob.ts` 当初存在的理由。
- **放 toast**：toast 会自己消失、不能点开、也不该承载"这一趟成没成"这种要回头看的事实。

## Consequences

- 状态栏多一格，1024 窗口下库路径让掉约 113px（实测 372 → 259，仍是一行、不折、不溢出；悬浮提示里有全文）。
- 失败原因不再一眼可见：要么悬浮状态栏那一格，要么点开同步那一面。39px 里只能放"同步失败"三个字。
- 结论 12 秒后自己收掉（`syncJob.dismiss()`）：页头那枚状态仍然常驻"多久以前"，所以收掉不丢事实；想
  再看得点开那一面，那一面有那一趟的账。
