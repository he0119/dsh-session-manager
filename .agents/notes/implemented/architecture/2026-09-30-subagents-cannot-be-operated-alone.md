# Agent Note: 子代理不能被单独操作

Status: implemented

## Problem

删除与迁移把族当单位之后，剩下两条按会话动手的路（归档、导出）还在按单条走：点名一条子代理会把
一族拆开——删掉它会在父会话日志里留一条指着不存在会话的 catalog；归档它会让侧边栏那一行看起来还在
父下面，点开却是另一条路径上的东西。

## Decision

两条判据，四条路同形：

- **单独点名一条子代理一律拒**（父会话还在库里时）：`loneSubagents()` 挑出 `parentSession` 指向一条
  **在库里、又不在这次操作里**的会话的那些，删除、归档与导出各自据此回绝，并指名该点哪条父会话。
  判据是「父会**不会**被这次操作带上」，不是「有没有同时点名」——坏数据里的环（A 的父是 B、B 的父是 A）
  从任一条展开都会把另一条带进来，那不算拆族，所以删除那条路把判据迭代到不动点。
- **孤儿除外**：父会话已经不在库里的子代理没有可跟随的会话，三条路都照旧允许单独操作（否则只能去
  `rm -rf`）。

界面把这件事做在前面：子代理行的勾选框直接**禁用**（`SessionRow` 的 `locked`，提示里写明该勾哪条父
会话），组头与「全选」也跳过它们。

## Alternatives considered

**允许单独操作，只在文档里提醒。** 后果是静默的：catalog 指向一条不存在的会话，而使用者只看到
「删干净了」。

**单独点名子代理时自动把父会话带上。** 向上牵连不是这个动作该做的事——点「删这一条」不该删掉别人的
父会话，而且父会话可能还活着、还在往里写。

**只把界面上的勾选框禁用，宿主侧照旧接受。** 端点会被别的调用方（模型工具、脚本）打到，判定必须在
宿主侧。

## Consequences

- 能勾的集合与「单独操作不会被拒的集合」一致——否则用户只能靠点下去被拒来发现自己点错了。
- 界面的判据是 `/state` 给的 `origin` 与 `parentSession` 两个字段，与宿主侧同源。
- `test/remove.test.ts` 与 `test/web.test.ts` 把这几条逐个钉住（只删子时的提示、孤儿、环、点名的
  同时又是别人的子代理）。
