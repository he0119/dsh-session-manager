# Agent Note: 筛选按「它是什么」判，不按它显示成哪枚标签

Status: implemented

## Problem

行上会挂标签（子代理 / 空白 / 已归档 / 活动中），筛选条也按这几类筛。而 `/state` 给的那个 `hidden`
只报**宿主先判的那一条**理由——一条会话既是空白又已归档时是 `blank`。它回答的是「侧边栏为什么不显示
它」，与宿主 `sessionVisible()` 的顺序一致，这个口径不能动。

但如果筛选与标签都读它：按 `hidden` 筛「已归档」，那条空白 + 已归档的会话就筛不出来；按 `hidden`
挂标签，用户会看到「筛了归档，却有几行没有归档标签」。

## Decision

筛选与标签共用一套**事实**字段（`origin` / `blank` / `archived` / `live`，见
`src/client/logic/sessionFilter.ts`），不共用 `hidden`。标签**能挂几枚挂几枚**，
筛选读原始事实，两边自洽。

「未分组」是这条规矩的**唯一例外**：它读的正是宿主的结论（`ungrouped`）。因为它问的不是「这条会话是
什么」，而是「侧边栏把它放在哪儿」——那件事只有宿主知道。

其余三条口径是刻意的：**多选＝任一命中**（这几类两两之间本来就很少同时成立，做成「全都要命中」的话，
勾第二枚时列表多半直接空了）；**每类的条数对整个库数**，不随当前筛选跳（会跳的计数没人信得过）；
**「全选」选的是眼下列出来的那些**，而已经勾上的不会因为切换筛选而丢。

## Alternatives considered

**筛选也读 `hidden`。** 上面两个现象就是结果，而且它们看起来都像 bug 而不像定义问题。

**把 `hidden` 改成一个数组（列出全部理由）。** 那会改掉宿主 `sessionVisible()` 的顺序口径，而
「侧边栏为什么只显示一条」这件事本来就是「取第一条」的语义。

**「未分组」也按原始事实推。** 那要么把 `sessionVisible()` 再抄一遍，要么把子代理、空白与已归档也算
成「未分组」——抄错过一次，见 [「未分组」就是外壳那一组](../bug-fix/2026-09-28-ungrouped-means-the-sidebar-group.md)。

## Consequences

- 「未分组」既是一枚类别胶囊也是行上的标签，一个事实一个名字，与外壳侧边栏那一组、迁移页那个来源同名。
- 迁移页只给搜索框、不给类别胶囊：它列的是**候选**（隐藏会话按设计不进候选），子代理 / 空白 / 已归档
  在那页永远是 0，摆出来只会让人以为筛选坏了。
- 搜索**标题与 id 都搜**：id 永远在、标题可能没有（老会话日志里就没有标题事件），区别只是行上显示
  哪一个。关键词与类别是两条独立的轴，一起用时是「与」。
