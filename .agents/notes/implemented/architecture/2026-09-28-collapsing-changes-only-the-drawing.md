# Agent Note: 折叠只改「画不画」

Status: implemented

## Problem

分组列表能折叠。问题是一个组收起来之后，「收起来的那些还算不算数」——要不要从勾选集里摘掉、要不要
从「显示 N / M 条」里减掉。

## Decision

折叠**只改显示，不改计算**：组头最前那个按钮把组内的行收起来，组头自己留着（连着「这组几条 /
勾了几条」）；收起来的是显示，不是「算不算」。列表高度是固定的，所以折叠不会改整页高度。

折叠状态的键与 React 的 key 都是 `groups.groupKey()`；「全部收起 / 全部展开」只对**眼下列出来**的
那些组生效——没画出来的组是什么状态看不出来，也不必记住。

## Alternatives considered

**折叠时把组内的行从「列出来的」里摘出去。** 那等于「点一下箭头悄悄改了要导出的东西」，而头部一直
报着「显示 N / M 条」，两者一对不上就是 bug。

**折叠时不报组内的条数。** 一个目录收起来之后，「里面有几条、勾了几条」正是最该看见的信息。

**折叠按钮放在组头末尾。** 树的惯例是左缘就是「这一组能不能折」的位置；代价是组头的内容整体右移了
一个开关的宽度，组内那些行的缩进得跟着加同样多（`.dsm-group > .dsm-row` 的 `padding-left: 48px`
= 4px 内边距 + 20px 开关 + 8px 间距 + 16px），否则组头的勾选框会跑到组内行的右边去，「行挂在组头
下面」就反了。这一档是量着调的：行里的标题因此窄了 22px（实测组头勾选框 x=504、组内行 x=520、
标题列 255px）。

## Consequences

- 组头的结构从「一个 label 包住整行」变成「一个 div 装着按钮与 label」：整组勾选那一块仍是 label
  （点组头任意一处仍等于勾上／取消整组），折叠按钮留在它外面——label 里放可交互元素是非法嵌套，
  点击行为也会两头打架。
- 真实 GUI 里量到的：35 行 → 33 行 → 0 行，列表框 242px、卡片 508px、外层 `scrollHeight` 898px、
  卡头按钮 x 845/927 全都不动。
