# Agent Note: 同步的计划与落地并进同一个弹窗

Status: implemented

## Problem

「WebDAV 同步」那一面是一枚 640 的弹窗，按「同步」之后再叠一枚 1080 的确认弹窗（标题「将要同步」）。
两枚弹窗说的是同一件事的两段：后面那枚把前面那枚整个盖住，关掉它又回到前面那枚——用户看到的是
"点一下，跳出一个新窗口，再关掉，回到旧窗口"。

同一轮里已经踩过两次同一个形状：导出 / 导入并在一枚弹窗里时，导出那半把列表又画了一遍；同步面板里
套了一张标题与弹窗标题一字不差的卡片。导入先改成了"同一个弹窗里的三段"（填表单 → 将要写入 →
导入中…），同步这一面还是两枚。

## Decision

同步的三段（面板 → 计划 → 落地）放进**同一个弹窗**，外壳归 `SyncPanel` 自己：

- 弹窗的标题、说明、宽度、底栏都跟着这一段换：面板段 640 / 标题「WebDAV 同步」/ 远端地址挂在
  `description` / 底栏「取消 · 同步」；计划段标题「将要同步」/ 底栏「返回 · 确认同步」；落地段标题
  「同步中…」/ 正文换进度块 / 底栏「转到后台 · 同步中…」。
- 计划段的「取消」变成「返回」：回到面板，可以改完再算一次，不必整枚关掉重来（与导入那一段同一套）。
- **宽度跟着里面摆什么走**：面板段与"两边一样、没有要同步的"那种计划段都只有几句话，640 正好；
  计划里有表（会拉取 / 会推送 / 本机独有的那些）时才要 1080——三张表在 640 里会把动作列挤成一个字。
- 页面那一级不再替它包外壳（`ManagerPanel` 只渲染 `<SyncPanel … onClose={close} />`），因为标题、
  宽度与底栏都要跟着段变，只有这一面自己知道现在是哪一段。

顺带清掉两处随之失效的东西：`ConfirmDialog` 的 `wide` 那一档（唯一的使用者是同步的计划，现在没有
调用方了），以及注释里"卡片底部那条动作行"那套说法。

## Alternatives considered

- **保持两枚弹窗，只把宽度换过来**（面板 640、计划 1080，已经是上一轮的状态）：仍然是"点一下跳出一枚
  新窗口"，正是这次要消掉的那一下。
- **合并后固定 1080**：面板段只有四行话，铺到一千像素右边空一大块；这正是前一轮从 1080 收到 640 的
  理由。
- **合并后固定 640，让计划表横向滚动**：三张表的动作列、会话列、机器列、差异列挤在 620 里，横向滚动
  在弹窗正文里最难用。
- **把计划的正文改成纵向清单**（一条会话一段）以适配 640：那是另一套排版，得重做那三张表的读法与
  分组，收益只是省掉一次宽度变化。

## Consequences

- 按下「同步」与按「返回」时弹窗宽度会变（640 ↔ 1080）：这是"里面装什么"的诚实反映，代价是一次跳动。
- 落地那一趟切到后台（「转到后台」）之后，弹窗关掉，进度回到状态栏那一格——这条路径与之前一致。
- `SyncPanel` 从"一面的正文"变成"一整个弹窗"：它得自己拿 `onClose`，页面那一级只负责把认领来的
  结论递进去（`backgroundLine`）。
- 计划段不再有 ConfirmDialog 的「预演中…」外壳：那几秒由它自己画进度块（与导入那一段同一个写法）。
