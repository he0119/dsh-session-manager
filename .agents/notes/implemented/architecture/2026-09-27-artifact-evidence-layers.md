# Agent Note: 产物证据分层，并做两道收窄

Status: implemented

## Problem

「这个会话创建了哪些文件」只有强弱不同的证据，日志里能读到的东西不是一回事：

| 证据 | 强度 | 语义 |
|---|---|---|
| `write` 工具的 `file_path` | 权威 | 创建 |
| `deliverables/presented` | 权威 | 主动交付 |
| `edit` 工具的 `file_path` | 权威 | 修改（非创建） |
| `pwsh` / `bash` 命令里的造物路径 | 启发式 | 需含造物动词才计为候选 |

把四类混成一个集合、直接搬，会得到一份很难用的计划。

## Decision

权威证据直接进候选；启发式证据只进**候选**（不是结论），并叠两道收窄：

- **与磁盘存在性求交**——实测 51 个候选里 39 个早已被会话自己删掉；
- **嵌套剪枝**——某目录要整体搬走时，它内部的文件不再单独搬一遍。

## Alternatives considered

**只认权威证据，不读命令行。** 那会漏掉用 `pwsh` 造物的那批真实产物，而它们在日志里确实留着路径，
只是没有结构化标记。

**把命令行里的路径当成结论（不进候选）。** 一条 `rm`、一次 `cat` 都会留下路径，误报会直接变成
「会搬这些文件」的承诺。

**不做存在性求交。** 计划会列出大量早已不存在的文件，使用者无法判断这份计划可不可信。

**不做嵌套剪枝。** 同一批文件会被列两次（目录一次、目录里的文件各一次），搬的时候还得去重。

## Consequences

- 计划里的每一项都能追溯到是哪一类证据发现的，误报与漏报的方向是明确的（启发式只增不减候选）。
- 三道判据都在 `test/artifacts.test.ts` 里钉住，包括「39 / 51」那种量出来的比例不是靠推的。
