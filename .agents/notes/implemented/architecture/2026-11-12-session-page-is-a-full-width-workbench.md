# Agent Note: 会话管理页从设置区块变成全宽工作台

Status: implemented

> 这一篇的骨架（工具条 + 状态栏 + 工作台 + 平铺表）仍然成立；它写的"页头里放一排页签"那一半已被
> [去掉页签：四件事各是一处入口 + 一个宽弹窗](2026-11-12-no-page-tabs.md) 取代。

## Problem

「会话管理」原先注册在 `settings.section` 里，是设置弹窗里的一格：内容列最宽 **960px**、居中，滚动与
左右内边距都归设置外壳。搬进侧栏（`main` + `sidebar.panellist`）之后，那一格没了，页面占的是整块
主栏，可是里面那条约 960px 的内容列还留着——1920 的窗口减去宿主侧栏，两侧加起来空出七百像素左右，
页面看着像"设置页被摊在了整块空白上"。

同一份设置形态还带来三件事：

- 列表高度写死 `min(420px, 42vh)`。卡片被拉宽之后是一条 1600×420 的横带，翻到第三十条时筛选条
  早跟着整页滚走了；
- 会话按目录分组、组头吸走"这条属于哪个项目"，于是没法跨项目按时间或大小排；
- 看一条会话的内容要开 640px 的弹窗，宽屏上看内容与看列表是两件事。

用户的原话是"既然现在是侧边栏的入口，那应该占满整个页面"。占满只是其中一半：另一半是宽出来的
地方放什么，以及哪些东西该一直看得见。

## Decision

页面骨架改成**一条工具栏 + 内容 + 一条状态栏**：

- 顶栏一行：标题（16px/500）、页内分页（官方 `SegmentedControl`）、右端「刷新」与「插件设置」；
- 底部状态栏：会话库路径、会话数与工作区数、版本号（版本号原先在右下角单独一行）；
- 内容占满主栏的宽度，**页面本身不滚**：其余分页在 `.dsm-panel` 里滚，「会话」页滚的是卡片里的
  列表（`.dsm-listFill`），表头 `position: sticky` 贴在列表顶，底部动作行留在卡片底边。

「会话」页由按目录分组改成**平铺表格**：

- 多一列「项目」——平铺之后它是"这条属于哪个目录"的唯一出处，在册项目写工作区标题、没登记的写路径；
- 表头三列可点着排（标题 / 大小 / 时间），默认时间从新到旧；排序只改看，不写盘。比较与筛选是
  纯函数（[manageRows.ts](../../../../src/client/logic/manageRows.ts)），`test/manageRows.test.ts` 直接测；
- 组头取消之后，"这条属于哪个项目""只看这个项目""整组处理"三件事挪到**左侧项目树**（见下）。

### 左栏：项目与筛选

- 左栏 208px，是一张与列表同规格的卡片：头（项目数）、项目清单（自己滚）、底部的筛选段。
  「全部项目」+ 每个项目，各带**整库**条数；点项目名 = 只看它，选中的行有底色。
- 鼠标停在项目行上（或键盘落在这一行）出现一枚勾选框，点它就是整组勾选；勾了一部分画横杠，整个
  项目都勾上就一直显形。作用面与卡头「全选」一致，都是**筛出来的那些**——不是库里所有条，免得
  勾了看不见的行。这个项目在当前视图里一条可勾的都没有时，勾选框干脆不画（画一个点不动的只是噪音）。
- 筛选标签从列表上方搬进左栏底部，搜索框留在卡头：项目与筛选都回答"中间这栏列哪些"，放在同一栏里
  比一个在左上、一个在列表顶上更好找。两者是「与」的关系；筛选标签上的条数始终按整库算，不随项目跳。
- 窄屏（这一块自己的宽度 ≤960px）左栏收成**浮动面板**：卡头出现「项目与筛选」，点开从左边滑出 280px，
  面板里那枚「关闭」或面板外面那块空白都能收起（见
  [浮动面板点外面就收起](../bug-fix/2026-11-13-overlay-closes-on-outside-click.md)）。宽屏与窄屏是
  **同一份 DOM**，靠容器查询换位置——不渲染两份，项目选中态与筛选标签就不会各说各话。阈值读的是
  工作台自己的宽度而不是窗口：宿主侧栏可以收起，同一个窗口下页面可用宽能差两百多像素。

### 右栏：详情

- 右栏 340px（不是 360：再宽 20px，1600 窗口的标题列就只剩 158px），一张与列表同规格的卡片：
  头、正文（标题、分类标签、项目 / 目录 / 创建时间 / 大小 / 文件数 / 会话 id）、卡底三枚动作。
  正文自己滚，头与动作行不动。
- 行尾悬停有两枚动作：「详情」把这一条交给右栏（不打开弹窗、不改变勾选），「内容」仍直接打开完整
  时间线。两件事分开：右栏答"这条是什么"，弹窗答"它都说了什么"。
- 右栏正开着的那一行左缘有一条品牌色细线、加一层淡底色；换一条只是换右栏内容，列表不跳走。
- 单条动作：打开完整内容（弹窗）、归档 / 取消归档、勾选 / 取消勾选。从右栏归档**单条**时不清手上
  那批勾选；勾选那枚与行上的勾选框同源，子智能体仍是禁用的。
- 宽屏（工作台可用宽 >1180px）右栏一直摆着，没选会话时是一句提示；≤1180px 收成从右边滑出的 340px
  浮动面板，没选时整栏不出现，点「关闭」或点浮动面板外面那块空白收起（见
  [浮动面板点外面就收起](../bug-fix/2026-11-13-overlay-closes-on-outside-click.md)）。宽窄是同一份
  DOM，
  靠容器查询换位置。

### 右栏的开头两轮

- 右栏在元数据之前先摆**开头两轮**：每轮一条人的消息 + 一条回答，各最多四行。读的是
  `/transcript?id=…&limit=240&maxChars=600` 的第一页，不把整份时间线拉进这一栏；思考块、工具入参
  与结果都不进来。
- 只认人发的消息（`synthetic` 是标题模型那种调用）；回答取这一轮**最后**一条有文字的，前面那些
  流式片段不重复。轮次边界与内容视图共用 `transcriptTurns.ts`。
- 这一页正好切在第二轮中间时（`nextCursor` 还在、最后一节没有 `turn/end`），把那半截丢掉——它往往
  只是"我先改一下"的过渡句。丢掉之后只剩一轮就只摆一轮，说明里写"最多两轮"。
- 选中一条才读；读到的按会话 id 缓存在组件里，宿主那侧还有日志解压缓存。读失败不写缓存，再选一次
  会重试。窄屏浮动面板、宽屏右栏是同一份 DOM，取数也同一份。
- 这一栏不做 Markdown 渲染：日志里是 `**…**` / 反引号就照原样摆（与内容视图一致），四行截断之后
  交给「打开完整内容」。

### 其余分页与说明

- 传输 / 同步 / 备份是表单与清单，正文限在 **1080px 居中**；「会话」是工作台，继续吃满。1600 窗口下
  一段同步说明原来会拉成一千二百多像素的长行，控件全挤在左边；限宽之后 1080 的正文与表单终于像一个
  整体。1080 是量出来的：再窄，同步的计划表与传输的五行清单就开始折行。
- 「传输」在这 1080 内**再分两栏**：导出 `1.3fr`、导入 `minmax(320px, 0.9fr)`，1600 下量到
  **625.8 + 433.2**，两张卡的顶边都在 70，正文不滚（`scrollHeight - clientHeight = 0`），导入卡
  304 高、不再落到首屏之外。阈值是这一块自己的宽度（wrapper 上的容器查询 ≤900 叠回一列），
  1024 下量到一列 691、导入卡顶边 720，与原来一样要滚。
- 「说明」不再是第五枚页签：页头那枚「?」把它开成官方 `Modal`（760px）。四节（分类 / 每页做什么 /
  数据从哪来 / 常见疑问）在弹窗正文里，节与节 16px；弹窗本身就是容器，四节不再各套一圈卡片壳。
  入口与「刷新」「插件设置」同排，都是页面级动作；关闭回到原来的分页。
- 说明里「会话」那一段跟着工作台改写：不再是"列表按目录分组"，而是"左边按项目筛、中间平铺、行尾看
  详情"。词条与标签文案仍复用同一份字典。

**全宽不等于所有东西都拉满**：表单与说明已经按可读宽度限——传输 / 同步 / 备份 1080px 居中，说明
760px 弹窗。页面宽度分档（≥1560 三栏 / 1200–1559 项目树收进工具栏 / 900–1199 详情变抽屉 / <900 单栏）
里的左栏、右栏、两处窄屏浮动面板与其余分页都已经落地；<900 时宿主把侧栏收成一列图标，
  这一页的页头仍是
一行。

## 量到的

在真实 dev GUI（1600×1000、1280×900、1920×1080 三个窗口）里量过：

- 1600 的窗口：页面可用宽 **1320px**、工作台 **1267px**（左栏 208 + 间距 16 + 列表 1043）；表头与
  行的网格逐列相同（`24 16 minmax(0,1.4fr) 168 84 120`），时间那一列 120px 正好放下
  `2026-10-13 15:06`（实测 110px）；
- 页面自身 `scrollHeight - innerHeight = 0`；底部动作行在 1000 高的窗口里 `bottom = 874`，始终可见；
- 状态栏 29px、顶栏 36px、卡片头部不动，列表拿到剩下的 599px 并在内容超高时自己滚；
- 加上左栏之后（1600 窗口，右栏还只是骨架时）：左栏 **208×869**、列表 **1043px**；筛选段 103px 高，
  项目清单拿到其余高度并自己滚；
- 三栏齐了之后（1600 窗口）：工作台 **1267px** = 左栏 208 + 间距 16 + 列表 **687** + 间距 16 + 右栏
  **340**；列表没有横向滚动（`scrollWidth - clientWidth = 0`），标题列从 534px 收到 **178px**
  （实测），长标题截断、完整标题在右栏；
- 1920 窗口：工作台 **1587px**、列表 **1007px**、右栏 340、左栏 208；
- 1280 窗口：页面 1000px（宿主侧栏 280），工作台 **947px**——低于左栏那档 960px，左栏收成浮动面板；
  右栏也低于 1180px，量到浮动面板 **340×769**，贴着工作台右缘，列表仍是 **947px**；
- 1200 窗口：工作台 **867px**，左栏浮动面板 280×769；
- 1024 窗口：卡片 **661px**、表格没有横向滚动，四个数字列与时间仍放得下；
- 其余三页限宽之后：1600 窗口下 `.dsm-panel` 量到 **1080px**，左边距 400（页面 1320 居中）；1024 窗口
  下 **696px**（页宽 724）；900 窗口下宿主侧栏收成 80px 图标，页面反而有 **796px**，页头仍是一行；
- 说明弹窗：1600 窗口下 **760×952**，正文滚动 950px（`scrollHeight - clientHeight`）；四节边框
  0px（弹窗里不再套卡片壳）；
- 传输页并排之后（1600 窗口）：网格 **625.8 + 433.2**，两张卡顶边 70，正文不滚；导出卡 674 高、
  导入卡 304 高；1024 窗口下网格 **691**（一列），导入卡顶边 720；
- 右栏开头两轮（1600 窗口、340px 宽）：一轮量到 **222px** 高（四行回答 + 轮次标签 + 说明），
  `-webkit-line-clamp: 4` 生效；这一条的第二轮被切在中间，只摆出完整的第一轮，右栏正文没有滚动。
  选中「待补日期含义、补齐与部署」时从点击到出内容约一秒内（首屏读 240 条事件；同一会话再选命中
  组件缓存）。

## Alternatives considered

**保留 960 居中，只把卡片铺满。** 宽屏上两侧仍旧空着；用户说的"占满整个页面"就是这个现象。

**只去掉宽度上限，列表仍按目录分组、高度仍固定 420。** 宽屏上是一条很长很矮的横带，且不能跨项目
按时间排；"按大小找最大的那份日志"这类事做不了。

**顶部的页签改成左侧竖导航。** 宿主本来就有一条左侧栏，再贴一条竖导航会读成"应用里套应用"；
而且项目树才是真正需要左栏的那一块，导航先占掉就没地方了。

**直接上主从双栏（左列表 + 右详情）。** 这是目标形态，但它依赖"平铺 + 表头 + 固定动作行"这套骨架
先在真实窗口里站住；一次改完会让宽度、滚动、勾选三件事同时出问题，没法量。所以拆成四步，这一步只
做骨架与平铺。

**左栏用一个原生 `<select>` 或一列纯文字链接。** `<option>` 只有一行可用，项目名与条数放不下，
也没有整组勾选框与悬浮提示；这一页还有一条"整页没有原生下拉框"的既有断言。

**左栏只放项目，筛选标签留在列表上方。** 那样窄屏收起左栏时筛选还在，不用再给筛选找第二个落点；
代价是宽屏上列表上方多占一行、左栏下半截空着。这一版把两者放在同一栏，窄屏时整栏一起收进浮动面板。

**详情仍然只开弹窗。** 宽屏上一眼能看见的信息还要点开、读完整份日志才能拿到，而且弹窗一关列表就
回到"什么都不知道"。右栏把"这条是什么"留在屏幕上，弹窗只负责完整时间线。

**点整行打开右栏。** 行本身是勾选面（点哪儿都切换勾选），这是这一页批量归档 / 删除的主要动作；
改成点行开右栏会让"勾一条"必须先瞄准勾选框。悬停那枚「详情」是显式的第二入口，两件事不抢。

**右栏只在选中时插进布局。** 那样没选时列表能宽 340px，但每次选一条列表就跳一次宽度，三栏的
骨架也不成立。这一版宽屏一直摆着，空态是一句提示。

**把「详情」与「内容」合成一枚。** 两件事：右栏是"这条是什么"（项目、目录、大小、时间、单条动作），
内容是"它都说了什么"（完整时间线）。合成一枚之后，想看一眼归属也得把整份日志读进弹窗。

**让其余三页也跟着吃满。** 1600 窗口下一段同步说明会拉成一千二百多像素的长行，表单控件缩在左边，
读起来要来回摆头；三页本来也不是工作台，是表单与清单。这一版给它们 1080px 并居中，只有「会话」吃满。

**说明继续占第五枚页签。** 它是一次性读的参考，不是日常动作；放在页签里会让"会话 / 传输 / 同步 /
备份"这四件事多一枚不常用的邻居，也把窄屏的页签挤到换行。这一版挪到页头「?」，开成弹窗。

**说明也做成一张 1080px 的页面（不用弹窗）。** 那样读的时候会离开当前分页，回来还得再点一次；弹窗
关掉就回到原来的页签，读词条与做事不互相打断。

**传输页维持上下堆叠。** 1600 窗口下导入卡要滚过整张导出列表才看得到，而这两件事（带走 / 带回来）
本来就该并排比较。这一版在 1080 内分两栏，导出宽、导入窄。

**传输页两栏各占一半。** 导出是五行清单（标题 / 项目 / 标签 / 大小 / 时间），一半宽会挤；导入是
320px 的字段。1.3 / 0.9 让清单拿到 626、字段拿到 433，两边都不折。

**把两张卡拉成等高。** 导入卡只有 304 高，拉高之后字段下面是一大片空；这一版按内容高度、顶边对齐。

**把整份时间线直接摆进右栏。** 340px 宽的一栏里，思考块、工具入参与结果会把两轮对话埋掉，也会让
每选一条都读整份日志。这一版只取第一页的前两轮，完整内容仍归弹窗。

**为开头单开一个宿主端点。** 现有的 `/transcript` 已经支持 `limit` / `maxChars`，读的是同一条日志、
同一套缓存；为预览再开一条端点会把"轮次怎么切"复制到宿主那一侧。这一版复用内容视图那一页接口。

## Consequences

- `docs/design.md` §2.1 的"内容列最宽 960px 居中"与 §2.3 的"组头 + 固定 420px 高"被删掉，改成
  工具条 / 状态栏 / 平铺表；
- 页头那篇旧决策（[页头照内建设置页](2026-09-28-page-header-matches-the-builtin-settings.md)）在
  "设置里一格"的前提下成立，这一页搬出来之后不再适用；那篇留着当历史，链接指到这里；
- 会话页的组头与折叠不再渲染；整组勾选搬到了项目树的行上（悬停出现），作用面与卡头「全选」一致；
  组头那套仍属于「传输」页；
- 窄屏的浮动面板是一次额外的点击（打开、关掉）；换来的是宽屏上项目树一直占着左栏。
  浮动面板现在只认「关闭」
  按钮，点外面不会收起——与目录字段的面板同一套行为；
- 平铺之后子智能体不再缩进，仍挂「子智能体」标签；父会话在别的项目里时挂「父在别处」的备注，
  "删了这条会带走谁"没有跟着缩进一起丢；
- 父在别处的备注与"父被筛掉"的旧画法不同：平铺不问父在不在当前筛选里，只问它在不在同一个项目里；
- 三栏之后 1600 窗口的标题列只剩约 215px，长标题要截断（完整标题在右栏与悬浮提示里）；这是右栏
  常驻的代价，不打算再把右栏收窄——再窄，目录与 id 就开始折行；
- 触屏没有悬停：行尾两枚动作顶替时刻那一格常显，时间要看右栏。桌面浏览器不受影响（悬停才出现）；
- 传输 / 同步 / 备份在 1600 窗口下左右各留 120px、1920 下各留 250px 的空白；换来的是说明句不拉成长行。
