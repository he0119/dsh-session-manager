# Agent Note: 会话管理页从设置区块变成全宽工作台

Status: implemented

## Problem

「会话管理」原先注册在 `settings.section` 里，是设置弹窗里的一格：内容列最宽 **960px**、居中，滚动与
左右内边距都归设置外壳。搬进侧栏（`main` + `sidebar.panellist`）之后，那一格没了，页面占的是整块
主栏，可是里面那条约 960px 的内容列还留着——1920 的窗口减去宿主侧栏，两侧加起来空出七百像素左右，
页面看着像"设置页被摊在了整块空白上"。

同一份设置形态还带来三件事：

- 列表高度写死 `min(420px, 42vh)`。卡片被拉宽之后是一条 1600×420 的横带，翻到第三十条时筛选条
  早跟着整页滚走了；
- 会话按目录分组、组头吸走"这条属于哪个项目"，于是没法跨项目按时间或大小排；
- 看一条会话的内容要开 640px 的弹窗，宽屏上看内容与看列表是两件事。

用户的原话是"既然现在是侧边栏的入口，那应该占满整个页面"。占满只是其中一半：另一半是宽出来的
地方放什么，以及哪些东西该一直看得见。

## Decision

页面骨架改成**一条工具栏 + 内容 + 一条状态栏**：

- 顶栏一行：标题（16px/500）、页内分页（官方 `SegmentedControl`）、右端「刷新」与「插件设置」；
- 底部状态栏：会话库路径、会话数与工作区数、版本号（版本号原先在右下角单独一行）；
- 内容占满主栏的宽度，**页面本身不滚**：其余分页在 `.dsm-panel` 里滚，「会话」页滚的是卡片里的
  列表（`.dsm-listFill`），表头 `position: sticky` 贴在列表顶，底部动作行留在卡片底边。

「会话」页由按目录分组改成**平铺表格**：

- 多一列「项目」——平铺之后它是"这条属于哪个目录"的唯一出处，在册项目写工作区标题、没登记的写路径；
- 表头三列可点着排（标题 / 大小 / 时间），默认时间从新到旧；排序只改看，不写盘。比较与筛选是
  纯函数（[manageRows.ts](../../../../src/client/logic/manageRows.ts)），`test/manageRows.test.ts` 直接测；
- 组头取消之后，「整组处理」改成"项目选择器选一个项目 → 卡头的全选"两步。选择器是一枚值控件 +
  浮层面板，不用原生 `<select>`：`<option>` 只有一行可用，项目名与条数放不下，也没有悬浮提示
  （与目录字段同一个理由，见 [目录字段是一枚值控件](2026-09-27-directory-field-is-one-value-control.md)）。

**全宽不等于所有东西都拉满**：列表吃满宽度，表单与说明仍然按可读宽度限（第四步落地）。页面宽度分档
（≥1560 三栏 / 1200–1559 项目树收进工具栏 / 900–1199 详情变抽屉 / <900 单栏）与左侧项目树、右侧
详情栏是接下来的三步，等这一步在真实窗口里量稳了再做。

## 量到的

在真实 dev GUI（1600×1000、1280×900、1920×1080 三个窗口）里量过：

- 1600 的窗口：页面可用宽 **1320px**、卡片 **1267px**、列表 **1237px**；表头与行的网格逐列相同
  （`24 16 minmax(0,1.4fr) 168 84 120`），时间那一列 120px 正好放下 `2026-10-13 15:06`（实测
  110px）；
- 页面自身 `scrollHeight - innerHeight = 0`；底部动作行在 1000 高的窗口里 `bottom = 874`，始终可见；
- 状态栏 29px、顶栏 36px、卡片头部不动，列表拿到剩下的 599px 并在内容超高时自己滚。

## Alternatives considered

**保留 960 居中，只把卡片铺满。** 宽屏上两侧仍旧空着；用户说的"占满整个页面"就是这个现象。

**只去掉宽度上限，列表仍按目录分组、高度仍固定 420。** 宽屏上是一条很长很矮的横带，且不能跨项目
按时间排；"按大小找最大的那份日志"这类事做不了。

**顶部五个页签改成左侧竖导航。** 宿主本来就有一条左侧栏，再贴一条竖导航会读成"应用里套应用"；
而且项目树（下一步）才是真正需要左栏的那一块，导航先占掉就没地方了。

**直接上主从双栏（左列表 + 右详情）。** 这是目标形态，但它依赖"平铺 + 表头 + 固定动作行"这套骨架
先在真实窗口里站住；一次改完会让宽度、滚动、勾选三件事同时出问题，没法量。所以拆成四步，这一步只
做骨架与平铺。

**项目选择器用原生 `<select>`。** 见上：一行放不下名字与条数，也没有悬浮提示；这一页还有一条
"整页没有原生下拉框"的既有断言。

## Consequences

- `docs/design.md` §2.1 的"内容列最宽 960px 居中"与 §2.3 的"组头 + 固定 420px 高"被删掉，改成
  工具条 / 状态栏 / 平铺表；
- 页头那篇旧决策（[页头照内建设置页](2026-09-28-page-header-matches-the-builtin-settings.md)）在
  "设置里一格"的前提下成立，这一页搬出来之后不再适用；那篇留着当历史，链接指到这里；
- 会话页的组头、折叠与整组勾选不再渲染；**下一步**的项目树会把"整组勾选"以一次点击的形式补回来。
  在补回来之前，整组处理是"选项目 → 全选"两步——能力没有丢，只多一步；
- 平铺之后子智能体不再缩进，仍挂「子智能体」标签；父会话在别的项目里时挂「父在别处」的备注，
  "删了这条会带走谁"没有跟着缩进一起丢；
- 父在别处的备注与"父被筛掉"的旧画法不同：平铺不问父在不在当前筛选里，只问它在不在同一个项目里。
