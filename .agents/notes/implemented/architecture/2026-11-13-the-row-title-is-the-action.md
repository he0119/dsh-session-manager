# Agent Note: 行这一格的主动作落在标题上，行尾不再有动作

Status: implemented

## Problem

行尾那枚「详情」是键盘唯一的入口，可它平时是藏着的（`visibility: hidden`，Tab 落到这一行的勾选框
才顶掉时刻出场），并且要靠一套叠格子（`.dsm-slot` + `:focus-within`）才不撑动行宽。对鼠标用户它多
一层没用的机关，对键盘用户它要按两次 Tab 才够得着；而"看这一条"本来就是这一行的主动作。

## Decision

- **行从 `<label>` 换成 `<div>`**：点的落点是"看详情"，不是"勾选"。勾选只剩最左边那枚勾选框，
  它有自己的一层 `<label class="dsm-rowPick">` 与一句只念给读屏软件的"勾选《标题》"（`.dsm-srOnly`）。
- **标题那一格是按钮**（`.dsm-rowOpen`）：整行的主动作落在它身上，键盘 Tab 到它、回车就打开右栏。
  它是个真的 `<button type="button">`，但把浏览器给按钮的默认外观全摘掉（边框、底色、内边距、字号、
  居中），外观跟旁边那段字一样；焦点环自己给（`focus-visible`，品牌色 2px）。
- **行尾只剩时刻**：`.dsm-slot` / `.dsm-slotActions` / `.dsm-rowDetail` 与 `:focus-within` 那几条
  一起删掉，那一格回到普通的元信息。
- 别的页（导出 / 迁移挑选）的行仍旧是 `<label>`：那里点哪儿都是勾选，没有"看详情"可开。

## Alternatives considered

**只删按钮，不给键盘留路。** 键盘用户就再也打不开右栏：这一行不是可聚焦控件，Tab 落在勾选框上，
回车是"勾选"；完整时间线又只有右栏里那一枚「打开完整内容」能开。等于把"读会话内容"从键盘上抹掉。

**留着那枚只给键盘的「详情」，把它挪进行尾更靠前的位置。** 那还是"行里藏一枚看不见的按钮"：
叠格子那套机关继续存在，键盘仍要两次 Tab，鼠标用户看到的东西一点没变。

**把整行做成 `role="button"`。** 行里嵌着勾选框，`role="button"` 的子节点会被当成装饰，屏幕阅读器
把整行读成一个按钮、吞掉勾选框——勾选这条路就断了。

**让标题 `<span role="button" tabIndex={0}>` 留在 `<label>` 里。** 省掉换元素，但 `<label>` 里放
交互内容本身不合法，读屏软件会把它的内容并进勾选框的名字里。

## Consequences

- 鼠标 / 触屏：点行里任何地方（标题、项目、字节、时间、空白）都打开右栏；点勾选框只改勾选。
- 键盘：Tab 到勾选框 → Tab 到标题按钮（那一格就是这一条的名字）→ 回车打开右栏。
- 行里没有第二枚动作，行尾那一格与别的列一样宽，不再靠叠格子藏东西。
- 由 `test/client.test.mjs`（行是 div、标题是按钮且停冒泡、勾选框那层 label 有只念给读屏软件的名字、
  行尾没有 `.dsm-rowDetail` / `.dsm-slot`）与 `test/styles.test.mjs`（`.dsm-rowOpen` 摘掉默认外观、
  `.dsm-srOnly` 不参与布局、那三条旧规则确实没了）钉住。篡改验过：摘掉 `text-align`、删掉
  `.dsm-srOnly`、去掉标题按钮的 `stopPropagation`、把 `dsm-rowOpen` 这个类去掉，四处各自变红。
- 真实 dev GUI 里量到的（1600 窗口，深浅两套各看一遍）：行是 `DIV`、标题是 `BUTTON`（`border 0px`、
  `padding 0`、透明底、14px 正文色，与旁边的字一致）；文字为「详情」的按钮 0 个；点行右侧 → 右栏
  换成那一条、勾选框一个没动；焦点落在标题按钮上（焦点环 2px）按回车 → 右栏换成那一条；点勾选框 →
  只勾上这一条，右栏不动；`.dsm-srOnly` 实测 1px。
