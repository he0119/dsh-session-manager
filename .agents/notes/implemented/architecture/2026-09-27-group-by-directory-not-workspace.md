# Agent Note: 列整库的两个分页按目录分组

Status: implemented

## Problem

要带走一批会话时，人的说法永远是「把这个工作区的会话都带走」，所以列表得一组一组地给，组头就是整组
勾选；要收拾一批会话时（归档 / 删除）说的是同一句话。

**分组键有两个候选**：目录（`cwd`）与注册表里的工作区 id。而这两件事经常不是一回事——注册表的
`sessionIds` 只是「登记在册」的那部分。真实库里就能看到这个差：写这份文档时
`~/dev/dsh-session-manager` 注册表登记 5 条、目录里实际 7 条；`~/test` 登记 5 条、实际 6 条。

## Decision

分组键取**目录**（`cwd`），不取工作区 id。工作区标题只是这个路径的**标签**（登记过才有；没登记的
目录直接显示路径并标出来）。

## Alternatives considered

**按工作区 id 分组。** 会同时犯两个错：把一个目录劈成「工作区」与「未登记」两组，而且两组都不是
使用者想带走的那一批。

**不分组，平铺一列。** 「带走这个目录的会话」就要一条条勾；而组头那个三态勾选框（全选／部分／未选）
承担的正是这件事。

**按注册表分组，未登记的单列一组。** 那就是上面那个「劈成两组」，只是把第二组摆到明面上。

## Consequences

- 组头的条数会大于注册表里的登记数，差额落在挂「未登记在册」标签的那几行上——标签是**逐行**的，
  不能按组一刀切。
- 「未分组」在这两页上因此是一枚**标签 / 筛选类别**，不是一个可整批带走的实体（外壳那一组可以横跨
  多个目录）——见 [「未分组」就是外壳那一组](../bug-fix/2026-09-28-ungrouped-means-the-sidebar-group.md)。
- 顺序与边界（组间顺序、重复路径、空串 `cwd`、组内定序）在 `test/groups.test.ts` 里钉着。
