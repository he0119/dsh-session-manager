# Agent Note: 目录字段点开一份候选面板，值控件不再是原生下拉框

Status: implemented

## Problem

候选是「已登记工作区 + 库里有会话的目录 +『未分组』」——工作区一多就是几十条，而这个列表只有**一行
字**可用：名字、项目身份、本机路径、库里条数只能挤成一串，挤不下就截断（原生 `<option>` 连悬浮提示都
没有）；找一条只能滚动，或者靠打字跳转（只认行首）。仓库在本机的两个克隆正是在路径那一段才分得开。

把筛选框挂在字段标题那一行的右端只解决了一半：它离被它筛的那个列表隔着一整个字段的距离，一眼看不出
它筛的是谁；一行里还并着字段名与值控件，三件东西读起来互不相干。

## Decision

**值控件是一枚按钮，点开的是候选面板**；字段里只剩两件东西——这枚按钮与「手输路径」。

- **按钮的文本就是那个值**（长值单行截断，完整值在它的悬浮提示里）：能对上候选时显示那一行的称呼
  （`pathLabel()`），否则原样显示路径；「未分组」显示成人话（`UNOWNED_SOURCE` 不上界面）；
- **面板与页面内那个目录浏览框同一套皮、同一个列表**（`.dsm-browser` + `.dsm-dirList`）：一边是"从候选里
  挑"、一边是"去文件系统里找"，两边的头各有一枚按钮互相切（`dirPicker.filesystem` /
  `dirPicker.candidates`）。宿主没有目录选择器时**不摆**那枚「浏览文件系统…」——不摆一个点了必然报错的
  按钮（同 [「浏览…」按宿主的能力走](../bug-fix/2026-09-27-browse-follows-the-picker-capability.md)）；
- **面板里一行两行字**：第一行名字（工作区标题 → 那一行自带的文案 → 项目名 → 本机路径），第二行本机
  路径与条数，整串（身份 + 路径 + 条数）退到悬浮提示里（`candidateRow()`）。`<option>` 只有一行可用，
  所以那边仍旧是 `pathLabel()` 的一整串——**同一份事实，两种摆法**，差别写在两个函数的文档里；
- **面板自带筛选框**（`filterPathRows()`），规则沿用
  [目录字段那篇](2026-09-27-directory-field-is-one-value-control.md)：只收窄列表、不碰值，对行自己的事实
  匹配，顺序照旧；
- **点一行就是选中**，随即关掉面板：挑的是"要用的那个目录"，没有第二步要确认的东西——真正的确认在
  「迁移」那个弹窗里（计划 + 数量）；
- 值不在候选里时仍补一行进行里，那一行带 `aria-current`：值控件的文本与列表里的一行对得上。

## Alternatives considered

**保留原生下拉框 + 标题行筛选框（上一个形状）。** 筛选框离它筛的列表隔着一整个字段，一行三件控件互不
相干；下拉框那一行还是只能挤一串被截断的字（没有第二行可用，也没有悬浮提示）。

**值控件仍是下拉框，候选面板挂在「浏览…」那枚按钮上。** 一个值两种外观：下拉框展开的列表与面板是同一
份候选，用户会问哪一个算数。

**把筛选框挪到下拉框正上方（仍用下拉框）。** 位置对了，但一行一串的截断、没有第二行、没有悬浮提示都
还在。

**筛完只剩一条就自动选中。** 打字不等于确认：半句话命中一条就改值，按「迁移」时搬走的是另一个目录。

**删掉「手输路径」，只留面板。** 任意绝对路径是这条字段的定义：候选永远列不全（目标目录甚至可能还没
建），兜底的那条路不能少。

**面板里再给一条「新建目录」。** 那是另一个能力（宿主没给创建目录的接口），不在这条决策里。

**把面板做成浮层（拉在字段上方、挡住下面的内容）。** 页面内那份浏览框就在字段下展开，两个面板同处一处
才好互相切；浮层还要自己算定位与焦点陷阱，换来的只是不占页面高度。

## Consequences

- 值控件不再是原生控件：键盘走位与"这是一个可展开的控件"要自己交代（`aria-expanded` + 列表里真按钮），
  换来的是能画两行、能筛、与文件系统那条路收在同一处。
- 「框里显示的就是将要用的」变成"值控件的文本就是那个值"——比原来更直接（原来靠 `value` 绑在 `<select>` 上）。
- 这条形状不依赖宿主能力：能力缺失只是面板头里少一枚按钮，值与语义不变。
- 面板与浏览框共用 `.dsm-browser` / `.dsm-dirList` 那套皮，于是"候选列表长什么样"由这一份 CSS 说了算；
  `test/styles.test.mjs` 的颜色检查面照旧覆盖它（没有新增色值）。
