# Agent Note: 术语收进一张表，别处只放链接

Status: implemented

## Problem

同一个词在仓库里有两三种写法：**回合**与**轮次**混用、**半边**与**这一侧**混用、会话同步写成
**推上去 / 拉下来**、DSH 进程写成**宿主机**、把"安静了一段时间"写成**静默**（官方「静默」是"不报错地"）、
`Slot` 译成**槽位**、`Host 半侧` 缩成**Host 侧**。

这些词散落在界面文案、两份 README、`docs/*` 与几百行注释里。规则本身也散着：根 `AGENTS.md` 的「官方
文档」段末尾列了八个词，`docs/design.md` 第 156 行又复述一遍同一批词，两处都对不上第三个地方——
于是每加一个词得改两处，改漏一处就没人发现（门禁核不了措辞）。

## Decision

新建 [`docs/glossary.md`](../../../../docs/glossary.md) 当**术语的唯一真源**：一张表，四列——概念 / 官方说法 /
别写 / 出处。每个「官方说法」都要能在官方包的中文文案（`@deepseek-ai/*` 的 `lib/client.js`）或官方文档站
上找到原文，出处写清是哪一页、哪个包。

同时把另外两处的复述收成一行链接：根 `AGENTS.md` 只留"写新词之前先查那张表，表里没有就按三步加一行"，
`docs/design.md` 只留"术语照那张表写"。`docs/AGENTS.md` 与根 `AGENTS.md` 的文档分工表各加一行，认这份新
文档。

## Alternatives considered

- **把术语表放进 `AGENTS.md`**：那份文件每轮都在上下文里，塞一张二十行的表会把真正要每轮看的约束挤到
  后面；而且它已经有一句"每条信息只写一处"，术语本来就该有自己的家。
- **放进 `docs/design.md`**：术语不只服务界面，代码注释与 README 也照它写，放界面规格里会让人以为只对
  文案有效。
- **不做表，靠 code review 拦**：这正是现在的结果——两处复述、对不上，且没有任何门禁能核措辞。

## Consequences

- 术语只有一处可改；`AGENTS.md` 与 `design.md` 变短，链接指向术语表。
- 表里「出处」那一列是硬要求：没有官方原文的说法进不了表，只能写"本仓库自己的用语"（例如拉取 / 推送）。
- 这次顺带把全仓的旧词按表改了一遍：界面文案（回合→轮次、半边→两侧、推上去→推送、宿主机凭据库→DSH 的
  凭据）、两份 README、`docs/*` 与 `src/**` 的注释（`静默窗口`→`空闲窗口`、`分桶`→`分目录`、`槽位`→
  `Slot`、`Host 侧`→`Host 半侧`、`宿主机`→`宿主`）。历史笔记里的旧词留着当当时的原话，只有引用了现在还
  在的界面文案的那一处跟着改了。
- 差异弹窗那句「这半边没有多出来的」顺手拆成两句（本机 / 远端）：只说"这一侧"读者不知道是哪一侧。
