# Agent Note: 子智能体缩进到父会话的下一级

Status: implemented

## Problem

父子关系本来就在数据里（与删除 / 迁移的级联展开读的是**同一条边**），而平铺的列表把一族会话打散在
组内的排序里，只留一枚「子智能体」标签。于是「这条为什么在这儿」「删掉上面那一条会带走谁」只能靠读
标签猜。

## Decision

同一个目录组里，子智能体会话再往里缩一级、挂在它的父会话下面（`nestSessions()`）。行上照旧挂
「子智能体」标签——缩进说的是「它属于谁」，标签说的是「外壳侧边栏为什么把它藏起来」。

**缩进只改画法**：勾选、组头那串「这组几条 / 勾了几条」、「显示 N / M 条」、全选，算的都还是这些行，
与缩进无关。删除预演清单里「随父会话删」的那些也缩进一级。

视觉上用与组头那一档同一套手段：再缩进一格（24px，正好是一个勾选框列的宽度）+ 一条导引线，线画在
父行内容左缘那一格。层次不能只挂在缩进上——窄屏、长标题、色觉差异下，最先被压没的正是缩进。

## Alternatives considered

**只留标签，不缩进。** 标签回答的是「侧边栏为什么藏它」，不回答「它属于谁」；一族会话在列表里仍然
是散的。

**把子智能体挪进父会话所在的那一组。** 分组键是目录，勾组头 = 勾这个目录下的会话；挪过去之后那一下就
勾到了别的目录的会话，「整组勾选」于是变成假的。

**用更深的底色代替缩进。** 浅色主题里可用的只有「字色兑出来的薄雾」，它的可见度依赖屏幕与视力；
缩进与导引线跟颜色无关。

**导引线用 `box-shadow` 画。** inset 阴影的语义是「从左边起画 Npx 宽的带」，要画在第 50px 上就得先
铺 52px 的带、再擦掉左边 50px，而 box-shadow 只能叠不能擦。改成**底图**画的代价是那一行的悬停只能改
`background-color`——写成 `background` 简写会把底图一起清掉。

## Consequences

- 「列表里看到的父子」与「删 / 搬会带上谁」是同一棵树。
- 四条边界都会在真实库里遇到，各自有确定的画法：父会话在别的目录组里（留在本组缩进一级 + 「父在别
  目录」标签）、父会话不在当前视图里（按普通行画，不缩进）、分叉（按普通行画）、坏数据里的环
  （走完之后把没画过的按原顺序补在最后——宁可少一层缩进，也不能让会话凭空消失）。
- 真实 dev GUI 里量的（本机 16 条会话那一组，浅深两套主题同值）：顶层行 `padding-left` 48px
  （勾选框 x=520），一级子行 72px（x=544），二级 96px（x=568）；导引线 2px 宽、画在 x=50
  （二级再加一条 74），两套主题里都是 `label-primary` 兑 14% 的同一条色。行高不受缩进影响（33px）。
