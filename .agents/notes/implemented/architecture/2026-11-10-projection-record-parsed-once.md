# Agent Note: 投影记录解析一次就记住，重扫时只为变了的那些重解

Status: implemented

## Problem

列表页（`GET /state`）每条会话要读一份宿主的投影记录：标题、空白判据、两枚活动时间。本机 1325 个
文件、合计 170 MB，单个文件 100 KB 上下（最大的 1.3 MB），而这里只要四个字段。`JSON.parse` 整份实测
687～705 ms，是整趟扫描里最大的一块（扫描本身 1159～1203 ms，其中读日志头 0.42 s）。

扫描缓存（[库没变时复用上一次的扫描结果](2026-10-19-reuse-scan-results-between-refreshes.md)）只在
"整库一个文件都没变"时命中，而它的指纹里包含全部投影文件；只要有一条会话在跑，宿主就会重写那一条。
实际使用中打开这一页几乎每次都要重扫（本机连续 9 次 `GET /state` 全部重扫，第三次起才在"连续两次都
没动静"之后命中），于是这 0.7 秒每次都付。

## Decision

`src/projection-cache.ts` 的 `createProjectionReader()` 把解析过的记录按文件记住：先 `statSync()` 拿
`size + mtimeMs`，加上这次查询的身份（`createdAt` + `cwd`）拼成键；对上就把上次那份记录直接交出去
——连文件都不读。上限 4096 条，超过就整体清空（它是纯缓存，清掉只是下次多读一遍）。

同一份库、同一台机器、同一个进程里量：

| 量 | 实测 |
| --- | --- |
| 1325 份投影文件只读一遍（不解析） | 63～81 ms |
| 读 + `JSON.parse` 全部 | 687～705 ms |
| 扫一遍库（1295 条，带投影记录）：新读取器 | 1159～1203 ms |
| 同一读取器再扫一遍 | 395～421 ms |
| `GET /state` 第一次（新进程） | 1532 ms |
| `GET /state` 紧接第二次（指纹变了，重扫） | 582～648 ms |
| `GET /state` 第三次（指纹命中，整趟缓存） | 34～40 ms |

第二行到第三行的差就是这一层省的：重扫时那 1295 条记录里通常只有一两条刚被改写，其余只花一次
`statSync`。

## Alternatives considered

- **只解析需要的那几个字段（手写扫描或流式 JSON 解析）。** 能把 0.7 秒压到毫秒级，但要在本插件里复刻
  宿主记录文件的嵌套结构；宿主哪天换了格式，现在这种"整份解析 + 按形状认字段"会安全地退回"没有记录"，
  手写扫描会静默读错。等真的需要再往这一步走。
- **用宿主内存里的投影服务（`ctx.sessionProjectionCache`）。** 它只服务部分键：没有
  `sessionListMetadata`，也没有 `timeContext`——空白与两枚活动时间拿不到。细节与实测见
  [库没变时复用上一次的扫描结果](2026-10-19-reuse-scan-results-between-refreshes.md)。
- **把解析结果落盘。** 跨进程复用，但要多一份文件格式、版本号与失效逻辑；收益只在重启后的第一次
  （0.7 秒）。
- **把投影文件从扫描缓存的指纹里拿掉。** 宿主改了标题之后列表会一直显示旧标题。
- **按"一次扫描"记忆化（读取器每次新建）。** 那样只能省同一次扫描里的重复读，而重复读已经不存在了
  （见 [扫描时每样东西只读一次](2026-10-19-scan-reads-each-thing-once.md)）；这里要省的是**下一次**
  扫描，所以缓存得挂在进程级那个读取器上。

## Consequences

- 常驻内存：1295 条记录（每条四个字段）不到 1 MB。
- 缓存跟着读取器实例活：界面那一个（每次打开这一页都走它）跨请求复用；`src/tools.ts` 里每次调用新建的
  读取器只有单次扫描内的收益，没有跨调用的。
- 迁移、删除、重新生成名称这几条预演路也注入同一个读取器（见 `src/web.ts`）：它们照旧重扫库（那几步
  马上要动磁盘，见 [库没变时复用上一次的扫描结果](2026-10-19-reuse-scan-results-between-refreshes.md)），
  但每条会话不再把同一个 JSON 重新解析一遍。
- 文件在同一毫秒里被改写、又恰好大小不变时，这里会继续用上一次的记录（最坏显示旧标题一帧）。文件改写
  一般连大小一起变，`mtimeMs` 在这一层又是亚毫秒精度；下一次扫描看见新时间戳自然更新。
- 文件被删时连缓存里那条一起清掉，不会拿一条已经不在磁盘上的记录当真。
