# Agent Note: 写入磁盘动作共用一扇执行窗

Status: implemented

## Problem

每个会写入磁盘的动作（删除、迁移、导入、回滚、整理远端、重算名称、同步）原来各自走到"确认"就结束：
确认弹窗在按下去之后切成进度形态，跑完窗口当场消失，结论换成页面上一条横幅。于是同一件事的三个时刻
挤在两处，且都不在用户按下去的地方：

1. **确认弹窗兼做进度窗**。它的底栏是「取消 / 确认」——执行中那两枚只能是禁用的，用户面前两枚死按钮；
   而"取消"在这里是个谎：宿主的几个接口都不支持中途停，按下去什么也不会发生。
2. **结果跑到页面上**。窗口没了，用户在原来那块地方看到一条绿底提示（同步还带一枚「知道了」），写入磁盘
   动作多一对一地各写各的提示行，有的带「撤销」、有的不带，位置也随各面板自己的布局漂移。
3. **关窗等于把进度藏起来**。只有同步那一趟活过了组件卸载（`operations/sync/syncJob.ts`），其余六个动作的进度
   与结果都挂在各自组件上——关掉窗口、切个页签就全丢，而宿主那边还在跑。
4. **同一件事说两遍**。同步跑完，页面上先是一条绿色横幅，状态栏那一格再说一句"后台同步结束：…"，
   面板里还有一块「上次同步」。三处都在讲这一趟，说法还不一样。

## Decision

七条流程共用一条界面线：**确认 → 执行中 → 结果 → 完成**，状态窗只有一扇。

- **确认**还是原来那枚确认弹窗（见
  [每个写入磁盘动作一个按钮开一个确认弹窗](./2026-10-03-one-click-confirm-dialog.md)），它只负责"要不要做"。
- **执行中**换成状态窗（`shared/ui/RunDialog.tsx`）：标题说这件事正在做，正文是进度块加这件事自己
  那句"中断了怎么办"，底栏是「转到后台」与一枚按不动的动作键。第一条事件还没到时只说「正在准备…」，
  不画一条 0/0 的进度条。
- **转到后台**：窗口关掉，活儿在宿主那边照跑。进度与结论搬到**底部状态栏那一格**（`RunChip`，与后台
  同步那一格同为 `dsm-statusJob`），跑着报"正在删除 3/7"、跑完报"删除完成 / 没做成"；点它回到同一扇窗，
  已经跑完就直接落在结果页。**执行中关窗就是转后台**，不是取消——这一版没有中途停下的入口。
- **结果**在同一扇窗里换：一句结论（成功色或错误色）、「没做到 N 条」清单（`shared/ui/ProblemsBlock.tsx`，
  与「上次同步」那张卡里那块同一副长相）、"需重启才生效"那句、以及「撤销」（只在真的留下能回退的备份时
  出现；点了先收窗、再打开「备份与回滚」指着那份备份）。底栏只剩一枚「完成」。
- **完成**收掉结论，状态栏那一格随之消失，回到页面。

状态放在模块级单槽（`operations/manage/runJob.ts`：`startRun` / `backgroundRun` / `openRunDialog` / `dismissRun`），
一次只放一趟（跑着时第二趟被拒）；窗口的标题、状态栏那一格的短标签、失败那句「没做成」由
`operations/manage/runLabel.ts` 的纯函数判，三处说法因此不会各长各的。

同步那一面是同一个形状，只是多一段计划：面板 → 计划 → 执行中 → **结果**（第四段）。它跑完也不回面板：
结论、没做到的清单与「撤销」都在结果页上（`operations/sync/syncStage.ts` 的 `syncStage(local, running, done)`），
按「完成」才收掉。随之删掉的是面板顶上那条绿色横幅、那枚「知道了」、以及"后台同步结束：…"那句
（`backgroundLine` 这个 props 一起没了）——它们说的是同一件事。

边界写在明处：**这一份状态只在浏览器内存里**，刷新整个页面就没了（宿主那边照旧跑完）。后台同步是
唯一例外：那一趟能从 `GET /panel/events` 认领回来，但只剩"跑没跑、搬了几条"。

## Alternatives considered

- **让确认弹窗兼做进度窗（现状）**：底栏只能摆两枚死按钮，而"取消"根本停不下来；跑完窗口消失、结论
  跑到别处，用户按下去的地方什么都不剩。确认、执行、结果三件事各自要一份界面，硬塞进一扇窗就得撒谎。
- **每条流程各写一扇窗**：六份几乎一样的弹窗、六份进度渲染、六份底栏、六种结果排版。改动一次（比如
  "结果页上也要给撤销"）要改六处，而它们的差异只有标题与结果正文——那两样本来就是各面板自己的数据。
- **保留页面横幅 + 弹窗**：两处都在说同一件事，用户还得自己挑信哪个；关掉弹窗之后横幅还在，等于把
  "做完了什么"钉在页面上等他自己关。
- **给"取消"做一个真的取消**：宿主的 `migrate` / `delete` / `import` / `rollback` / `sync` 都不接受中途
  停；伪造一个"取消了"的按钮，实际是让界面与宿主各说一套。宁可没有，也不给一个假的。

## Consequences

- 「没做到 N 条」这一块从两处各画各的收成一份（`ProblemsBlock.tsx`），六个结果页与「上次同步」用同一
  副长相。
- 执行中不能取消：用户能做的只有等，或者转后台。要停只能等它跑完再按「撤销」退回去。
- 状态栏那一格多了一个来源（`RunChip` 与同步那一格共用 `dsm-statusJob`）：写入磁盘动作跑着时，这一排会比
  以前多一格，1024 窗口下由库路径让位（与同步那一格同一套取舍）。
- 刷新页面会丢进度与未读的结果（后台同步除外）；写入磁盘的只有各自的记录（同步的 `state.json`、备份清单），
  它们说的是上一次。
- 在确认弹窗里看到的进度说明（"删除先备份再删""中断了这份备份就在「备份与回滚」里"）跟着搬进状态窗：
  同一句话只在一个地方说，且是做事的时候说。
- 界面冒烟里推不动这一份模块级状态，所以它自己的生命周期单机钉在 `test/client/operations/manage/run-job.test.ts`；"点击之后真的
  进状态窗、跑完换成结果页、按完成收掉"这条链由 `test/plugin/client.test.mjs` 照着点击走一遍事件流来核
  （`migrationRun()` 那两个用例）。
