# Agent Note: 危险动作的确认加一道「我明白」，照官方那套排

Status: implemented

## Problem

删除、迁移、回滚、恢复、整理远端这五个动作都会改写或删掉真实数据，但确认弹窗只有「取消 / 确认」
一对按钮：计划清单摆在那儿，主按钮一按就落地。官方有一枚 `RiskConfirmation`——警告句加一枚勾选，
没勾上之前主按钮按不动——本页没有用它，等于少了一道"手滑挡板"。

## Decision

- 确认弹窗的正文在清单之后加一行警告（官方警告图标 18px + 一句话，字色 secondary 14/22），再一枚
  官方 `Checkbox`「我明白」；没勾上之前主按钮按不动（`disabled` 多一项 `!acknowledged`）。
- 忙碌起来（正在做）就把警告与勾选撤掉：那一步已经没有可确认的东西。
- 每个动作一句自己的警告话（删除 / 迁移 / 回滚 / 恢复 / 整理远端各一条），勾选框那句共用「我明白」。
- 底栏两枚按钮的最小宽度照官方 `RiskConfirmation`（取消 72px、确认 136px）：五个动作的按钮文案长短
  不一，不钉住的话底栏宽度跟着字跳。

**为什么不直接用官方那枚原语**：`RiskConfirmation` 的正文只有 `description`（字符串）与勾选框，没有
放任意内容的槽；而这五个动作的正文正是"将要发生什么"的清单（哪几条会话、哪些动作、备份落在哪）。
直接换成官方那枚就等于把清单从弹窗里拿掉，而那正是这些确认框存在的理由。所以照它的排法做在我们的
对话框里：官方 `Modal` + 官方 `Checkbox` + 官方警告图标，尺寸与颜色照 `RiskConfirmation.module.css`
（图标 18px 走 state 色、警告句 secondary 14/22、勾选与它隔 12px）。

## Alternatives considered

**直接换官方 `RiskConfirmation`，清单不要了。** 用户看不到"将要删哪些"，只剩一句摘要；删除还会
级联带上子智能体（清单里逐条标着「随父删」），这层信息一丢，确认就变成了点头。

**两段式：先在我们这枚弹窗里看清单，再开官方那枚确认。** 三下点击，而且第二下时清单已经被挡住，
用户靠记忆确认。

**勾选框用官方 `Checkbox` 而不是官方那枚的裸 `<input>`。** 官方 `RiskConfirmation` 内部用的是带
`accent-color` 的裸 input；本页勾选框一律走官方 `Checkbox`，外观与行上的勾选框一致，键盘行为也由
原语负责。

## Consequences

- 五个危险动作都要多勾一下；主按钮在那之前是禁用的（键盘也按不动）。
- 计划算出问题（例如会话还活在宿主内存里）时，主按钮照旧禁用——两种禁用叠加，勾上也不会解锁。
- 由 `test/client.test.mjs`（删除弹窗里没勾之前主按钮禁用、"我明白"那枚默认没勾、勾上写回的受控值
  是 `true`、警告句在正文里）钉住；文案键 `dialog.acknowledge` 与五个动作各自的 `*.acknowledge`。
- 真实 dev GUI 里量到的（删除那条，计划 ok 时）：勾选前 `确认删除` 的 `disabled` 是 `true`，勾上之后
  变 `false`；警告行带 `.dsm-riskIcon`（图标 18px），勾选框是官方 `Checkbox`（label 即「我明白」）；
  底栏两枚实宽 72px 与 136px（与官方那两枚的最小宽度一致）。
