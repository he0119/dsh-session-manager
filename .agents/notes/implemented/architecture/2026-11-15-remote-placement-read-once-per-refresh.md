# Agent Note: 会话在远端哪几处，界面一次刷新读一次

Status: implemented

## Problem

同步把会话推到远端时，一台机器一格、一条会话一个包（`dsh-session-manager/<机器>/<id>.dshsess`）。
页面里没有任何一处说得出来"**这条会话在远端哪儿**"：会话列表只有本机的事实（目录、大小、时间、id），
同步那张计划表只在跑一趟的时候按"拉 / 推 / 不动"列出来，关掉就没了。

代价在排查时最明显：某条会话的图挂了、远端缺附件对象，"去持有这些对象的那台机器上把它推上来"这句话
就落不到具体位置——人得去 NAS 上按机器格子一格格翻，或者盯着一串会话 id 猜。远端索引里其实就写着
每条会话在各台机器上的位置与活动时间，只是界面上没有出口。

## Decision

多一条一次性的读，右栏加一格：

- **宿主**：`GET /remote` 一遍读齐远端（每台机器那份 `index.json`，不是包），回
  `会话 id → [{ machine, path, bytes, lastActiveAt? }]`（`src/operations/sync/index.ts` 的 `remotePlacements()`，
  纯函数，`test/operations/sync/sync.test.ts` 钉住排序与聚合）。与 `RemoteLibrary.entries` 的标准刻意不同：那里每个
  id 只留**赢的那一份**（用来判"该拿哪份"），这里按机器逐份列全（用来回答"哪几处有"）。
  没配同步 → 409（界面据此整格不出现），不是"远端空着"。
- **界面**：一次刷新只读一次（`src/client/operations/sync/remoteLibrary.ts`，模块级 store）。触发点是清单换了
  对象（`panelEvents` 上 `state` 变了）与一次同步应用之后——后者会改远端，不重读就还停在应用之前的
  样子。右栏那格只是**查表**：选中哪条会话就在这份上查，不现读（`src/client/operations/sync/remoteRows.ts`
  决定摆什么，`test/client/operations/sync/remoteRows.test.ts` 钉住）。
- **说不全时不撒谎**：读失败照实说原因；某台机器的索引没读到时不说"远端没有这条会话"（它可能就在
  那台没读到的机器里），改说"可能不全"。只有**一台都没缺**时"远端没有"才是结论。

## Alternatives considered

- **并进 `/state`**：那条是"扫本机"的结果，页头、清单、计数都等它；把一次 NAS 读塞进去，远端关着
  （或密码过期）就会把整页清单一起拖住，而远端读不到本来只该影响右栏那一格。
- **按会话现读（选中才问一次）**：右栏是"点一下看一眼"的地方，每点一条等一次网络（实测一次读要列
  目录 + 取每台机器那份索引），翻十条会话就是十次。一次给全部反而更省：读的只是索引，包本身一个
  字节都不碰。
- **搭在 `/panel/events` 那条长连接上**：清单每变一次就要读一次远端，而那条流上跑的是本机的进度与
  状态；远端读失败还要在流上编一种"失败事件"，形状比一条一次性响应复杂得多。
- **把包路径留给界面自己拼**：路径 = 命名空间 + 机器格 + `encodeSegment(id)` + 扩展名，界面要复刻
  `encodeSegment()`；已经在走线上的字符串再拼一遍，省不下来多少，错一次就指到不存在的路径。

## Consequences

- 每次刷新多一次远端读：一次列目录 + 每台机器一次 `index.json`（两台机器就是三跳）。清单本身照旧
  不等它，远端慢的时候只是右栏那格晚一点从"正在读"变成结果。
- 响应大小（实测）：拿本机 1471 条会话的真实 id 造一份、两台机器各 1174 / 600 处位置，JSON 是
  **322 KB**（gzip 后 34 KB）；这条端点的响应没压缩，走线就是这份原文。要再省就该把重复的路径前缀
  收进响应头，那是另一次改动的活。
- 右栏那格多一行（机器 + 字节 + 最后活动时间），路径另起一行用等宽字（`.dsm-inspectorPath`），
  悬停看全文；同一 id 在几处都有时一处一行。没配同步时整格不出现——与"这个宿主没有附件服务"那几条
  同一条标准：没这个能力就不摆一个永远空着的格子。
- 一次同步应用之后会重读一次远端：那是这一页唯一"改完立刻再看一眼"的地方（推上去的包、补上去的
  对象都在远端）。
