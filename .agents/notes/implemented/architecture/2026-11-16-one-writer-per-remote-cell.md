# Agent Note: 同一台机器的远端格子同一时间只让一件事写

Status: implemented

## Problem

远端同步的布局是"一台机器一格包 + 一份 `index.json`"（见
[formats.md](../../../../docs/formats.md)）。写自己那一格的入口有五个：

- 界面上的手动同步应用（`POST /sync?mode=apply`）；
- 界面上的整理远端（`POST /sync?mode=tidy`）；
- 删除会话时勾了「同时删除远端」（`removeRemoteCopies()`）；
- 后台自动推送（`createAutoPushTimer()` → `runAutoPush()`）；
- 模型工具 `sync_sessions`（`apply: true`）。

它们各自在开始前读一次远端，应用时**整份重写**自己那一格的索引。手动同步原先只用 `applying` 挡
"另一趟手动同步"，整理只挡手动同步，自动推送有自己的 `busy`，删除与工具完全不看这些闸。两件事一起
跑时，后写的那个拿的是较早读到的快照：刚推上去的条目会消失、刚留下的删除记录会被抹掉，下一次同步
于是把删掉的会话又拉回来。

这不是理论风险：整理那段的注释已经写了"两边都写自己那一格的索引，同时跑会互相踩"，只是当时只数了
两个写手。

## Decision

加一把**进程内**的互斥锁（`src/operations/sync/remote-write.ts` 的 `createRemoteWriteGate()`），一个插件实例造一把，
五个入口共用：

- **拿不到就不做，不排队**：`tryAcquire(label)` 返回 `undefined` 时，手动同步 / 整理回 409，模型工具
  回一句"上一轮…还在跑，这次没有同步"，自动推送报 `skip: 'busy'` 并结束这一轮，删除远端的
  `remoteCopiesPort` 在结果里报"远端这次没有删"（本机已经删完了，不能回滚那一步）。
- **排队为什么不行**：排到之后用的还是开始前读到的快照，正好是这把锁要防的"旧快照盖新条目"；跳过
  则下一轮会重新读一份新的。
- **只挡写，不挡读**：预览、`GET /remote`、`/sync-diff` 不拿锁；它们只读，最多看到一次写的中途，
  不会把别人的改动盖掉。
- **进程内**：桌面版与 Web 版同时跑、或者同一 profile 起两个进程时挡不住。那一层要靠 WebDAV 的条件
  写（ETag / If-Match），不是所有服务器都支持，这一版不做；`remote-write.ts` 的文件头写明了这条边界。

## Alternatives considered

- **排队等锁**：实现更简单，但等到锁之后手里还是旧快照；除非拿到锁再重读一次远端，而那等于把整个
  计划重算一遍。跳过 + 下一轮重来更便宜，也不会在用户面前假装"这一轮成功了"。
- **只锁索引写入（`dav.put(index.json)`）这一句**：能让索引不被两个写手同时覆盖，但包的上传与删除
  仍会交叉——整理可能把同步刚推进去的包当成多余包删掉。锁的粒度按"这一格的一次写事务"划，才对得上
  实际会互相踩的范围。
- **一把全局锁，把迁移、删除本机、导入也串起来**：它们不写远端，串起来只会让两个无关的动作互相等；
  锁的范围按"写远端格子"这一件事划。
- **WebDAV 的 LOCK / UNLOCK**：协议上有，但各家服务器实现差异大（很多 NAS 只支持一半），而且锁超时
  之后还要处理残留；先用进程内互斥解决本机能确认的那一类。
- **让每个入口自己判断别人在不在跑**：五个入口各写一遍判据，迟早漏一个；收在一个 `RemoteWriteGate`
  里，新增入口只要记得拿锁。

## Consequences

- 撞上时是"这件事这次没做"，不是"等一会儿自动做"：手动同步 / 整理会看到 409；删除远端的结论里会多
  一条"远端这次没有删"；自动推送这一轮跳过。
- 自动推送被挡下时不会立刻重排一个定时器；下一次会话活动会重新起安静窗口。手动同步通常就在用户眼前，
  跑完之后再点一次即可。
- 锁只在进程内；两台机器各跑一个 DSH 时，它们本来就写不同的格子，不需要这把锁；同一个 `machineId`
  被两台机器共用是配置错误（`README` 已写），不在锁的解决范围内。
- `src/index.ts` 造一把传给 `registerTools()`、`resolveAutoPushRuntime()` 与 `registerWebRoutes()`；
  测试可以各造各的，`createApiHandlers()` 与 `createAutoPushTimer()` 在缺席时自己造一把。
