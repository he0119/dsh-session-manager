# Agent Note: 会话管理页分两份加载，清单没到之前先说实话

Status: implemented

## Problem

页面一挂载就把 `GET /state` 发出去，而那一份要扫完整库：每个项目目录 readdir、每条会话读首帧解析
header、再为每条折一次标题（本机 454 条会话，热投影缓存下实测 160～300 ms，冷缓存另算，标题那一遍
是其中的大头）。在这个往返走完之前页面手上什么都没有，于是它按"空"画：

- 页头「会话库：」后面是空的，条数写着 `0 个会话 · 0 个工作区`；
- 「会话」与「传输」两个列表框里写着"这个会话库里还没有会话"；
- 「会话」页还多一句"这个宿主没有 `workspaceRegistry` 服务（归档是它的能力），所以归档按钮不可用"。

这些都不是占位符，是**结论**——而那一刻的真相是"还不知道"。反过来，库在哪、这个宿主有哪些能力位，
宿主立刻就能答：前者是配置解析出来的 `paths`，后者是一次宿主服务探测，与扫库毫无关系。

## Decision

一次加载拆成两份，宿主侧两条端点：

- `GET /meta`：`sessionsRoot` / `registryPath` / `pickerKind` / `archiveAvailable` / `sync`。不碰会话库。
- `GET /state`：同一批字段**加上**这次扫库扫出来的 `problems` / `repos` / `sessions` / `workspaces`。
  它是 `/meta` 的**超集**：这五项两边来自同一个 `metaFacts()`，不各算一份。

客户端 `Promise.allSettled([fetchMeta(), fetchState()])`：先到的先落地，`/state` 回来再填清单。页头与
各分页按 `state ?? meta` 取那些**不依赖清单**的字段，凡是清单到位前答不出来的地方一律说「读取中…」：

- 页头：「会话库：」后面先印 `/meta` 给的位置，条数那一段说「读取中…」；两份都没到（首帧）时整行只有
  一句「读取中…」。
- 「会话」与「传输」两个列表框：里面说「读取中…」，不说"这个会话库里还没有会话"。
- 「会话」页那句归档能力说明、「同步」页那句"没配置同步"、迁移页两个字段的「浏览…」：等都答得出来
  再说 / 再画。
- 「说明」页那两条路径（会话库 / 注册表）同样先印 `/meta` 给的那一份。

`/meta` 拿不到**不算这一页的错**：那几项只是"先说清楚"，`/state` 照样把它们带回来；拿不到就退回
「读取中…」，不报横幅，也不清掉上一次拿到的位置。

## Alternatives considered

- **只把空态文案换成「读取中…」，位置留空。** 最省事，但页头那一句问的正是"库在哪"：宿主那一刻已经
  知道，没有理由不显示；能力位同理，不显示等于让读者自己猜这个宿主支不支持归档。
- **一次响应分两段（SSE 先发位置再发清单）。** 一次 HTTP 响应只有一个 body，JSON 要么整份到要么不到，
  要提前只能换协议；为几十到几百毫秒的窗口引入一种新响应形状，还得给"清单还没到"再定一套事件语义，
  比多一条只读端点贵。
- **客户端把上一次的位置存在内存或 localStorage 里。** 首访没有，跨标签页与跨机器还可能是过期的：
  改了 `sessionsRoot`、换了 `DSH_HOME` 之后显示的是旧路径——一处缓存换一处撒谎。
- **让 `/state` 先回一份不带标题的清单，标题后补。** 还是要分两段，而且列表会重画一次（行的身份、
  分组、条数都变），比页头一句说明贵；标题那一遍确实最贵（见
  [标题来自日志事件](./2026-09-27-session-title-comes-from-an-event.md)），但那属于"清单慢"，不是
  "位置显示不出来"。
- **页头干脆不显示位置，只说"读取中…"直到清单回来。** 与第一条同一类：把已经知道的事实藏起来，
  用户失去的正是他唯一能核对"我在看哪个库"的那一格。

## Consequences

- `/state` 与 `/meta` 那五项必须逐字相同：`test/web.test.ts` 按两组宿主（能力位真 / 假）各核一遍；
  `/meta` 那条另核"一条会话都不读"——注进去的标题读取器与项目身份入口被调到就红。
- `/meta` 失败是一条安静降级路：没有横幅、没有错误态，只是页头晚一步，退回「读取中…」。
- 「读取中…」在界面上多了四处，但复用的是同一个键 `page.loading`，没有新增文案，也没有新增控件。
- 宿主没有 `GET /meta`（半侧版本对不上）时退回上一版的样子：位置等 `/state`，其余照旧。
- `/state` 后来变成了一条**事件流**：扫库那一段逐条报 `scan` 进度（`test/web.test.ts` 核事件顺序），
  但**结果仍是完整一份**——位置与清单还是同一份 payload 一起到。上面那条"先发位置再发清单"的备选
  因此仍然是被否的：这次流的只是"做到哪了"，不是"半份 payload"（见
  [每个长动作都报进度](./2026-10-08-every-long-action-streams-progress.md)）。
- 界面结构没动，也没有新增颜色或尺寸：`.dsm-intro` / `.dsm-empty` / `.dsm-hint` 还是原来那几个，
  这次改的只是"什么时候说什么"（页头规格见
  [页头照内建设置页的规格](./2026-09-28-page-header-matches-the-builtin-settings.md)，
  空态画在框里见[三个分页共用一份列表实现](../simplification/2026-09-28-three-pages-share-one-list.md)）。
