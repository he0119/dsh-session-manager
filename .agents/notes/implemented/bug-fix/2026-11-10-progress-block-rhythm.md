# Agent Note: 进度块四行归位：计数在条上面，条目退出主色

Status: implemented

## Problem

后台同步与「立即推送一次」那张卡片在真实页面上是这么一副样子：一句 12px 的灰字「正在同步（后
台）」、紧贴着一条通栏的进度条、条下一句「正在推送 50 / 50」、隔开一大段空白后才出现会话名
（`Codex · 分析 sing-box 连接超时`，13px 主色，整块里最大最亮的一行），最后再隔开一段是那句说明。

两个来源叠加：

- `ProgressBlock` 的四样东西是四个 `<p>` / 一个 `<div>` 直接塞进 `.dsm-progressBanner` 的纵向
  flex。`.dsm-banner` 自己不带 `gap`（它是给"一句话 + spacer + 按钮"那一行写的），而 `<p>` 有浏览器
  默认的上下外边距（1em，13px 字号下就是 13px）——于是四行的间距一会儿 2px、一会儿 13px，看着忽松
  忽紧。
- 「当前那一条」用的 `.dsm-rowTitle`：正文档、主色。它是列表行标题的样式，摆在进度块里就成了这块
  最抢眼的一行——比"正在推送到第几条"还重，而它只是"现在在搬哪一条"。

## Decision

`ProgressBlock` 重排成"一句读数 → 条 → 当前条目 → 说明"四行，整块由 `.dsm-progressBlock` 的
`gap: 6px` 定节奏，行上的 `<p>` 外边距一律归零；那句计数用 12/18 次要色 + 等宽数字，当前条目用
12/18 三级色、单行省略（完整名字挂 `title`）。进度横幅的头部补一枚官方 `StateDot` 的 ongoing 转圈与
一句 13/18、字重 500 的标题（"这是哪一趟"），横幅的留白与描边照卡片那一档（12px 14px、
`settings-card-stroke`），不再用 `currentColor` 描边。

## Alternatives considered

- **只把 `<p>` 的外边距去掉。** 间距会齐，但"条目比计数更亮更大"的层级问题还在：读者第一眼仍落在
  某一个会话名上，而不是"做到哪儿了"。
- **把计数拆成左"正在推送"、右"50 / 50"。** 要动 20 个 phase 的文案键（每句现在是一个整句），
  为一次观感改动换一整套文案口径，不划算；等真的需要右侧对齐那枚百分比时再拆。
- **保留 `.dsm-rowTitle`、只把字号压到 12px。** 主色 + 正文档的字面还是把条目推到与标题同级；进度块
  里"在搬哪一条"属于次要信息，用三级色才和它的角色一致。
- **给进度横幅加底色（`bg-layer-2`）。** 浅色主题下那几级底色几乎是同一个白（行悬停底色踩过同一个
  坑），加了等于没加；描边才是这两个主题里都成立的边界。
- **用 `<ProgressBar>` 自带的状态点代替 `StateDot`。** 进度条只回答"多少"，`StateDot` 回答"还在动"，
  两件事本来就有两个原语。

## Consequences

- 四行的间距不再由浏览器默认值决定：改节奏只改 `.dsm-progressBlock` 的 `gap` 一处。
- 当前条目单行省略，长标题不再把这一块撑高或顶出边界；完整名字在悬浮提示里。
- 弹窗里的进度块（迁移 / 删除 / 回滚 / 导入 / 同步）走同一份组件，观感与外层横幅一致。
- 横幅比原来高（12px 内边距 + 最多五行），后台同步跑着时页面顶部多占一行的高度。
- `test/styles.test.mjs` 钉住"行外边距归零 + 块内 6px"；`test/client.test.mjs` 钉住"计数在条上面"与
  条目那行的挂钩。
