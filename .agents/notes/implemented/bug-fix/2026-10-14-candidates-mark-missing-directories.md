# Agent Note: 候选里盘上已经没有的目录挂着标签、点不动

Status: implemented

## Problem

「迁移」的目标目录与「导入」的落地目录共用同一份候选（`planRows.directoryTargetRows()`），候选来自注册表
里已登记的工作区。而注册表里的**登记**不保证盘上还有：项目文件夹被删掉、目录改了名之后，那条登记照旧
在，宿主也照旧把它列进 `/state`。于是候选面板里"盘上还在的"与"只剩一条登记的"长得一模一样——实测 dev
库里的 `sync-dev-test`（目录早已不在）与 `test` 两行，名字、路径、悬浮提示全都同形。

点下去的结果是走一步撞一次：宿主在 `assertTargetCwd()` 里 stat 一下，弹窗顶上红一行「目标工作区目录
不存在：/home/uy_sun/dev/sync-dev-test」。用户按的是**候选列表里的一行**，得到的却是"这个目录不存在"，
而候选列表里没有任何一处说过它会不存在。

## Decision

宿主在 `/state` 的每条工作区上多报一个事实 `exists`（`canonicalDirIfExists(record.path) !== undefined`
——一次 realpath + stat，解析得出来且是个目录才算存在）。界面据此把盘上已经没有的那些**照旧列出来、挂
一枚「不存在」的标签、并置灰**：`PathRow.missing` → `CandidateRow.missing` → 那一行按钮的
`disabled`，悬浮提示里说清"登记还在、目录没了，当不了目标目录"。

三条边界：

- **不把它们从名单里删掉**：那是用户自己登记过的块工作区，"名单里怎么少了一块"比"多一条点不动的候选"
  更难查。这也是这个仓库里其他"事实与显示不一致"的地方一贯的做法（侧边栏看不见的会话照样列出来、各带
  各的标签；悬空登记点名报出来）。
- **`exists` 缺席按"还在"处理**（客户端那份类型是 `exists?`）：拿不到这个事实时退回改动之前的样子，不在
  界面上替宿主猜。
- **只判工作区，不判会话的 `cwd`**：目标候选只来自注册表；而"会话的源目录已经删掉"在这条路上是**允许**
  的（迁移正是为了把那几条会话从已经删掉的目录里搬到别处，见 README），给源目录也挂这枚标签等于把一件
  正常的事说成故障。

## Alternatives considered

**把盘上已经没有的候选从列表里滤掉。** 用户会看到自己登记的工作区凭空消失，而原因（目录没了）只能靠
猜，顺带把"这不影响别的会话"也藏了起来。

**候选照旧可选，靠落地那一步报错。** 那就是改动之前的样子：选择发生在候选列表里，报错发生在弹窗顶上，
两者之间没有可见的联系。

**在客户端探测目录。** 浏览器半侧没有文件系统，只能问宿主；而"问宿主"就是 `exists` 这个字段，多一次
往返换同一份结论。

**字段取"没有"的极性（`missing`）而不是"有"（`exists`）。** 极性反过来会让"缺席"同时有两种含义（是
"还在"还是"这个宿主没给"），而 `exists` 是宿主自己算出来的正向事实。

## Consequences

- `/state` 的 `workspaces[]` 多一个 `exists: boolean`——对外契约的一次**加法**，拿不到就按旧行为走。
- 每个工作区多一次 realpath + stat（本机 13 个工作区），用来挡"点了一行必然报错"。
- `test/web.test.ts` 那条"登记过、但目录已经改名"的用例顺带核 `exists`（目录没了报 `false`、还在报
  `true`）；`test/planRows.test.ts` 与 `test/client.test.mjs` 各钉一条：`exists: false` 的行带
  `missing`，面板里挂标签、置灰且点不动。
