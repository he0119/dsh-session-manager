# Agent Note: 导入时把「当前工作目录」里的旧机器路径一起改写

Status: implemented

## Problem

会话从另一台机器搬过来时，日志 header 的 `cwd` 会被改写成本机路径（库目录名与它绑死，不改写就落不
下来）。但正文里 `working-directory/change` 那些事件还留着源机器的写法，比如
`C:\Users\me\Work\repo\.agents\worktrees\fix\x`。

宿主把它们折成「当前工作目录」这个投影值，并要求它在本机是绝对路径（`dsh-working-directory` 里的
`z.string().min(1).refine(isAbsolute)`）。`C:\…` 在 Linux 上不是绝对路径，投影因此失败，而
`sessionQuery` 一旦投影失败就把**整条会话**判成读不出来：对话页首屏直接报
「历史加载失败：failed to project session "…": [{"code":"custom","path":[],"message":"Invalid input"}]（gateway/internal）」。

本机 1400 条会话里踩到 3 条，都是 Windows 上跑过、再同步或导入到这台 Linux 机器的。症状不是"少了
几个字段"，而是**这条会话再也打不开**：列表在、内容页（自己读日志）在，对话页进不去。

## Decision

把事件里那些"跟着会话根一起搬的路径"跟着会话根一起改掉，只改**在本机不是绝对路径**的那些。

- **哪些值**：只有 `working-directory/change` 的 `data.cwd`。它是宿主要做绝对路径校验的那一个；
  工具入参、正文里的引用、工作树记录没有谁校验，属于历史事实，不动。
- **怎么映射**：会话根 → 会话根，根以下的子路径跟着换、分隔符跟着目标走
  （`C:\work\repo\.agents\x` 在 `C:\work\repo → /home/me/repo` 下变成 `/home/me/repo/.agents/x`）。
  落在源根之外的值原样保留，并报给用户（"这几个改不了"）。
- **判据为什么是"本机不是绝对路径"**：本机就合法的路径（Linux 上换目录、`/home/a/repo` →
  `/home/b/repo`）宿主读得出来，改它只是抹掉事实。跨系统的写法才让会话读不出来，也只改那些。
- **落到哪两处**：导入/同步落地（`src/transfer.ts` 的 `rewriteCwd()`，与 header 改写同一处），以及
  修**已经落地**的日志（`src/path-repair.ts` + 工具 `repair_session_paths`，默认只预演）。
- **字节级分寸**：仍然只重压改动的那几帧，其余帧原样拼接；改完整份重新解码，必须逐字节等于文本形态
  的改写结果，否则不落盘。修已经落地的日志之前先留一份逐字节备份。
- **比对那一侧**：`src/session-diff.ts` 比两份日志时，把两边"会话根底下的路径"都归一成占位符再比。
  没有这一步，改写过的那份会被同步报成"两边各写过"，它在本机续写之后就再也推不回远端。

## 只有这一条路径要搬

宿主对路径的校验只出现在「当前工作目录」这个投影上。别的路径（`plugin:worktree/created` 的
`path`/`repositoryRoot`、工具调用入参里的路径）只要求是字符串，跨机器留着不会让会话读不出来。把它们
一起改会多改掉一批能读的事实，收益却是零，所以不改。

## Alternatives considered

- **只在上游修**（让单个投影失败降级成"这个值没有"，或者让校验同时认 Windows 盘符）：这是治本的
  方向，但本仓库改不到那一层，而且已经坏掉的三条等不起一个上游发版。两条并行：本仓库先把数据修好。
- **凡是本机不认的路径一律改成本机会话根**：保证能打开，但抹掉了"当时在哪个工作树里"，日志看起来修
  好了、内容却被改了，属于假修。只在前缀能对上时才改。
- **导入时拒收这类会话**：把"能不能看历史"变成"能不能搬"，问题推回给用户，而且拒收之后那条会话连
  列表里都没了。
- **只改日志、不归一比对**：那三条会话在本机一续写，同步就会认为两边各写过，新内容永远推不回远端。

## Consequences

- 落地或修完之后，本机这份日志与远端那份的**事件字节不同**了。同步的内容指纹仍只归一 header 的
  cwd，所以这几对筛不动，会走"取两边日志逐行比"那条较贵的路（比对侧已归一，结论是同一份）。
- 修日志要把整条会话解一遍（扫全库时最贵的一段），所以工具默认只预演，并允许只点名几条会话。
- 备份目录里是逐字节副本加一份 `repair.json`，没有迁移那份 `manifest.json`；撤回的方式是把它复制回去，
  不走 `rollback_session_migration`。
- 宿主持在内存里的会话不动（它手上是另一份日志），工具会点名让人先关掉或重启。
