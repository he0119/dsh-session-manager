# Agent Note: 窄屏浮层点外面就收起

Status: implemented

## Problem

「会话」页的两层浮层——左栏的「项目与筛选」与右侧的「详情」——窄屏下都盖在列表上（左栏 ≤960px、
右栏 ≤1180px）。收起它们的路只有每层右上角那枚「关闭」：鼠标要先找到那个角，手指在窄屏上更要够到
它；点列表、点卡片空白都没有反应，看着像点漏了，而不是"这里不接点击"。左栏打开时点某一行，用户
以为会跳到那一行，实际什么都没发生。

## Decision

浮层外面铺一层**不画东西**的收集层（`.dsm-scrim`），点它就收起——一次把两层都收掉。

- 它常驻 DOM；显不显示由 CSS 读两层各自的浮层状态：左栏是「≤960 且带 `dsm-treeOpen` 类」（兄弟
  选择器），右栏是「≤1180 且 `.dsm-inspector` 的 `data-empty` 是 false」（`dsm-workbench` 上的
  `:has()`）。宽屏上没有它，窄屏没有浮层时它不可见、也接不到点击（见
  [浮层进出用滑动](2026-11-13-overlay-motion-slides-with-visibility.md)）。
- 它挂在**主栏**（`.dsm-workbenchMain`，新加的 `position: relative`）里，不是挂在工作台上：
  960–1180 那一档左栏还是常驻的一列，挂在工作台上就会连它一起盖住——点项目变成"先收起右栏、
  再点一次才选得到项目"。
- z-index 5（左栏 6、右栏 7）：两层浮层自己的项目行、动作按钮照旧可点。
- 它接住这一下点击，所以点到的列表行不会顺带被选中、右栏也不会顺带换一条——一次点击只做一件事。
- 它 `aria-hidden`、进不了 Tab 序；键盘那条路仍是两层里那枚「关闭」。

## Alternatives considered

**在 document 上挂 `pointerdown` 监听，判 `contains()`。** 不用改 DOM，但点列表行时这一下会
**穿过去**：浮层收起的同时那一行被选中、或者右栏被打开。要拦住穿透就得在捕获阶段吞掉事件，那会
连带挡住页面里别处的东西，代价比一层空白大得多。

**写一层会变暗的遮罩。** 浮层已经靠宽度与那道阴影跟列表分开，再压一层底色只是把用户正在看的那
一列染灰；还多一处颜色决策要跟着深浅两套主题走。收起是这一层唯一的作用，就不画。

**两层各挂一层空白。** 两层都开着时（先开项目栏，再点一行行尾的「详情」），中间那块被上面那层
接走：一次点击只收一层，要连点两下。共用一层之后"点空白"只有一个意思——把浮层都收起来。

**把那一层挂在工作台上（顺手铺满整块工作台）。** 960–1180 那一档左栏是常驻的一列，被盖住之后
点项目只会收起右栏，用户得点两下才选得到项目；挂在主栏里就只盖列表那一块。

**点外面的第一下顺带执行一次点击（不接住）。** 与第一条同一个毛病：收起与"选中一行 / 打开右栏"
同时发生，用户没法预期这一下到底算哪件事。

## Consequences

- 窄屏上收起的入口从一枚按钮变成"按钮 + 任意空白"；宽屏一点没变（同一份 DOM，那一层是
  display:none）。
- 浮层打开时，列表上的一切点击都先变成"收起"；要选行、要看详情，收起之后再点。
- 960–1180 那一档点左栏不会收起右栏（那一层不盖左栏），选项目照旧一下就成。
- 结构由 `test/client.test.mjs` 钉住：那层空白挂在主栏里、不在工作台那一层，`aria-hidden`，点它
  一次写下两处状态（左栏收起、右栏清空）。显形的两条规则、定位与 z-index 由 `test/styles.test.mjs`
  钉住。
- 真实 dev GUI 里量到的（工作台宽 796px，窗口 900）：两层浮层任一打开时那层空白的矩形与主栏逐像素
  相同（80, 62, 796, 667），计算值 `display: block`、`position: absolute`、`z-index: 5`、背景
  `rgba(0, 0, 0, 0)`；点浮层里面不收、点外面收，且不勾选任何行、右栏不换一条。工作台 1072px
  （960–1180 那一档）时它只铺主栏（528, 62, 848, 767），点左栏命中的是树自己的行；工作台
  1272px（>1180）时它是 display:none，右栏回到文档流。深浅两套主题各走了一遍。
