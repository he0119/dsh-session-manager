# Agent Note: 同步跑完没做到的那几条，界面要点得出名字

Status: implemented

## Problem

同步跑完之后，页头那枚状态只说一句「上次同步有 1 条没做到」。它数的是宿主 `SyncOutcome.problems`
的条数——那几句是**汇总**：`本机有 3 个附件对象在远端共享库里也没有，这次补不上`、
`同步映射把 /a 指到了 /nope，但那不是一个存在的目录`。界面上没有任何一处把这些句子渲染出来，也没有
任何一处说得清"是哪条会话"。想知道到底出了什么事，只能重新跑一次预演，从三张计划表里找那几行
`skip`；窗口一关、宿主一重启，那条记录在新版里还有个 `problems` 数组，在旧版里连记录都没有
`（`state.json` 是后加的），细节就彻底没了。

结果是：状态点变黄了，用户知道"有事"，但拿不到下一步——不知道是哪条会话、为什么、要不要管。

## Decision

「没做到」在宿主那侧摊成**点名版**，界面上两处把它说出来。

- **点名版长这样**（`src/sync.ts`）：`SyncLeftover { message, sessionId? }`，
  由 `collectLeftovers(outcome)` 从两处来路拼：计划里那些 `action: 'skip'` 且不 `identical` 的行
  （它们本来就有标题与 id，句子是 `名字（id）：原因`），加上 `plan.problems` 与 `outcome.problems`
  的原话（映射、远端索引、整理那几步不属于任何一条会话）。`identical` 不算——那是"本来就没事"。
- **落盘**：`state.json` 的记录多一项 `leftovers`（读的时候形状不对就当没有，与那一层其余字段同一
  口径）；`/sync` 的响应也带同一份，所以"刚跑完"和"重启之后回来"看到的是同一张清单。
- **界面**（`src/client/`）：
  - 页头那枚的悬浮提示在计数句之后接上**前 3 条原话**，多的折成「还有 N 条（点开看全）」；
  - 同步弹窗的面板段多一块「上次同步」：时间与"拉几条推几条"一句，然后逐条列出没做到的；
    带 `sessionId` 的那条多一枚「只看这一条」——关掉弹窗、把左栏切回「全部项目」、搜索框填上这个 id，
    列表因此只剩它。
  - 旧记录（只有 `problems`、没有 `leftovers`）退回按汇总句一条一句地列，不会空着。

## 为什么不直接改 `problems` 的形状

把 `problems: string[]` 换成对象数组是最"正统"的做法，但它是**跨层的公共形状**：同步的三个产出点、
`state.json` 的格式、`/sync` 的响应、模型工具的 `problems` 字段、以及十几个断言都在用它。为了多带
一个 id 把整条链改一遍，收益与"在计划行上衍生一份点名版"完全相同，风险却大得多。

同理没有选"在 `problems` 的文本里拼上 id"：文本是给人读的，靠解析它取 id 很脆（措辞一改就断）。

## Alternatives considered

- **只做界面、不做点名**：页头从"1 条没做到"变成"1 条没做到：映射指到了不存在的目录"——仍然没有
  哪条会话，用户还是得自己去找。
- **把整份计划存进记录**：一次同步的计划可能有几十上百行，其中绝大多数是"不用做"（`identical`）。
  存下来既大又要把 `SyncPlan` 变成持久化格式，而界面真正要的只是那几行没做到的。
- **记录里存渲染好的文本**：界面就没法给「只看这一条」——那需要 id，而不是一句话。

## Consequences

- 弹窗的面板段多了一块（一条 ~110px、三条 ~200px，见 design.md 那张规格）。它只在有记录、或有没做到
  的条目时出现；从没同步过、或上一趟干干净净时一个字都不加。
- 这块要读成"一次记录"，不能读成四段说明：块里的段落必须把浏览器默认段距归零（不归零时量到的节奏是
  6 / 12 / 18px 混着，四行字一样灰），有遗留时才成块（告警色淡底 + 左边一道细线），条数那句缩成 12px
  的小标签。踩到的两个坑（默认段距、行内按钮被挤成两行）已经钉进 `test/styles.test.mjs`。
- 页头的悬浮提示变长（最多 4 行原文 + 计数句）。`title` 本来就能多行，这一处不引入新的浮层。
- 「只看这一条」是这一页唯一会往搜索框里写值的动作：用户看得到它做了什么（搜索框里有那个 id），
  清空搜索框就回到原来的列表。
- 记录里的 `leftovers` 与 `problems` 是同一件事的两种粒度，会有重复的句子（计划与落地两段可能算出
  同一句）——`collectLeftovers()` 按句子去重。
- 旧宿主没有这一项、旧记录也没有：界面两处都退到 `problems`，条数与清单仍然对得上。
