# Agent Note: 「未分组」就是外壳那一组

Status: implemented

## Problem

同一个名字在三处各答各的：

- 「会话」页 / 传输页行上那枚「未分组」小标签与筛选条里的芯片，只看 `SessionSummary.workspaceId`
  缺省（「注册表没认领」）；
- 迁移页的「未分组」来源（`unownedSessions()`）还要叠一层隐藏过滤。

于是子代理、空白与已归档的会话明明不在侧边栏那一组里，行上却挂着「未分组」，迁移页那个来源又不认
它们——同一个名字两种答案，而这正是让人对着两个界面猜账的根源。

## Decision

「未分组」只有一个定义，算在 `src/visibility.ts` 的 `isUngrouped()` 里：**谁都没认领**
（`!accounted`）**而且**侧边栏默认视图**会显示它**。`/state` 把它作为 `ungrouped` 发给界面。

多出来的那半句定义（「侧边栏会显示它」）就是 `hiddenReasonOf()`，所以两件事现在是同一个模块里共用
`visibilityFacts()` 的两个函数。

## Alternatives considered

**继续按「有没有工作区认领」这个中间事实判。** 那要自己把宿主 `sessionVisible()` 的三条判据再抄一遍，
而抄错过一次：只看「有没有认领」时，子代理、空白与已归档也成了「未分组」。

**让三处各自修一遍。** 三处判据分别演化下去，下一次分叉只是时间问题；判据必须收在一处。

**把「未分组」改成「未认领」并保留原语义。** 名字与外壳侧边栏那一组不一致时，界面之间照样对不上
账——名字的价值就在于它是同一件事。

## Consequences

- 三处读同一个结论：「会话」页 / 传输页的标签与筛选芯片、迁移页的来源。
- 迁移页那个来源另外要求有 `cwd`（它要改写 header，`relocateHeaderCwd()` 拒绝没有 `cwd` 的 header）——
  那是来源自己的**能力**限制，不是定义的一部分。
- 外壳不显示的那三类各自挂自己的标签（子代理 / 空白 / 已归档），不挂「未分组」；
  `test/visibility.test.ts` 与 `test/web.test.ts` 各钉一条。
