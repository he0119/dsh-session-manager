# Agent Note: 预演表的动作列只放动作，整句留给 title 与「这次不动」那一节

Status: implemented

## Problem

同步预演的两张表（会拉下来 / 会推上去）沿用了导入预演那张表的动作列：`.dsm-planTable .dsm-colAction`
声明 60px，`table-layout: fixed` 下内容区只有 60 − 16（单元格左右各 8px padding）= 44px。导入预演往
那一列放的是两个字的标签（「新建」「跳过」），而同步预演放的是整句：

- zh「本机有、远端没有」实测 110px（en `here, not on the remote` 158px），
- 「本机更新，重推刷新」实测 122px（en `local is ahead, re-uploaded` 176px）。

`.dsm-tag` 是 `white-space: nowrap` 的小块（这一条本身是有理由的，见
[只走 token 的颜色](2026-09-27-token-only-colors.md)），于是标签直接画到右边那一格上：实测顶出格子
114px、压住会话名 98px。现象是"动作列的字显示不全"，实际被盖掉的是邻居那一列的会话标题——两列的字
叠在一起，谁也没读全。

## Decision

那一列只放**动作**，一句"为什么"分两处放：

- 可见文字换成三颗短标签（`syncTagPull` / `syncTagPush` / `syncTagRepush`）：zh「拉下来 / 推上去 /
  重推刷新」（实测最宽 62px）、en `Pull / Push / Re-push`（最宽 63px）。
- 整句挂在标签的 `title` 上（`syncCodeMissingPull` / `syncCodeMissingPush` / `syncCodeLocalAhead`），
  悬停看得到；「两边都有、这次不动」那一节照旧用整句（那里是整行说明，不是窄列）。

列宽按"列宽是设计，不该由内容的字数决定"的既有口径分开量：同步那两张表自己一条
`.dsm-syncPlanTable .dsm-colAction { width: 88px }`（内容区 72px，装得下最宽的那颗 63px 还有 9px
余量），导入预演那张表仍留 60px——「新建」「跳过」用不上更宽。

再加一条兜底：预演表里的标签 `box-sizing: border-box` + `max-width: 100%` + `overflow: hidden` +
`text-overflow: ellipsis`。列宽是设计、标签长短是文案，两者对不上时宁可让这一格自己截断，也不要把
邻居压掉一半（`border-box` 是必须的：默认 content-box 下 `max-width` 只管文字那一层，左右 6px
padding 与 2px 边框照样多顶出去 14px）。

## Alternatives considered

**把列宽加到装得下整句。** en 那句要 158px，加单元格 padding 是 174px，会话那一列（吃掉剩余宽度）
要少 114px —— 为一句已经写在标题里、而且每行都一样的话，把会话名的宽度让出去，不划算。

**让动作列的标签折行。** `.dsm-tag` 的 nowrap 是量出来的：折行会把行高从 51px 顶到两行，中文还会从
词中间断开（「本机有、远」/「端没有」）。标签是方块，不是一句话。

**可见文字只留一个字（「拉」「推」），整句放 title。** 两个字太含糊：推表里"新推"与"本机领先要重推"
是两件不同的事，而这两件事恰好是那一列唯一的用处。

**取消动作列，改成整行说明（像「这次不动」那一节）。** 同步一次动辄几十上百条，一行一条会把表格的
密度换成几十行段落；预演的价值正是"一眼看完会动哪些"。

## Consequences

- 两种语言都装得下：真机（dev GUI）量到可见标签的右缘停在格子内容边界以内（zh「推上去」−22px、
  en `Push` −29px），离下一列的会话名还有 38 / 45px；行高与列数不变（88 / 239 / 139 / 68）。
- 会话那一列窄了 28px（267 → 239px）。它本来就带省略号、每行显示标题或 id，这一档不改变可读性。
- 整句仍读得到：悬停有 `title`，「这次不动」那一节照旧逐条给整句。`title` 是**看不见的文案**（键盘
  与读屏都取不到），所以"必须有"的信息一条都不放那里——那三句"为什么"在 kept 一节里都有，动作列的
  可见文字本身就是那句动作。
- 兜底是**给将来**的：现在的文案都在 72px 以内、一个都没被截断（真机量过 `clipped: false`）。将来谁
  再往那一列塞整句，会在自己那一格里截断（实测塞进 110px 的整句时标签停在边界上、文字截断），而不是
  压住邻居。
- 验证：`test/styles.test.mjs` 钉住同步表的列宽 ≥79px（= 最宽的标签 63px + 单元格 padding 16px，
  这是量出来的下界而不是抄一个数）与兜底那三条声明；`test/client.test.mjs` 钉住三颗标签的可见文案、
  变体类 `dsm-syncPlanTable`（列宽那条规则的选择器）与 `title` 上的整句，并钉住整句不再出现在动作列
  里。七处篡改各自红在对应断言上：把整句放回标签（拉表那一颗、推表那颗「重推刷新」）、表上不再带
  变体类、标签去掉 `title`、列宽退回 60px、兜底去掉限宽、兜底去掉截断。
