# Agent Note: 同步跑着时点状态栏那一格，看到的是进度而不是「上次同步」

Status: implemented

## Problem

底部状态栏那格「同步中 3/7」说的是"这一趟正跑到第几条"，可点开它进的同步弹窗却停在**面板段**：
正文是「上次同步 · 3 分钟前 · 拉取 0 条、推送 0 条」和几句说明，底栏的「同步」还按不动（因为那一趟
在跑，`applying` 把它禁了），正在跑的那一趟一条字都没有。用户能看到的只有"在跑"这个事实，看不到
它在做什么、跑到哪、卡没卡。

原因在 `SyncPanel` 把"摆哪一段"算成了 `dialog === null ? 'idle' : dialog`：`dialog` 只记**这一页
自己**走到哪（点「同步」→ 计划、按「确认同步」→ 落地）。点状态栏那一格只是把弹窗打开，`dialog` 还是
`null`，于是摆面板段——而那一趟可能是这一页发起后转到后台的，也可能是刷新之前、另一个标签页里发起的
（认领来的）。实测（2026-11-14，web-dev 实例 + 本地 WebDAV 夹具）：状态栏写着「同步中…」，点进去只有
上次的结论；把远端每个请求拖慢之后，拉取那一段在弹窗里同样一条进度都不出现。

设计文档本来就写着那一格点开"字节、正在处理的那条会话、失败原因都在那一面里说"，所以这是实现没跟上
规格。

## Decision

「摆哪一段」改成两个输入一起判：这一页自己的意图（`dialog`）与宿主那边跑没跑（`job.running`）。
规则抽成纯函数 `syncStage(local, running)`（`src/client/logic/syncStage.ts`）：

- `local` 非空就跟它走——这一页正在算计划，不能被后台那一趟拽走（那是用户当下在看的东西）；
- `local` 为空而 `running` 为真：直接摆落地段，进度块就在那里；
- 两者都没有：面板段。

跑完之后 `running` 归零，落地段自然回到面板段：这一页发起的拿 `takeResult()` 的结论说一句，认领来的
用 `done.adopted` 那句「后台同步结束：拉取 X 条、推送 Y 条」。认领来的那一趟没有逐条事件（宿主只留
"跑没跑、搬了几条"），落地段因此不画一条不会动的进度条，改说 `sync.background.adopted` 那句
"这一页看不到逐条进度，跑完会补上条数"。

## Alternatives considered

- **留在面板段，在顶上叠一条进度横幅**：与「三段」的形状打架——同一条进度会同时出现在面板段横幅与
  落地段；底栏那枚禁用的「同步」也还是没有解释，得再补一句话。
- **在 `useEffect` 里把 `dialog` 置成 `'apply'`**：结果一样，但多一份要和"跑完了没"对齐的状态；
  派生出来就不会出现"状态说在跑、界面还停在面板段"的中间态。
- **面板段加一枚「查看进度」**：用户点状态栏那一格本来就是想看进度，再点一次是白加一步。
- **只认领来的那一趟这样处理**：这一页自己发起、转到后台的那一趟同样点不出进度，现象一模一样。

## Consequences

- 状态栏那格点开就是 `dsm-progressBlock`：那句"正在拉取 1 / 1"、进度条、当前那条会话的名字与说明；
  底栏换成「转到后台 / 同步中…」。实测截图里正是这段。
- 认领来的那一趟点开是「正在同步」+ 那句说明（没有逐条进度可画），跑完自动回到面板段并补上条数；
  不再出现"停在正在同步、按钮永远按不动"的死状态。
- 跑着时从状态栏进来，弹窗宽度跟着落地段走（1080），关掉再开还是这一段，直到那一趟结束。
- 分支判定在 `test/sync-stage.test.ts` 里逐支钉着；"跑着"这种状态在冒烟夹具里种不出来，所以只钉
  纯函数那一层（与 `test/sync-job-label.test.ts` 同一条理由）。
