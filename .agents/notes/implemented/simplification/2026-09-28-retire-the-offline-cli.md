# Agent Note: 删掉离线 CLI

Status: implemented

## Problem

迁移原本有第三个入口：离线 CLI（`src/cli.ts` → `lib/cli.js`，附 `bin`）。它带来的东西只有一件：
**DSH 没启动时也能搬会话**。

代价则是对外契约的增加：一份命令行解析与退出码约定、一个 `bin`、一个 `./cli` 导出——都是改一次就要
兼容一次的东西，还要各自跟着文档走。

## Decision

删掉这个入口。要恢复离线能力，正确的位置是**另起一个不依赖宿主进程的入口**，而不是把 CLI 塞回这个
包里。

## Alternatives considered

**留着它。** 另外两个入口各有覆盖面：工具层覆盖「让模型先预演再落盘」，设置页覆盖「人自己点着看
预演」；离线 CLI 覆盖的「DSH 没启动」是一个真实场景，但为它维护一份并行的入口契约不划算。

**把它改成只读的工具（比如只做预演）。** 那仍然是第三份要跟着编排层改的调用面，只是少了一半功能；
离线预演的价值本来就低于离线执行。

**留着但现在不维护。** 对外暴露的 `bin` 会一直在那儿，使用者会依赖它，坏掉的时候是本仓库的账。

## Consequences

- 少一份命令行解析、退出码约定与文档；包的对外面只剩工具与 HTTP 端点两条。
- 离线搬会话从「本包的一个子命令」变成「另起一个入口」，这是一条有意留白的方向，不是遗漏。
- 这条删除是破坏性改动，提交里标了 `!`（`db5777f`）。
