# Agent Note: 行尾的动作撤出悬停，只留一枚给键盘的「详情」

Status: implemented

## Problem

点整行已经能打开右栏之后，鼠标划过一行仍然会浮出「详情」与「内容」两枚小字：前者与点整行是同一件
事，后者打开的完整时间线在右栏里也有一枚「打开完整内容」。于是那一格既是重复的入口，又靠一套叠格子
+ `visibility` 的机关撑着（还有一条触屏常显的退路），鼠标用户看到的是"一行上突然多出两段字"。

## Decision

- **「内容」删掉**：完整时间线只剩右栏那枚「打开完整内容」一个入口（点行 → 右栏 → 那枚按钮）。
- **悬停不再浮出动作**：那一格在鼠标划过时照旧只有时刻；要详情就点整行。
- **「详情」留着，只给键盘**：它平时 `visibility: hidden`（不进 Tab 序），Tab 落到这一行的勾选框时
  整行 `:focus-within` 让它顶掉时刻出场，再 Tab 一下够得着它。
- **触屏那条退路一起删**（`@media (hover: none)` 里让动作常显的那一段）：触屏点整行就是详情。
- 跟着收拾的：`manage.transcript.open` / `.openTip` 两个文案键从 zh / en 两份字典里删掉；右栏空态
  那句从"点行尾的「详情」"改成"点一行会话"；transcript-e2e 那个 skill 的脚本改成"点行 → 打开完整
  内容"。

## Alternatives considered

**两枚都删，只靠点整行。** 鼠标与触屏没问题，但键盘就没有任何打开详情的入口了：这一行是 `<label>`
（勾选框的无障碍名字靠它），不是可聚焦控件；Tab 落在勾选框上，回车是"勾选"不是"看详情"。

**把整行做成可聚焦的按钮（`role="button"` + `tabIndex`）。** 行里嵌着勾选框与动作按钮，`button` 里
再套交互控件不合法；`role="button"` 的子节点还会被当成装饰，屏幕阅读器把整行读成一个按钮、吞掉
勾选框。这比留一枚只给键盘的小按钮代价大得多。

**把「内容」留在悬停里，只删「详情」。** 那正是鼠标用户看到的那一段小字；而它的功能与右栏那枚重复，
只省一次点击。留下它等于没解决"这一行浮出两段字"。

**把「内容」挪到卡头当页面级工具。** 卡头那一行回答的是"这一页"，不是"这一条"；右栏与行才是这一条
的落点。

## Consequences

- 悬停时行上只有时刻（行本身有底色与指针光标提示可点），Tab 进这一行时才出现那枚「详情」。
- 键盘打开详情：Tab → 勾选框 → Tab → 「详情」→ 回车。完整时间线：点行 → 右栏 → 「打开完整内容」。
- 由 `test/client.test.mjs` 与 `test/styles.test.mjs` 钉住：行上没有 `dsm-rowInspect`、只有一枚
  `dsm-rowDetail` 且它与时刻同格；CSS 里没有 `:hover` 显形、没有 `@media (hover: none)` 的退路，
  只剩 `:focus-within`。
- 真实 dev GUI 里量到的（1600 窗口）：悬停第三行时时刻 `visibility: visible`、动作组 `hidden`、
  行里只剩 1 个按钮；勾选框获得焦点后动作组变 `visible`、时刻变 `hidden`；在「详情」上按回车，
  右栏开出那一条；点「打开完整内容」弹出时间线（80 张卡）。
