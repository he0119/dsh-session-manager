# Agent Note: 三个分页共用一份列表实现

Status: implemented

## Problem

行怎么画、勾选框怎么摆、标签挂哪几枚、列表框多高、筛选条长什么样——这些东西在三个分页里是同一件事，
而写三遍的代价已经付过两次：

- 迁移页那份 `formatTime` 收的是 ISO 串（调用处 `new Date(createdAt).toISOString()` 绕一圈，
  三份实现里只有它的容错不一样）；
- 「注册表没认领」这枚标签在三页里叫两个名字（「未登记在册」与「未分组」）。

**一处逻辑写三遍，改一处就会漏两处。**

## Decision

共用的边界划在**一行的解剖结构**与**列表的框**上，只在 `src/client/sessionList.tsx` 里写一遍。
各页自己的东西留在各页：传输页按目录分组的组头、会话页的归属那一格与删除计划、迁移页的「全部 / 子集」
单选框与备份回滚。

## Alternatives considered

**各页各写一份，靠评审保持同步。** 上面两次漂移就是这么来的，而且漂移的形态是「同一件事有两个名字」
这种不会报错的东西。

**再抽一层通用表格组件。** 三页的差别不在表格能力上，而在「列什么、能做什么」上；抽成通用组件之后
各页要传一堆开关，比现在更难读。

**只共用纯函数（格式化、分组），各页自己写 JSX。** 那正是漂移发生的位置——第二份 `formatTime` 就是
「反正是个小函数」写出来的。

## Consequences

- 三页的列表都**高度固定**（`dsm-listFixed`），并且连「一条都没筛出来」也画在框里面。
- 两页同形、一页不同形：传输页与会话页列的都是整个库，连分组与折叠都一样（会话页原先多一列「归属」，
  分组之后那一列进了组头）；迁移页列的是一次一个来源的候选，天然是平铺的。
- 各页的筛选状态与勾选集仍是**页内状态**，切到别的分页再回来会清空（分页是挂载 / 卸载的）——
  这是这一页骨架一直以来的样子，不是这次改动的取舍。
