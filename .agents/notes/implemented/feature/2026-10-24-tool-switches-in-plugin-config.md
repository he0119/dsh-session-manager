# Agent Note: 5 个模型工具各自能在插件配置里关掉

Status: implemented

## Problem

这 5 个工具以前是**无条件注册**的：只要插件装上，模型那份工具清单里就一定有它们。可是"装上这个插件"
不等于"我这儿 5 个都用得上"：

- 不用 WebDAV 的人，`sync_sessions` 永远只会回一句"没有配置"，却一直占着清单里的一格；
- `migrate_sessions` / `rollback_session_migration` / `sync_sessions` 三个只要模型决定传
  `apply: true` 就会写盘（虽然每次写之前都留字节级备份），有人希望这类动作在**装配层**就不存在，
  而不是靠提示词约束模型别去调；
- 工具清单本身就是模型上下文的一部分，用不上的工具一直摆在那里，白占位置也白增加选错的机会。

注册只发生在插件装配那一刻，所以"关掉"这件事没法在运行期做，只能在配置里表达、由装配时读。

## Decision

插件配置多一节 `tools`，5 个布尔键，一个键对一个工具：

| 键 | 工具 |
|---|---|
| `plan` | `plan_session_migration` |
| `migrate` | `migrate_sessions` |
| `rollback` | `rollback_session_migration` |
| `verify` | `verify_workspace_sessions` |
| `sync` | `sync_sessions` |

- **判据只有一条：显式写 `false` 才关。** 缺席、写 `true`、整节都不写、或者那一节里只点名了几个键，
  其余一律照旧注册（`toolsSection()` 里就是 `value.x !== false`）。这样手写的老配置升级上来行为不变，
  而"只写想关的那几个"是最省事的写法。
- **关掉等于不注册**，不是"注册了再拒绝"：`registerTools()` 里每个 `ctx.tools.register()` 前面挂着
  一个按开关的包装（`when(switches.x)`），关掉的那一支直接返回空操作。宿主那份工具清单里没有它，模型
  看不到它，连"调了被拒"这一轮都不会发生。
- **这一节不是活字段**（`ToolsConfigSchema` 不标 `.volatile()`）。注册发生在装配时，标了就等于向设置面
  承诺"改完立即生效"，而实际上得重启宿主才会按新开关重新装配。不标就不会出现在设置页那张表单上——与
  `sessionsRoot` / `registryPath` / `backupRoot` 三个路径字段同一类口径（见
  [同步配置在页面里就地可改](../architecture/2026-10-01-sync-config-is-live-in-the-page.md) 里"哪些字段
  是活的"那一段）。
- **启动日志点名**：关掉任何一个工具时，`apply()` 往日志里写一句"按配置没有注册 xxx（改完要重启才
  生效）"。配置写在文件里、界面看不见，出问题时要有个地方能查"为什么模型说没有这个工具"。
- **管道与页面不受影响**：开关只管"模型能调什么"。设置页里的迁移、导入导出、同步照旧可用，它们走
  `src/web.ts` 那几条路由，不经过 `registerTools()`。

## Alternatives considered

**一个总开关（`tools: false`）。** 最省事，但没法只关有写盘风险的那三个、保留两个只读的——而"只关
一部分"恰好是这个需求的主场景。

**按风险分两档（只读 / 写盘各一个开关）。** 5 个工具里读 2 个、写 3 个，实际想关的往往是单个工具
（比如没配远端就想关 `sync_sessions`），分组还得再解释一层"到底哪几个属于哪一档"，不如一个工具一个键
直白。

**用完整工具名当键（`migrate_sessions: false`）。** 与工具名一一对应、不用查表，但配置里读起来长，
而且和 `tools` 这个节名拼在一起更像在写代码。现在用短名，靠 `TOOL_BY_SWITCH` 这一张对照表和一条测试
（键集必须与工具名集合对上）防止"加了工具忘了开关"。

**放进设置页表单、改完立即生效。** 要在配置变更时注销再重注册工具，而容器层面这属于"插件重新装配"，
做不好会出现双份注册或半注册的中间态；收益只是少按一次重启。等真有人嫌重启麻烦再说。

**注册了再在 `execute()` 里拒绝。** 模型仍然看得到工具、仍然会去调、拿到一条报错、白费一轮；工具清单
（也就是上下文）一点没省下来，正好违背了要开关的两个理由。

## Consequences

- 配置文件多了一节不在设置页上的字段；改完要**重启 DSH** 才生效，README 与新的一节「关掉不用的工具」
  都写清了这一点。
- `tools` 里写非布尔值（`migrate: 'no'`）在装配时当场抛，不会静默当成"开"混过去。
- 5 个全关是合法配置：插件照常装配，只是模型那份清单为空；设置页与 HTTP 端点照旧。
- 加第 6 个工具时，`TOOL_BY_SWITCH`、`ToolsConfigSchema`、`toolsSection()` 三处都要跟着加一个键，
  `test/config.test.ts` 里"键集与工具名对上"那条会拦住漏加。
- 反事实（把被测行为改回去，测试必须变红）：把 `when()` 里的开关判断去掉（关掉也注册）、把
  `!== false` 改成 `=== true`（缺席当成关）、把 `tools` 从 `Config` 里摘掉（非布尔值不再当场抛）。
