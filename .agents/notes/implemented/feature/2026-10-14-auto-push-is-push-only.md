# Agent Note: 自动同步只推送，拉取永远要人看着

Status: implemented

## Problem

会话同步要在多台机器之间来回搬，而「想起来才点一次」有它自己的代价：忘了推的时候，另一台机器上看到的
是几天前的状态；等到想用另一台机器接着干活时才发现本机那些轮次压根没传上去。

把这件事自动化有一个绕不开的岔路：自动跑的那一轮**要不要也拉**。两个方向在无人在场时的风险完全不对称。

拉取那一侧有两条路径会**动本机已有内容**：远端那份领先时「先备份再顶掉本机那份」（`kind: 'replace'`），
以及两边各自写过而远端更新时同样覆盖。这是这个插件里唯一会撤掉本机已有会话的动作——界面上它前面挡着
一个确认弹窗，用户得看清"这会覆盖本机那份"才点得下去。后台跑意味着没有这个人。

推送那一侧是纯增量的：远端没有的传上去、本机领先的刷新远端、远端的独有内容一个字节都不碰。它不需要
任何人看着。

## Decision

自动推送是一个**全局节拍**（不做成每条通道一份设置），跑的那一轮**只推不拉**。

- **`planSync()` 收窄（`narrowToPushOnly()`）**：`pushOnly: true` 时拉取整表摘掉（`pull` 与 `pullIds`
  一起清空、`bytesIn` 归零），推送表只留"本机这一侧确实领先"的几类——`upload`/`missing`（远端没有）、
  `update`/`local-ahead`（远端停在旧代次，刷新是纯增量）、`update`/`local-newer`（两边各自写过而本机
  更新，刷自己那一格）、`skip`/`identical`（内容一致，留着当"这次不用动"的唯一说明）。其余 `skip` 全
  摘掉：`remote-ahead` 与 `diverged` 是拉取侧的判断，**这个方向本来就不在**，留着只会让"这次不推它"
  看起来像一次判断。摘掉的行不进 `blank`（那是空白会话专用名单）。
- **两条"目录不存在"要改写**：`planSync()` 在拉取侧算落地目录时会把"映射指到了一个不存在的目录"记进
  `problems`。只推这条路**不看落地目录**，留着它会让自动推送报一个与它无关的错、甚至按 `ok: false`
  拦住整轮，所以那一处把原文改写成"那个目录在不在不影响这次推送（只有拉取才要落地目录）"。
- **`runAutoPush()` 没有预演与确认**：一次调用算完就落地（`runSync()` 那条单次调用路），**不是**
  `syncPrepared()`——那个是"照着用户确认过的那份计划落地"，后台没有用户确认过的东西。也正因为计划里
  没有拉取，它不必问宿主"这条还活着吗"、不必备份、不写注册表、不请宿主重折投影检查点：那几件事全都挂
  在"真有东西落到本机"那条路上，纯推送自然全空。
- **没得推也要收尾**：本机删掉的会话得从**自己那一格的索引**里消失，而那一步在
  `applyPreparedSync()` 里。所以"推送表空"**不等于**"不用落地"——判据是三项：推送表空、空白名单空、
  且自己那格索引里没有本机已经没有的会话（`indexNeedsSettling()`）。三项都成立才按 `idle` 早退，
  连索引都不写。
- **节拍器每 tick 现读配置**（`createAutoPushTimer()`）：`sync` 那一节是活引用（见
  [同步配置在页面里就地可改](../architecture/2026-10-01-sync-config-is-live-in-the-page.md)），所以定时器只按
  `min(间隔, 60_000)` 的粒度醒、每次醒来看一眼当前配置。关掉/改小因此是**立刻**生效的，不必重启 DSH；
  按配置挂 `setInterval` 就得再补一套"配置变了重挂定时器"的订阅，还会在重挂的空档里漏掉一次。
  **这一层后来退成了兜底**：本机写完一轮就推由会话事件那一层负责（见
  [跟着轮次走](../architecture/2026-10-14-auto-push-follows-turn-end.md)），定时器只负责它够不到的那三类。
- **速度闸与"正在跑"由节拍器把关**：间隔毫秒（缺省 300000，下限 60000）与"一次只跑一轮"都在这一层。
  上一轮还在跑时这一轮回 `busy` **不排队**——每轮读的都是同一份"最新"，排队只会让积压的轮次一个接一个
  空跑。`busy` 那一支报的仍是**上一轮**的结论，不合成一条新的：合成会把上一轮真跑出来的结果盖掉。
- **`failures` 是连续失败计数**：`ran` 且有 `problems` 也算失败（推了一半），跑成功清零；没跑（各种
  `skip`）不动它。**`runAutoPush()` 不抛**——后台任务抛出去没人接。
- **界面那枚「立即推送一次」绕过速度闸**（`force`）：用户手点的那一次不该被"距上次才过了 20 秒"挡住。
  它只在开关开着时出现——关着时点下去必然是 `skip: 'disabled'`，等于没反应。
- **`ProgressEvent.what`**：自动推送报的每条进度都带 `what: 'auto-push'`（缺席按 `'sync'`）。界面上
  后台那条流可能与用户手点的那条同时在跑，没有这一项就分不出"正在推送 3 / 8"是谁的。手动那两条路不
  传它，行为与这一项出现之前逐字节相同。

## Alternatives considered

**自动跑照旧两个方向都做。** 这是最省事的一版（`runSync` 直接复用），但它把"覆盖本机那份"变成无人
值守的动作；那道确认弹窗挡的正是这件事，自动化绕过它等于取消那道闸。放弃"两个方向都能自动"，换来
"后台永不动本机"。

**只自动拉、不自动推。** 反了——拉取才是会动本机的那一侧，而且"本机的活推上去"也正是用户忘了做的那
件事（远端是别人的活干出来的）。

**做成每条通道一份设置**（多台远端时各推各的）。当前 `sync` 只有一节（一个远端、一个机器名），没有
"多条通道"这个对象可挂；等真的支持多远端再谈。

**把"要不要收尾索引"也交给 `idle` 那一支之外的判据**（比如按时间定期重写一次）。那样"本机删掉的会话"
在索引里留存的时长取决于运气；按集合包含判一次既准确又免费（索引本来就在预演时读回来了）。

**每 tick 造一个新的节拍器/运行时。** 那样"上一次真跑是什么时候"与"连续失败几次"这两份跨轮状态每次
都会重置，间隔闸永远算成"该跑了"——自动推送会退化成"每次有人打开页面就跑一轮"。所以节拍器每个宿主只
造一个，挂在插件生命周期上（`ctx.effect`）。

**把「立即推送一次」画成无条件可点**（关着也能点，当手动兜底）。关着时它必然回 `skip: 'disabled'`，
是个点了没反应的按钮；想要"手动推一次"的人要的是**受控的整次同步**，那由「同步」加确认弹窗负责。

**让后台那轮也走"先预演、再确认"那条两次调用的路。** 后台没有那个确认的人；而且那条路的价值是"用户
按下确认时不必重算计划"，无人在场时它只是多存一份会过期的数据。

**给只推这条路的 `takesEffect` 走 `effectOf()` 探测。** 那个探测问的是"宿主能不能接住这次的注册表
改动"，而这一轮根本没有那种改动——探出来的结果只会是一句假的重启警告（与
[重启提示只在坏消息时说话](../architecture/2026-10-06-restart-notice-up-front-and-only-on-bad-news.md)同一条口径）。
所以直接写死 `immediate`。

## Consequences

- **「自动同步」这个名字只对了一半**：它只推送。远端的独有内容、以及远端更新过的那几条，都不会自己
  下来——要拉得手动点「同步」并在弹窗里确认。README 里写清了这一点。
- **间隔与下限**：`autoPushIntervalMs` 缺省 300000（5 分钟），小于 60000 的值会被抬到下限
  （`MIN_AUTO_PUSH_INTERVAL_MS`）——填错了不报错（用户想的是"勤快点"），但也不让一个 0 把远端打爆。
  界面上那一栏留空即用缺省值。
- **`narrowToPushOnly()` 按"动作 + 码"过滤，不按关系重算**：它读的是已经算好的那张推送表。所以
  `local-newer`（分叉但本机更新）**在只推时仍然要推**——它是本机领先，把它一起摘掉会让这类会话在这条
  路上永远推不上去。判据表在 `test/auto-push.test.ts` 里逐类钉着。
- **反事实**（把被测行为改回去，测试必须变红；实测七组全部变红）：去掉 `planSync` 里那句过滤调用、
  去掉 `identical` 那个例外、去掉 `runAutoPush` 里传的 `pushOnly`、去掉速度闸、去掉 `idle` 早退、
  去掉 `indexNeedsSettling()`、去掉"目录不存在"那句改写。
- **`SyncInfo.autoPush` 只在开着时出现**（不是 `enabled: false`）：界面靠这一项决定要不要摆"自动推送
  已开"那句话，也决定要不要画那枚「立即推送一次」。
- **实测**（自检跑的）：`pnpm typecheck` / `pnpm build` / `pnpm test`（tests 561 / pass 559 /
  fail 0 / skipped 2）/ `pnpm check:package`（42 个文件）四项全绿。
- **一个既有布局的连带改动**：`test/client.test.mjs` 里"种第几个 `useState`"的偏移随 `SyncPanel` 多
  两个状态位而变（八个 null + 结论）；`test/web.test.ts`、`test/artifact.test.mjs` 里"十二条界面路由"
  跟着变成十三条。两处都补了注释说明"动这几个组件的 useState 个数或先后就要改这一行"。
- **`src/client/api.ts` 里 `download()` 的 DOM 面改成就地声明**：本文件同时被两套工程检查，而
  `tsconfig.test.json` 是 Host 侧、**没有 DOM lib**。从测试里 import 这个文件（`test/browser-auto-push.test.ts`
  引 `runAutoPushNow()`）就会把它拉进没有 DOM 的那一套，原来那三行全局 `document` 会把整个测试工程卡住。
  声明的是用到的那几个成员，不是一整套 DOM。
