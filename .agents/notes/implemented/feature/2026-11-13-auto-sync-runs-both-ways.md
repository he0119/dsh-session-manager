# Agent Note: 后台那一轮可以跑双向，但只在明确选了那一档时

Status: implemented

## Problem

后台自动那一轮原先只有一档：**只推不拉**（[自动推送只推送](2026-10-14-auto-push-is-push-only.md)）。
那条边界的理由是"拉取会动本机已有内容，那件事得有人看着"。

只推能解一半的问题。多台机器轮流干活的人遇到的另一半是：**别的机器写的那几条永远到不了本机**，除非
自己记得去点「同步」再确认一次。忘了就等于另一半工作在本机看不见——而这正是"自动化"该消掉的那部分。

麻烦在于两个方向的风险不对称：推是纯增量（远端没有的传上去），拉会覆盖本机（远端更全时先备份再顶掉
本机那份）。无人在场时做后者，一旦判据出错，丢的是本机的会话内容。

## Decision

自动那一档有**三档**（配置里是 `sync.autoPush` 与 `sync.autoSync` 两栏布尔，拍成一个 `mode`）：

- `off`：不自动跑；
- `push`：只推（原来的行为，判据一条没改）；
- `sync`：双向 + **收尾整理自己那一格**。

两栏是同一件事的强弱两档，**强的那档赢**（两个都写着时按 `sync` 走），因为升级上来的配置里
`autoPush: true` 还在，把它当"降级成只推"用是最不会预期的事。界面上它们不是两个开关，而是**一行
三选一**（关闭 / 仅推送 / 双向）：两个开关摆在一起会多出"两个都开算哪个"的中间态，还得为此加一句
"已由另一个包含"的说明。换档时只发让配置落成那一档的最小几条（选只推送就清掉 `autoSync`，反之亦然，
关闭时两栏都清），不留另一档的键——留着的话下次打开会回到旧那一档，看着像没关掉。

三处一起定的边界：

1. **覆盖允许，但有备份**：双向那一档走的是手动那条路的同一段代码（`applyPreparedSync()`），覆盖前先
   落一份 `kind: 'replace'` 备份，在「备份与回滚」里可退回；正在本机开着的会话照样跳过（`liveBlocked`）。
   也就是说"无人在场"这件事由**用户明确选的那一档**来承担，而不是由代码悄悄决定。
2. **自动整理只删确定多余的**：`planTidy()` 算出来的两种（另一格有一模一样的、已被更全的一份取代）
   会删；**孤儿包（索引里没有的包）一个不动**——索引万一坏过，它们可能是某条会话在远端的唯一副本。
   手动那枚「整理远端」照旧连孤儿一起清（人看着）。实现上是 `applyPreparedSync()` 的
   `tidyOrphans: false`。
3. **"没事干"要把整理算进去**：双向那一档即使一条都不用搬，自己那一格里可能躺着几份重复的包，那一趟
   仍然值得跑（否则那些包永远没人清）。

名字里的 push 保留：它是这条后台通道的名字（配置键 `autoPush`、路由 `/auto-push`、事件 `auto-push`）。
双向打开之后它跑的是完整的一轮——改名要动 300 多处、28 个文件，收益只是名字更顺；界面上的文案按档说，
代码里由 `AutoMode` 那一处统一解释。

## Alternatives considered

- **`autoPush` 与 `autoSync` 当两个独立开关**：两个都开着时行为要靠"谁赢"解释，而用户没法从界面看出
  来。拍成一档（强的那档赢 + 界面置灰）只留一个真值。
- **双向也不覆盖本机**（只拉本机没有的）：最保守，但它解不掉"远端更新了本机那份"这一类——而那正是
  多机轮换最常撞上的。既然用户明确选了双向、且有备份与实时跳过，覆盖是这一档该做的事。
- **自动整理连孤儿包一起删**：省空间，但索引异常时会把"唯一的副本"删掉，而这件事在后台发生、没人
  看着、事后也很难发现。
- **给自动那一档加"间隔"旋钮**：什么时候跑由"本机写完一轮 + 安静 5 分钟"决定（见
  [等安静之后再跑](../bug-fix/2026-10-22-auto-push-waits-for-quiet.md)），多一个周期只会多一种"为什么
  没跑"的解释。

## Consequences

- 后台会改本机了：代价是"一觉醒来本机某几条会话被远端那份顶掉"。后悔面是备份（每次覆盖一份）与
  正在开着的会话跳过。
- 一轮双向比只推重：除了上传，还要读远端索引、比对内容、可能拉包写盘、最后整理。安静窗口（5 分钟）
  与"上一轮还在跑就让开"（`skip: 'busy'`）都没改。
- `/meta` 的 `sync.autoPush` 多了 `mode`；`/auto-push` 的结论多了 `pulledCount`，`takesEffect` 不再
  写死 `immediate`（双向真的会写注册表，按宿主能力说话）。
- 配置多一个 `autoSync` 布尔。旧配置（只有 `autoPush: true`）行为不变（界面上读成"仅推送"）。
- 设置表单里"自动"从一枚开关变成一枚三选一的分段控件（官方 `SegmentedControl`）；那一行下面的说明跟着
  当前那一档换。
