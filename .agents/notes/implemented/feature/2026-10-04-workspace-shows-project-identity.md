# Agent Note: 工作区组头只摆名字与一枚主机标签，项目身份与本机路径进悬浮提示

Status: implemented

## Problem

界面上凡是"一个目录"的地方，能显示的只有**本机绝对路径**（未登记目录拿它当组名，登记过的目录把它放在
标题旁边）：`/home/uy_sun/dev/dsh-session-manager`、`/opt/work/proj`。

路径是**机器特有**的。同一个项目在两台机器上可以落在完全不同的目录里（这正是同步要解决的第一件事，
见[跨机器的项目身份是 git remote](2026-10-01-project-identity-is-the-git-remote.md)），而插件已经有了
一个机器无关的名字——那篇笔记定下来的项目身份 `host/owner/repo`。用户在界面上看到的却是那条与项目无关
的路径：同一屏里两个目录谁是谁只能靠读绝对路径，跨机器对照（"我这边这条会话属于哪个项目"）更是无从
谈起。

把身份直接印在组头上再试一次，会撞上另两件事：**身份比路径还长**（`git.hehome.xyz/hehome/smart-home-deploy`
39 字符对 `/home/uy_sun/dev/smart-home-deploy` 32 字符），一长就被省略号截断，而**截断到一半的身份比不
显示还难认**；它占的还是名字与右侧那两串数字之间的宽度。这个信息（"是哪个仓库、在本机哪个目录"）是
**想知道才看**的那一类，不是每一眼都要读的。

可整条撤掉又走到另一个极端：**哪些目录是认得出身份的仓库，一眼看不出来了**——要逐个悬浮才知道。少了
这个记号，列表里"这个本机目录在别的机器上也认得出来"（同步能不能自己落地）就完全不可见。

## Decision

组头上**只摆一个名字**，项目身份与本机路径一起进那一格的**悬浮提示**（两行：身份在上、本机路径在下）。

- 名字取人认得的那一个：注册表里的**工作区标题**优先（用户自己起的名字），没有标题才退到**项目名**
  （身份最后一段）。未登记目录原来拿整条本机路径当名字——有身份就换掉它，机器特有的绝对路径对认项目
  没有帮助；没有身份则照旧显示路径（那时它是唯一的名字）。
- 名字后面挂一枚**主机名标签**（`github.com`、`git.hehome.xyz`）：它就是那个"看得见的记号"——扫一眼
  就知道哪些目录认得出身份，不必逐个悬浮。只挂主机名而不是整条身份：整条又长又会被截断（那正是它从
  这一行撤下来的原因），而"这枚标签说的是哪个远端"由标签自己的悬浮提示给全。行高压到 18px，与 14px
  的名字（行高 20px）一样高——不然挂了标签的组头比没挂的高 2px（量到 39 vs 38px），同一列组头下沿
  参差。
- **悬浮提示**是组头上唯一还看得见身份与本机路径的地方。两行一起给：身份是跨机器认得出来的名字，本机
  路径是同一个仓库在本机的两个克隆之间唯一的分辨依据。
- **下拉框照旧两个都摆在文本里**（`identity — 路径`）。这一处与组头**刻意不同**：`<option>` 没有悬浮
  提示，路径一旦不在文本里就彻底看不见，而迁移恰恰要在"同一个仓库的两个克隆"之间选一个。
- 没有 cwd 的那一组照旧用自己的文案（它不是一个目录）；认不出身份的目录名字与提示都只剩路径。
- **数值来源**：宿主 `GET /state` 报一栏 `repos`（目录 → 身份），认的目录就是"界面上真会出现的那些"
  ——每条会话的 cwd 加注册表里登记的工作区路径。界面只读这一栏，不自己推判据。
- **认不出来就不显示**：不是仓库、没装 git、没有 remote、目录已经不在——一律没有身份。这条与同步落地
  同一口径（读不到就当没有身份，不报错、不半途失败）。
- **进程内缓存**：`createRepoLookup()` 在插件实例里造一份，一个目录只问一次 git（认不出来也记下来）。
  `/state` 是页面的热路径（每次刷新都拉一遍），每次都为二十来个目录起 git 进程会把列一次会话拖慢。
- **称呼规则只有一份**：`planRows.projectLabel()`（组头：名字 + 悬浮提示）与 `planRows.pathLabel()`
  （下拉框那一行）。列表、同步弹窗与两个下拉框读同一份口径，同一个目录在四处长得一样。
- **右侧那两串数字自己贴右缘**：组头原来靠那段 `flex: 1 1 0` 的等宽路径占住中间，撤掉它之后让位改由
  计数块承担（`.dsm-groupCounts` 的 `margin-left: auto`），否则数字会紧贴名字、每个组头里离右缘的距离
  随名字长短变。

## Alternatives considered

- **身份留在组头上（只把路径退到提示里）**：这是同一件改动的前一版。量下来身份的可见部分常被截断成
  `github.com/he0119/dsh-sessi…`，而它正是这份信息里最不该被截断的那一段；名字与计数也被它挤窄。
- **不挂标签，只留名字**：最安静，但"哪些目录认得出身份"就只剩悬浮才知道——那是这一栏里唯一能一眼
  判断"这边同步能不能自己落地"的记号。
- **标签里放整条身份**（`github.com/he0119/dsh-session-manager`）：等于把刚撤下来的那串字换个样子放
  回去，长身份照样被截断；主机名已经回答了"哪个远端"，剩下的由标签与名字的悬浮提示给全。
- **标签只放一个图形标记**（git 图标之类）：更短，但图标要说清"这是远端仓库"得贴一层悬浮提示，而
  `github.com` / `git.hehome.xyz` 这几个字顺带告诉人**它在哪个站上**——自建 git 与 GitHub 混在一起时
  这一点有信息量。
- **组头分两行**（名字一行、身份一行）：一行 33px 的组头会变成两行 50px+，几十个组的列表长度翻倍；而
  这个信息只在"想知道"时才需要。
- **名字始终用仓库名**（登记过的也用）：注册表标题是用户自己起的名字（"测试项目"），比仓库名更贴近他
  心里的那个项目。身份只补上"它其实是哪个仓库"，不取代它。
- **下拉框里只显示身份**：`<select>` 没有悬浮提示，路径会彻底看不见——同一个仓库在本机克隆两份时两个
  候选长得一模一样，而迁移恰恰是要在这两者之间选一个。
- **把身份写进每条会话**（而不是 `/state` 一栏 `repos`）：同一个目录的几十条会话会把同一串 URL 重复
  几十遍，而这个值只跟目录有关。
- **不缓存，每次 `/state` 现问**：诚实（改了 remote 立刻反映），但页面的热路径上每次多二十来个 git
  进程；而这一栏只是"它叫什么"，不值得为它拖慢列会话。
- **缓存带 TTL / 按 `.git/config` 的 mtime 失效**：多一层时间语义与一次 stat，换来的只是"改完 remote
  不必重启"——同步落地那条路本来就不复用这份缓存（它每次现读），落到哪儿永远是对的。
- **身份做成可点的链接**：`host/owner/repo` 不带协议，补一个 `https://` 是**猜**（自建 git、SSH-only 的
  host 未必有 Web 页），界面不该给一个点了打不开的东西。显示即可。

## Consequences

- 组头一行里只剩一个名字加一枚主机名标签：列表更安静，名字与右侧计数都不再被机器字符串挤，而"哪些
  目录认得出身份"仍然一眼可见。代价是**身份与本机路径都要悬浮才看得见**——想知道"这条属于哪个仓库、
  在哪个目录"要动一下鼠标。
- 主机名会重复（同一台 GitHub 上的十个项目都挂 `github.com`）：这是刻意的——标签回答的是"哪一类"，
  不是"哪一个"，"哪一个"在名字与悬浮提示里。
- 改了仓库的 remote 之后，**悬浮提示里那一行要重启 DSH 才会刷新**（缓存是进程内的）。同步落地不受影响：
  它每次现读身份，落到哪个目录永远是对的。
- 插件在宿主进程里跑 git 的场景多了一处：`/state`（此前只有同步）。仍然只读、带 2s 超时、关掉凭据提示
  与索引锁，读不到就当没有身份。
- 同一个仓库的两个克隆**在组头上同名**（都用标题或项目名），只有悬浮提示里的路径能区分；下拉框里两者
  都带路径，不受影响。这是"名字取项目"的代价，换来的是跨机器认得出来。
- `host/owner/repo` 是同步报错里点名用的同一个字符串：悬浮提示里看到的名字与"同步为什么跳过这条"说的
  是同一件事。
- 认不出身份的那些目录（非 git 目录、裸路径 remote 等）名字与提示都只剩路径，组头读起来与改前一样。
