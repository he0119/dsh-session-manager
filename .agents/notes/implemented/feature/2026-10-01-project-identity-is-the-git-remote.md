# Agent Note: 跨机器的项目身份是 git remote

Status: implemented

## Problem

同步落地要把"别人的 cwd"换成"这台机器的目录"。拿 cwd 当键（配置里的 `sync.mapping`）时，键是
**机器特有**的绝对路径，于是：

- 配置必然每台机器一份：`/home/alice/dev/proj` 与 `/opt/work/proj` 得各写一行，装第三台机器就再写
  一行。想多机共用一份配置（同一段 `sync` 块）做不到。
- 两台机器路径**相同**时也要写一条自己到自己的映射，否则预演里全是「没配映射」——因为口径是"没配
  映射就跳过"，不猜。

需要的是一个**机器无关**的项目身份：两台机器凭什么认定"这两个目录是同一个项目"。

## Decision

身份取**仓库的 git remote**，规范化成 `host/owner/repo`；索引里每条会话多记两个字段：身份 `repo` 与
会话 cwd 在仓库根之下的相对路径 `repoPath`（POSIX 分隔符，仓库根是 `.`）。落地顺序：

1. **显式映射优先**（用户配了就算数，不会因为"本机恰好也有这个仓库"而改道）；
2. 否则用身份在本机找仓库根，落 `根 + repoPath`；
3. 都没有就跳过（`no-mapping`），理由里**点名仓库**，用户据此知道该在本机打开哪个项目。

落地目录在写进注册表与 header 之前还要归一成宿主存的那个拼写（git 给的正斜杠、手输的结尾分隔符与
大小写都算另一种拼写），见[落地目录要写成宿主存的那个拼写](../bug-fix/2026-10-04-landing-directory-is-the-hosts-spelling.md)。

- **为什么是 remote 而不是目录名 / 仓库名**：目录名是各人自己起的，仓库名会重复；remote 是仓库自己的
  名字，克隆到哪儿都一样。两台机器把同一个仓库克隆成不同名字的目录照样对得上；反过来，两台机器上同名
  的目录若是两个仓库，也不会被认成同一个项目。
- **为什么记相对路径**：会话的 cwd 常常在仓库的子目录里（`packages/web`）。只记身份的话，落地只能落到
  仓库根——把会话记到一个它从未运行过的目录。相对路径让"结构化一致"这件事跨机器成立。
- **本机怎么认**：候选目录取**会话的 cwd** 与**注册表里登记的工作区路径**（去重、排序），逐个问
  `git rev-parse --show-toplevel` 与 `remote.origin.url`，同一个目录只问一次，一次同步内缓存；远端
  一条带身份的条目都没有时整段跳过（不白跑 git）。
- **读不到就退回老路**：没装 git、不是仓库、没有 remote、目录已经不在——一律当"没有身份"，那条会话
  按老口径（映射或跳过）处理，不报错、不半途失败。每个 git 调用都有超时（缺省 2s）。
- **凭据永不进身份**：`https://user:token@host/...` 只取 host 与路径；用户要的是把 remote 当名字，不是
  把令牌写到共享的 WebDAV 上。认不出来的形状（`file://`、裸路径、与自己同机的 git 目录）原样退回，
  但仍然去掉凭据。
- **索引只加字段、不加版本号**：新字段可选，老索引读回来就是"没有身份"，按映射或跳过处理；老版本插件
  读到新索引会忽略这两个字段（它只读自己认识的键）。

配置因此可以字面一样：`url` 相同、`machineId` 缺省取主机名、`mapping` 留空。`mapping` 与身份**共存**
而不是互相取代——它是显式覆盖，也是没有 remote 的项目（非 git 目录）唯一的路。

## Alternatives considered

- **项目名绑定**（配置里 `projects: { 项目名: 本机目录 }`）：也能让键空间跨机一致，但要求每台机器都把
  项目名抄一遍（名字谁起、撞名怎么办都要约定），而且推送的那一侧得先把"这条会话属于哪个项目"定下来。
  身份从 remote 自动读出来就没有这一步。
- **相对 home 的根**（各机都挂在 `~/dev/<repo>`，只配一个根）：真零配置，但只对结构一致的项目有效，
  且拼错会落到一个不存在的地方（现在要靠"目标目录必须存在"兜）。
- **把工作区注册表里的 uuid 当身份**：那是每台机器自己生成的，跨机不成立。
- **按目录名匹配**：`~/dev/foo` 与 `~/work/foo` 会被认成同一个项目——同名不同仓库是很常见的。
- **升级索引 `version`**：新增可选字段不需要；升版本会让老插件直接拒绝读新索引，代价大于收益。

## Consequences

- **新机器上要先让项目出现过一次**（在 DSH 里打开过那个项目，或拉着它的会话）：候选目录就是这两处。
  本机完全没有这个项目时只能跳过——但那种情况下也确实没有可写的目录。预演会点名仓库。
- 项目在各机上的目录**结构**要一致（会话在 `packages/web` 里跑过，本机那个克隆也得有 `packages/web`）；
  没有就按"目标目录不存在"跳过，不会硬塞。
- remote 改名（或换到另一个 fork）就是换了一个身份：老条目认不出来，会跳过并点名，不会静默落到错处。
- 插件因此会在宿主进程里**跑 git**：只读命令、带超时、关掉凭据提示与索引锁，读不到就当没有身份。
  这是这一版新增的运行时依赖（`src/repo.ts`）。界面显示那一路（`GET /state` 的 `repos`）另走一份带
  进程内缓存的入口，见[工作区组头只摆名字与一枚主机标签](2026-10-04-workspace-shows-project-identity.md)：
  身份从此不只服务落地，也用来在界面上称呼一个目录（组头的名字与它的悬浮提示）。
