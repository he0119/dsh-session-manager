# Agent Note: 同步关掉窗口之后接着跑，回来还看得见

Status: implemented

## Problem

同步落地是这一页最长的动作：一次整库同步要重扫本机、读远端索引、逐条走网络，真机上几十秒到几分钟。
而它的进度与结果原先挂在**同步弹窗那个组件**上：

- 弹窗里「取消」在忙碌时是**禁用**的，唯一让它消失的办法是按 Esc 或点右上角那个叉——可那一下就
  等于把进度丢了，用户只剩一句"我按过了，现在它在干什么"；
- 切到别的页签、关掉整个设置窗口，那棵组件树卸载，进度与结果一起没；
- 而宿主那一侧根本没停：客户端中途断开之后，服务端的 handler 照旧把整趟跑完（实测本机 Node：断开后
  服务端又写了 20 次全是 200，没有抛错）。也就是说用户看不到的那段时间，活儿是真的在干。

结果就是三种难受：不知道还要多久、不知道成没成、回来之后什么都没留下。

## Decision

**那一趟的状态从组件里搬到模块级**（`src/client/logic/syncJob.ts`）。组件挂不挂载都不影响它，谁渲染
谁读：

- **发起**：确认之后由 store 发请求，进度事件进 store；
- **关掉弹窗**：忙碌时那枚「取消」换成「转到后台」，按下去只是把窗口收起来；Esc / 叉同理。活儿照跑；
- **页面顶上一条横幅**（`ManagerPanel`，页签之上）：跑着的时候是进度块，跑完留一行结论——"拉取 N 条、
  推送 M 条"，或者失败的原因——直到用户按「关闭」。它挂在**页面**这一级而不是同步分页里，所以切页签、
  关掉设置再回来都还在；
- **刷新整个页面之后**：那一份内存没了，但宿主还在跑。页面打开时从面板那条连接（`GET /panel/events`
  上的 `sync` 一条）认领：说"还在跑"（并带上宿主记下的最后一条进度），之后每变一次宿主推一次，跑完
  补上"搬了几条"。

宿主那边补两件事，都是这一条路逼出来的：

1. 把"有没有一趟在跑""刚才那一趟成没成、搬了几条"报出去（现在走面板那条连接上的 `sync` 事件）。
   宿主进程内存里只留一份，重启就没了——它是给**没在听那条事件流的人**看的。
2. **同一时间只跑一趟落地**：跑着的时候第二趟直接 409。以前只有"别开两个弹窗"这种口头约束，而现在
   一趟会比发起它的页面活得久，刷新之后、另一个页签里都可能再点一次；两趟一起跑会互相踩同一份预演
   缓存、同一个远端、同一条本机日志。

结论只有一处负责说：这一页自己发起的那一趟带着完整结果，由同步分页取走（`takeResult()`，取走即清空）
说那几句细的（覆盖了几条、附件对象搬了几个、计划是不是重算的）；认领来的那一趟没有完整结果，由页面
横幅说那几条计数。两者不会同时出现。

**同一条口径也用在自动推送那一轮上**：那一轮多半是兜底定时器或事件层发起的，进度只回给发起它的那个
请求，页面这边本来什么都看不到——用户点「立即推送一次」只会吃一句"上一轮还在跑"，却看不见它在跑什么。
所以节拍器记下"正跑着的那一轮"（`AutoPushRunning`：开始时刻 + 最后一条进度，谁发起都记），并把之后
每一条进度与收尾结论推给订阅者；面板那条连接是它的订阅者，把每一条转成 `auto-push` 事件（上一轮结论
只回计数，不回整份计划）。

于是同步页不必再自己"进页面问一次、在跑才接一条流"：这一页本来就接着面板那条连接，那条连接从一开始
就带着 `auto-push` 这一半——后台那一轮不管是定时器、事件层还是别的页签发起的，横幅与「正在自动推送…」
都能一帧不落地接上，页面闲置时也不用轮询（见
[一条连接看完这一页](../architecture/2026-10-21-one-stream-for-the-whole-panel.md)）。

## Alternatives considered

- **把结果落进宿主、让界面每次打开都去取**（真正的后台任务队列）。宿主重启之后也还在，代价是多一套
  落盘格式、版本号与清理规则；而这条需求的落点只是"关掉窗口别丢"，进程内存里那两枚事实已经够用。
- **只搬状态、不加宿主的闸**。界面这一侧已经会禁用「同步」按钮了，但刷新之后、另一个页签里、以及工具层
  调用都不看那个按钮；没有闸就有两趟并发的口子，而它们动的是同一批文件。
- **关掉窗口就把请求 abort 掉**。那样"后台继续"就无从谈起——宿主那一侧其实已经跑起来了，abort 只是让
  自己看不见它，反而留下"以为停了、其实还在写"的更糟状态。
- **所有长动作都做成后台**（迁移、导入、删除、回滚）。它们的进度也在弹窗里，关掉同样会丢；但它们的
  窗口期短、并且都以"备份 + 可回滚"收尾，眼下先把最长的这一条修好，其余几个仍然在忙碌时禁用那一枚
  ——界面不假装做得到，见 `ConfirmDialog` 的 `backgroundLabel`：不给它就跟以前一样禁用。

## Consequences

- 关掉窗口之后进度在页面横幅上继续走；切页签、关设置、再打开设置都还在；跑完留一行结论。
- 刷新整个页面之后能认领到还在跑的那一趟，但没有逐条进度（只有宿主记下的最后一条）与完整结果。
- 同一时间只允许一趟落地；第二趟拿到 409，界面那一侧由 store 直接拦住，宿主那边兜底。
- 多出来的两份进程内存状态（正在跑的那一趟、最近一次的结论）各只有一条记录，宿主重启即清空。
- 进度条与横幅复用了现有的 `ProgressBlock` 与 `.dsm-banner`，没有新增样式；`test/sync-job.test.ts`
  钉 store 的七条行为，`test/web.test.ts` 钉状态端点与那道闸，`test/client.test.mjs` 钉忙碌时那枚
  按钮不再是"取消"。
- 自动推送那一轮的进度同样是"只回给发起者"，所以由节拍器把状态与之后的每条进度交给面板那条连接
  （订阅者挂在节拍器上，一个宿主一个）；`test/auto-push.test.ts` 钉"没在跑 / 跑到第几条 / 跑完留结论"
  三段与"订阅之后一条条推、退订就不再推"，`test/web.test.ts` 钉面板流上那一条的形状（结论只回计数
  不回计划）与"连接断了就退订"。
