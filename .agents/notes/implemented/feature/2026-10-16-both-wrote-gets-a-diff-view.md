# Agent Note: 两边各自写过时先看差异，这一页只读

Status: implemented

## Problem

同一个 id 在两边各自写过之后，同步的结论只有一个词：`diverged`。预演里那几条**一条都不动**，用户手上
没有任何东西能判断该留哪一份——两份日志都不小（本机 936 个文件 / 548.6 MB，平均 ~600 KB），"两边不同"
这句话没法拿来决定删哪边。

判不出谁更新的原因是具体的：索引 v3 才记 `lastActiveAt`，旧索引（v1/v2）里没有这个字段，`newerSide()`
就只能放弃判断，把决定交回给人。

## Decision

给 `diverged`、以及那几个"一份会顶掉另一份"的结论加一页**只读**比对：`GET /sync-diff` 从远端取回那一个
包，本机读自己那份，比**原始行**，界面按三段摆出来（共有的折成一句、两条尾巴各列一份）。

- **比原始行，不比解析后的事件**：日志是 JSONL，解析层会把同一件事的不同写法归一化；差异页要回答的是
  "这两份文件哪里不一样"，所以逐行比（`split('\n')` + 去掉行尾空白后比较）。
- **header 单独比，不掺进正文**：迁移落地会改写 header 里的 `cwd`（见
  [迁移那篇](../architecture/2026-09-27-migration-rewrites-three-things.md)），于是大量 `diverged` 其实事件逐条一致、
  只有 header 差一两个字段。那种情况说成一句话（"保哪一份都一样"），不能跟真分叉混起来看。
- **三类关系分得清**：`same`（含"只有 header 不同"）、`*-extends`（一边是另一边的前缀——同一条延续，
  只是写得远一点）、`forked`（共同前缀之后两边各写各的）。前两类不是分叉，界面照实说。
- **分类写在脸上，不靠一句话**：三种关系、两边、七个种类各一枚官方 `Tag`。档位取的是语义而不是
  配色——真分叉（唯一需要人做决定的那一类）落 `warning`、续写落 `info`、完全一致落最安静的 `quiet`；
  本机与远端各一档且必须不同；种类沿用内容视图那条色边的同一套意思（用户蓝、助手灰、思考更淡、
  工具琥珀、系统绿、事件无专属色）。只写一句散文说"关系"时，一屏看下去分不出哪条属于哪一类。
- **三条分类一格都不少**：两条尾巴都出块，0 条那块给一句「这半边没有多出来的」；顶部再摆三格计数
  （共同 / 本机独有 / 远端独有）。零条那半块整块不渲染时，「远端独有 0 条」这句结论是隐形的，看着像
  这半边还没查。预演三张表的头一格也叫「结论」：格里的值（拉取 / 推送 / 两边各自写过）都是结论，
  「动作」只在传输那张表里站得住。
- **只列摘要、只列前几条**：每条一行（正文首行，或 `工具名 + 入参首行`），一次最多 20 条、每条 200
  字符，剩下的报个数。把几 MB 正文搬进浏览器既慢又没必要——原文另有内容视图那一页。
- **一个字节都不写**：这条路只读本机日志、从远端 `GET` 一个包，不改本机、不改远端、不写索引，所以
  可以随手点开。裁决（留哪一份、要不要两边都留）是下一步的事。

## Alternatives considered

- **预演里就自动解决**（取更长的、取事件多的、取时间更新的）：判不出谁更新正是 `diverged` 的定义；
  拿长度或条数当判据，会把"删掉一段重写"判反。
- **比解析后的事件**：归一化恰好抹掉"文件确实不同"这件事——两份内容不同的日志可能解出同一串事件。
- **落成一条真的 Git 分支或 `parentSession`**：`parentSession` 在宿主里是**子智能体**的语义（会折进父
  会话、侧栏也隐藏它），拿它当分支会改掉会话树的意思。"落成一条新会话"是另一种形态，不在这一页里做。
- **差异整页搬进浏览器**：远端要下整包、正文几 MB，页面还得自己分页——收益只有"能看全文"，而全文已经
  有内容视图那一页。
- **两栏并排（左右对照）**：两条尾巴是各自独立的事件串，左右对齐会暗示逐行对应——看着像 diff，
  其实左边第 3 条与右边第 3 条没有关系，容易读成"这一行被那一行换掉了"。
- **只在界面上报事件条数**：知道"差 300 条"但不知道差在哪，仍然决定不了。

## Consequences

- 多一条只读端点（`GET /sync-diff`）与一页界面；预演那三张表各多一列（96px，放不放按钮由结论决定）。
- 关系判定建立在"共同前缀"上：日志被整段改写（而不是续写）时会报告成 `forked`——这是保守的方向，
  宁可让人多看一眼，也不要把两份内容不同的日志说成"只是另一边写得多"。
- 索引 v3 铺开之后，那批"旧索引缺 `lastActiveAt`"的 `diverged` 会自己消失，剩下的才是真分叉。
- 远端取包失败、本机读不出来、机器名对不上这些情况都各有状态码与整句说明；这条路**不降级成写操作**，
  失败就只是没看成。
- 两张分类表（关系 / 种类 / 两边分别落哪一档）是纯数据，放在 `src/client/logic/diffTags.ts`，
  由 `test/diff-tags.test.ts` 钉住；改档位就是改判据，会在那一层变红。
- 两边那两块与三格计数同理：`src/client/logic/diffStats.ts` 是判据（两块都在、0 条也在、三格各有
  各的数），`test/diff-stats.test.ts` 钉住。
