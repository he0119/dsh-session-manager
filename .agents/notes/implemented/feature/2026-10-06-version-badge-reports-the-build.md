# Agent Note: 右下角那枚徽标报的是哪个构建

Status: implemented

## Problem

一页界面跑起来之后，**没有任何地方能回答"这是哪个构建"**。npm 装的那份还能查版本号（`package.json`
或者插件列表），而从仓库直接把检出软链进 profile 的开发实例连这个都不成立：`0.3.1` 这个数字在两次发布
之间一动不动，改了几十行它还是它，于是"我用的是 0.3.1"指不到任何一个提交，报告一个现象时说不清是哪份
代码跑出来的。宿主外壳自己那枚 `brand.localBuild` 徽标只报 DSH 的构建（`brand.localBuild` + 构建版本），
不报插件的。

难点在于"这个构建是谁"这件事只有在**编译那一刻**才知道：`lib/` 不进版本库、发布时才现编译
（`prepublishOnly`；CI 的发布流程在打标签的那个提交上跑），运行期能读到的只有 `package.json` 里的
版本号，而**短 commit 在安装后的包里根本不存在**（tarball 没有 `.git`）。

## Decision

- **构建期把身份写进客户端产物**：`tsdown.config.ts` 用 `define` 把 `__DSM_VERSION__` /
  `__DSM_COMMIT__` / `__DSM_DIRTY__` 三个常量替换成字面量（只写在客户端那一份配置上，Host 半侧不显示
  版本）。页面渲染时读的是三个常量，**运行期不碰 git、不发请求、没有 IO**。
- **三种构建，三种自述**，判据在 [build-identity.ts](../../../../scripts/build-identity.ts)：
  - HEAD 就是 `v*` 标签指向的提交 → **发布构建**，只报版本号（标签与版本号是同一件事，再挂 hash 是噪音；
    标签落点由发布流程自己校验）；
  - 有 git 但没有标签 → **直接 build**，报版本号 + 短 commit；构建时工作区有未提交改动再挂 `-dirty`；
  - 没有 git（源码包、快照、机器上没装 git）→ 只报版本号。
- **徽标落在「会话管理」页的右下角**（`ManagerPanel` 的页脚，页面最后一个元素）：`v0.3.1` 或
  `v0.3.1 · 0b8c452`，悬浮提示用字典把那句话补全（"发布版"还是"本地构建 git …"）。字号比正文小一档、
  颜色取页内最静的那一档（`label-tertiary`，与页头说明行同一个 token），靠右对齐——它不该跟内容抢注意力。
- 文本规则（`v0.0.0` 怎么拼、`-dirty` 挂在哪）单独放在 `src/client/logic/version.ts` 这个**纯**模块里，
  读构建期常量的那一支在 `src/client/build.ts`：于是规则能被不经过构建的单元测试直接钉住，而"常量真的
  注入了"由产物用例核。

## Alternatives considered

**放在整个界面底部那条 `shell.bottom`。** 那才是字面意义上的"界面最右下角"，任何页面都看得见。落选是
因为它是个 `single` 槽：实验性的 inspector 插件也在往那里注册，而渲染器只画 `entries[0]`——两个插件同时
装时**先注册者赢，输的那个静默不显示**（不报错、不留痕）。一枚版本徽标不值得赌这个，也不该占着全应用的
一条状态位。

**运行期读 `package.json` 再跑一次 `git`。** 不用改构建。代价是每个宿主进程启动都 spawn 一个子进程
（可能还没有 git、没有仓库、超时），而 npm 装的那份本来就读不到 commit——能读到的恰好只有"仓库就在
旁边"的开发实例，付出的是所有实例的成本。

**发布包也带上 hash。** 发布产物是在打标签的提交上编译的，带上 hash 并不难。落选是因为对装机的人没有
信息量：版本号已经唯一确定那个提交，而一串短 hash 只会让"我装的是哪个版本"这个问题多一个要对照的字段。

**显示构建时间。** 时钟不代表代码：同一个提交可以构建很多次，而两次构建的代码一模一样；反过来时钟还
会被时区与机器时间骗。

**用 semver 的 build metadata（`0.3.1+3c9f1ab`）。** 形状很正，但界面上那一行会读成"版本号的一部分"，
和"发布版 vs 本地构建"这件事反而分不开；`v0.3.1 · 3c9f1ab` 一眼看得出后半截是附注。

**自己解析 `.git/HEAD` 与 `refs/`，不 spawn git。** 少一个子进程，但等于复述一份 git 的引用解析（worktree
的 `.git` 是文件、packed-refs、符号引用），它会跟着 git 漂移。

## Consequences

- 开发实例（软链进 profile 的检出）右下角是 `v0.3.1 · 0b8c452`；npm 装的那份是 `v0.3.1`——报告问题时
  前者能指到具体提交。
- `src/client/build.ts` 里那三个标识符在源码里**不存在**：只有经过 `tsdown` 的产物才能跑，直接 import 它
  会 ReferenceError。所以纯规则单独放在 `logic/version.ts`，`test/version.test.ts` 不经过构建就能钉它。
- `tsconfig.test.json` 的 `include` 多了 `scripts/`：构建判据与其它源码进同一趟类型检查。
- 篡改验证（把被测行为改回去，测试必须变红）：去掉 `define` → 产物里那三个标识符原样留着，页面渲染
  当场 ReferenceError，产物用例红；去掉"HEAD 上有标签就不挂 hash"那一步 → `build-identity` 用例红；
  去掉工作区检查（永远 `dirty: false`）→ 同一文件里那条用例红。
