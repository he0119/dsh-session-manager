# Agent Note: 同步预演按项目分组

Status: implemented

## Problem

同步预演弹窗把三张表（会拉取 / 会推送 / 没动）画成三条平铺的长清单：每条会话一行，行里各带一个 `cwd`
列。一次整库同步的计划里同一个目录会连着出现十几条，于是那一列是一串重复的路径——要找"这条会话属于
哪个项目"只能逐行读，而真正要看的动作、会话名与大小挤在剩下的宽度里（拉取 / 推送两张表的路径列占 26%，
会话名那一列常常只够放一个 uuid 的开头）。

## Decision

三张表都按**项目目录**分组：组头是一条横跨整行的横幅（工作区标题 + 等宽路径 + 这一组几条），行里只
剩动作、会话名与大小。

- 分组键取**本机那个目录**：拉取取落地后的 `toCwd`，推取本机的 `cwd`。用户是从"我哪个项目要动"这个
  角度读计划的，远端那半边的路径只是"从哪儿来"。唯一的例外是**没有映射**的拉取行——本机根本没有那个
  项目可分组，退到远端的 `fromCwd` 当组头，那正是要用户补的那条映射。
- 组的次序与会话列表同一套（已登记工作区按注册表顺序 → 其余路径按路径排序 → 没有 cwd 的那一组最后），
  而且实现是共享的（`groups.orderProjectPaths()` / `groups.workspaceTitles()`）：同一个目录在两处排的
  位置必须一样。
- 组内**保持计划给的顺序**：那是宿主算出来的先后（远端索引顺序 / 本机扫描顺序），界面不再给一个顺序。
- 表结构是"一个 `<thead>` + 每个项目一个 `<tbody>`"，组头是 `<th scope="colgroup" colSpan>`：会话名与
  大小仍然对着表头那两列，列宽也只有一份。横排靠组头内层一个 flex 行，不给单元格本身换 `display`
  ——给 `<th>` 换 `display: flex` 时浏览器会补一个匿名单元格，`table-layout: fixed` 的列宽就跟着走形。
- 「这次不动」原来那一列是"路径或机器名"（`syncWhere()`）。路径去组头之后，这一列剩下的信息只有
  "另一份是谁的"：列头改成「远端机器」，值就是贡献那条远端副本的机器名。
- 拉取行原来的 cwd 列还在说"从哪改写到哪"：那句话退到会话名的悬浮提示上，**只有两端路径真的不同**
  才补一句（路径相同、或这条会话本来没有 cwd 时，它的项目就是组头那一个）。
- 会话名那一格改用 `planRows.sessionLabel()`（标题优先、没有标题退到 id、id 在提示里），不再各写一份。

## Alternatives considered

- **每个项目一张表**：会话名与大小就对着不了同一份表头（一张表只有一个 `<thead>`），列宽也会各算各的。
  组头插一行、每个项目一个 `<tbody>` 才是"同样的三列 + 分段"。
- **保留 cwd 列、只加组头**：路径在同一组里重复 n 遍，宽度还是从会话名身上扣——这正是要修的那件事。
- **分组键取远端路径**（按"从哪个项目来"分组）：与用户的读法相反；何况同一个仓库在两台机器上的路径
  不同，按它分组会把同一个项目拆开、把两个不同项目并成一组。
- **组内按会话名或大小重排**：两次预演的次序会与宿主的计划对不上，而"这一条在第几位"正是进度条按条
  报进度时用户对照的东西。
- **组头用普通 `<tr>` 塞进与行同一个 `<tbody>`**：画出来一样，但组头与它那几行的从属关系没有载体
  ——读屏要按列组解释它，`scope="colgroup"` 得有地方放。

## Consequences

- 路径这一份清单里只说一次；拉取行的"从哪来"只在悬浮提示里，且只有改写过的行才有。
- 同一个目录在列表（`.dsm-groupHead`）与弹窗（`.dsm-planGroupHead`）里长得一档：12% 兑色横幅、14px/600
  的标题、等宽次要色的路径。深浅两套主题在真实 dev GUI 里量过：浅色横幅 `srgb 0.887`（≈#e2e2e3）、
  标题 #0f1115（14.97:1）、路径 #61666b（4.59:1）；深色横幅 `srgb 0.238`（≈#3d3d3e）、标题 #f9fafb
  （10.38:1）、路径 #cfd3d6（7.20:1）。
- 会话名那一列从路径列手里拿回了宽度（同一台 dev GUI 量：弹窗表宽 592px，会推送表 88 / 436 / 68，
  没动表 122 / 316 / 154）。
- 字典里的 `noCwd` 与 `colNote` 再没有人用，随这次改动删掉（没有 cwd 的会话由组头 `noCwdGroup` 说）。
