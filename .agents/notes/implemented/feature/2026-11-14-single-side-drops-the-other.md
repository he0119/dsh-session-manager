# Agent Note: 裁决分三种：选单边就只留那一份，两份都留才落新会话

Status: implemented

## Problem

[裁决那篇](2026-10-16-adjudication-keeps-one-branches-the-other.md)本来是"挑一份当正本"：两枚按钮
「以本机这份为准」「以远端这份为准」，两种结果都是**两边都留**——落选那份落成一条新 id 的新会话，标题
带上「来自 <机器> <时刻>」。

用起来两处不对：

- 选「以本机这份为准」的人以为另一份会被丢掉（按钮就是这么读的），结果库里多出一条带来源标记的副本，
  要自己再删一次；同一对分叉比对几次，副本就攒出好几条。
- "两份都留着、只是不想自己判断谁占原来那个 id"这件事反而没法表达——要么放弃一份，要么人肉挑。

## Decision

`SyncDecision` 变成三档，界面在差异页给三枚按钮：

| 选择 | 留下什么 | 原 id 归谁 |
| --- | --- | --- |
| `keep-local`（保留本机） | 本机这份 | 本机 |
| `keep-remote`（保留远端） | 远端那份 | 远端 |
| `keep-both`（保留两份） | 两份（另一份落成新会话） | 最后活动时间更晚的那份 |

**只有 `keep-both` 才落新会话**。计划行上带一个可选的 `keepLoser: true`，落地那两段（拉取侧的落选
本机副本、推送侧的落选远端副本）只在它置位时跑；`branchSessionLog()` 本身一个字节都没改。

`keep-both` 的判据用 `newerSide()`（与本机/远端"谁更新"同一把尺子：两边活动时间取晚的那枚）。
三种退化都归本机占：

1. 比不出来（旧索引没记那枚钟、或者两边一样）；
2. 远端更晚，但它这次落不了地（缺映射、映射指到的目录不存在）；
3. 远端更晚，但这条会话正开着（宿主手里还有写句柄）。

后两种不能把行降成"不动"——那等于按了按钮什么也没发生，而且这一对会一直卡在「两边各自写过」里。本机
占 id 那份总能推上去，两份内容也都还在。

**选单边时另一份去哪**：本机这份由覆盖那一步先备份（`kind: replace`，备份区里能恢复）再顶掉；
远端那份压根不取回——它还留在原来那台机器上。两条路都没有不可恢复的删除，所以不必再加一道
「我明白」。

计划行里的说明写清"谁占了原 id、另一份去了哪、为什么是它"，界面原样当悬浮提示（覆盖行原来只看码，
现在也读这句），不再由界面按码另拼一句。

## Alternatives considered

- **只改文案、行为不动**（两枚按钮 + 那句"另一份会落成新会话，不删"）：问题不在于说得不清，而在于
  用户要的就是"选一份就只留一份"；文案改得再准也给不出这个结果。
- **加第四、第五种组合**（比如"留本机、另一份落新会话"再拆一枚）：与现有三档没有新语义，只是把
  `keepLoser` 变成按钮。
- **选单边也先落成新会话、再删掉**：等于先复制一整份日志再删除，白搬几十万字节，还多一次写盘失败
  的机会。
- **`keep-both` 时让人再指定谁占原 id**：这一档存在的意义就是"不判断"；再问一次等于退回两枚按钮。
- **远端更晚但落不了地时把行降成「不动」**：按了按钮什么也没发生，这一对下次预演还是
  「两边各自写过」。
- **选单边要勾「我明白」**：本机那份有备份、远端那份没离开那台机器，没有不可恢复的删除；每次裁决多
  一道勾选只会让人点得更快。

## Consequences

- 计划行（拉取、推送两侧）多一个可选字段 `keepLoser`；`SyncDecision` 多一个值，`POST /sync` 的裁决表
  认它。
- 界面：差异页三枚按钮（保留本机 / 保留远端 / 保留两份，都不预选）；计划表标签按
  `keepLoser` 显示「保留两份」，否则「保留本机 / 保留远端」；推送表里 `keep-local` 那一类原来落到
  "推送"的兜底，现在有自己的标签与整句。
- 「保留两份」时另一份没能落成新会话（远端那包取不到、写盘失败），这一条这一步就不推、也不覆盖本机
  那份：先落到本机才谈得上"两份都在"，失败照样逐条进 `problems`。
- 之前积下的「来自 <机器>」副本不会再自动增加：只有选「保留两份」时才会新长出一条。已经存在的那些
  可以照常在会话页删掉。
- 自动推送（只推不拉）不带 `decisions`，三档仍只在手动同步这条路上生效。
- 旧的"两边都留"口径只在 `keep-both` 这一档成立，[裁决那篇](2026-10-16-adjudication-keeps-one-branches-the-other.md)
  顶上已加一条指过来。
