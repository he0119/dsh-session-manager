# Agent Note: WebDAV 同步是运输层，只增不覆盖

Status: implemented

## Problem

同一个项目在多台机器上往往装在不同目录（`/home/alice/dev/proj` 与 `/opt/work/proj`）。会话库却不能
直接同步：库里每一条的目录名由 `projectKey(cwd)` 决定，header 里的 `cwd` 又与目录名绑死（见
[迁移是三件事同时改](../architecture/2026-09-27-migration-rewrites-three-things.md)）。把 A 机的库
拷到 B 机，header 里写的还是 A 的路径——轻则 Ungrouped，重则 `corrupt session log`。

已有的导出 / 导入能跨实例（导入会把 `cwd` 改写成目标工作区），但它是一条**人工**流程：去界面挑会话、
下载、搬文件、在另一台机器上传、选目标、预演、确认。两台以上、每天都要做的时候，这件事本身就是负担。

## Decision

远端只当**运输层**：放的是 `.dshsess` 包与一份索引，落地一律复用导入那条编排（`planImport` /
`applyImport`），由它把 `cwd` 改写成这台机器的路径。

```
<url>/dsh-session-manager/<machineId>/index.json                这台机器贡献了哪些会话
<url>/dsh-session-manager/<machineId>/<encodeSegment(id).dshsess>  一条会话一个包
```

最上面那层 `dsh-session-manager/` 是插件自己的命名空间、机器格直接放在它下面，由代码固定（为什么不靠
用户在 URL 里写，见[远端第一层是插件自己的命名空间](../architecture/2026-10-02-remote-namespace-is-the-plugins.md)）。

- **一机一格**：WebDAV 没有锁，多台机器共写一份 `index.json` 就是"后写的盖掉先写的"。每台机器只写
  自己那一格、读别人的全部（同一 id 由多台贡献时取**领先**的那份：代次是另一个的超集且共有代次内容
  一致；没有领先关系才按格子名排序取第一个，结果确定），于是不需要锁、也不需要"谁先谁后"的约定。
  只看格子名是不够的：一台机器把拉取来的会话继续写下去之后，它的格子里是更长的那份，而格子名恰好排
  在前面时别处拉到的会是旧的那份（缺最新代次，还看不出少）。
- **只增不覆盖**：库里已有同 id 的会话一律不拉取。两边都有时按代次指纹判四种关系——内容一致（不动）、
  本机严格领先（共有代次逐条一致，说明远端那份确实是本机这份的前缀 → 重推刷新）、远端领先（不动，
  报告）、两边各自写过（不动，报告）。判据是"远端那份是不是本机这份的前缀"，不是时间戳：文件的
  修改时间经不起复制，而没有共同祖先的两条日志本来就分不出谁更新（与
  [导入只跳过，不覆盖](../architecture/2026-09-27-import-skips-never-overwrites.md) 同一条口径）。
  索引里存的指纹是**与 cwd 无关**的内容哈希（把 header 的 cwd 归一成占位符再算）：落地一定会改写
  别人的 cwd（库目录名与 header 的 `cwd` 绑死），按字节比就会把拉取来的那份判成"两边各自写过"——
  报告里的理由是错的，更要紧的是它在那台机器上**继续写之后也推不回去**，新代次永远留在本机。
  cwd 是"这份会话在这台机器上落在哪儿"，不是"这是哪份会话"。
- **显式映射表**：远端 `cwd` → 本机目录，配在插件配置里。没配映射的会话跳过并列出来，**不猜**。
- **密码只放引用**：`passwordRef` 是凭据引用名（环境变量名），值由宿主 credentials 服务解析（缺席退到
  `process.env`）；引用名缺省是 `DSH_DAV_PASSWORD`，于是"直接输密码"不必先给变量起个名字。界面上的
  密码框是官方控件库那个只写控件，按「保存」把值写进宿主机凭据库（`remote.credentials` 的 `set`，
  落 `$DSH_HOME/.credentials.yaml`）——值归凭据提供方，配置只携带引用，所以配置备份、同步、截图
  都不会把密码带走，界面上那个框也永远从空白开始（没有读路径会把值送回来）。**引用名那一栏不在同步
  设置那张表单上**，只由插件配置改：卡片问的是"密码是什么"，"放在哪个名字下"是配置的事。
- **两个入口共用一份编排**：`sync_sessions` 工具与 `GET|POST /sync` 都调 `src/sync.ts` 的 `runSync()`，
  默认只预演。
- **「测试连接」是只读的一次探测**：`/sync?mode=test` 走 `testSyncConnection()`，两次 PROPFIND（资源根
  Depth 0 + 命名空间 Depth 1），结论是一个码（`ok` / `unauthenticated` / `forbidden` / `notFound` /
  `unsupported` / `unreachable` / `serverError` / `other`），句子在浏览器半侧——同一个码在两种语言里是
  两句话，宿主不该猜用户装了哪一种。401 那一类还带上"这次有没有拿到用户名、有没有拿到密码"两个事实，
  界面据此分成"没填用户名"「引用名里没有值」与"服务器不认这套"三句：处置完全不同，混成一句用户只能
  在服务器与配置之间来回猜。探测**不试写**（不 MKCOL、不 PUT）：命名空间那一次留给第一次同步。
- **远端驱动只用四种方法**（PROPFIND / GET / PUT / MKCOL）加 Basic 鉴权，实现在 `src/dav.ts`，不引
  webdav 库：多一个运行期依赖就要跟着它的安全更新与 Node 版本走。

推送的那一侧每次同步都会重写自己那格的索引，条目只描述"我这台机器现在还拿得出的会话"：本机删掉的
下一次推送就从索引里消失（远端那份包不主动删），别的机器已经取走的副本不受影响。

## Alternatives considered

**把 `sessionsRoot` 直接指到 davfs / rclone mount 上，多机共用一个库。** 除了 `projectKey(cwd)` 会按
机器路径分叉成两拨目录，宿主的写入还假设本机文件系统的原子 `rename`——网络盘上这条不成立。

**多机共写一份索引、或共用一个越来越大的包。** 无锁写就是丢更新；一个大包还会让"只拉一条"变成
"每次整包下载"，而 WebDAV 上真正贵的是往返。

**按工作区标题或 `git remote origin` 自动配对路径。** 标题重名、非 git 目录、同一个 remote 的多个
clone 都会错配，而错配的代价是把会话落到一个不是他要的目录里（还要连带改 header）。先做显式表，
缺映射时如实报告——这条留在报告里比留在猜测里便宜。

**同 id 覆盖或合并代次。** 覆盖可能用更旧的历史压掉更新的；合并两条没有共同祖先的日志会打架（事件
序号）。分叉的两份都保留，代价是同一条会话不会合流——这一条写进了 README、说明页的常见疑问与预演
输出。

**远端那份比本机旧时也覆盖它。** 那会丢掉远端已经续写、本机还缺的代次。只有"远端是本机这份的前缀"
（共有代次逐条一致）时才允许刷新。

**引一个 webdav 库。** 只用得上四种方法与一种鉴权，代码量在这里换得到（`src/dav.ts` 一个文件，含
一个宽容的多状态响应解析器）。

**在配置里再加一个 `password` 字段（`role('secret')`），让设置接缝把它脱敏。** 那条路只在"值本来就
该待在配置文档里"时成立；密码是凭据域的东西，官方口径是配置携带引用、值归凭据提供方
（[用户凭据](https://deepseek-harness.github.io/deepseek-harness/reference/subsystems/credentials)），
官方的网页搜索与 GitHub webhook 也都这么做。塞进配置等于把明文交给一份会被同步、备份、截图的文档，
还得额外指望每一层都记得脱敏。

**在同步设置那张卡片上再摆一栏"密码引用"。** 同一个配置项就有了两个编辑口（卡片里那份草稿，以及
插件配置页那份通用表单），而它几乎不需要改；官方那几个要密钥的卡片也都是"卡片只问密钥，引用名留在
配置里"（网页搜索的 `apiKeyEnv` 就不在卡片的字段表里）。代价是换引用名、或改用启动环境里的变量，
要走插件配置页——写得出来，只是不在手边。

**「测试连接」顺手 MKCOL 命名空间、甚至 PUT 一个探针文件，把写权限也验了。** 建目录倒还好（第一次
同步本来也会建），PUT 一个探针文件则要在别人的服务器上留个东西、还得指望删得掉；换来的只是把"没有
写权限"这个失败从确认那一步提前到测试那一步。只读探测的代价写进 README 与界面文案：只读共享测得出
"连得上"，到确认那一步才失败。同理，探测只报事实、不报"该改哪里"——**建议改哪里**这句话属于句子
（浏览器半侧），不属于传输层。

**把「测试连接」也做成一个模型可调的工具。** `sync_sessions` 的预演已经会在读不通时报出同一句原始
错误，模型不缺这个能力；多加一个工具就多一份要维护的 schema、描述与文档，而这条能力是给人点的。

## Consequences

- 同步是**只增**的操作：它不会让两边已有的任何一条会话变差；代价是删不掉远端、同 id 不合流——两条
  边界在 README 的「同步」一节与说明页的常见疑问里都写明了。
- `machineId` 必须每台机器唯一（缺省主机名；两台同名机器会互相盖掉对方那一格）。
- 只支持 Basic 鉴权；Digest / OAuth 之类的服务器暂时用不了。
- 密码是**只写**的：界面能写、能报"配没配"，但读不回来（这正是它不进配置的代价）。改密码就是再输一次；
  要**清掉**已存的那一个得去宿主机凭据文件里删那一条，或者把它指到另一个引用名——本页没有"清除"按钮。
- 路径映射是配置项，不是自动发现：新增一台机器或换目录时要补一行映射，否则预演里那几条会一直
  "缺映射"。
- 验证：`test/dav.test.ts` 打一个真的 WebDAV 夹具（含 401、404、405 与畸形多状态响应），
  `test/sync.test.ts` 用两台假机器跑端到端（推送、拉取、空转、重推、坏包、缺包），工具层与端点各有一条
  钉住"预演只读、apply 才落地"和"没配置时如实拒"。「测试连接」另有几条：探测恰好两次 PROPFIND、
  一个字节都不写，命名空间还没建算成功，401 / 403 / 404 / 405 / 5xx / 连不上各归一类，失败时的原始
  一句话原样带出去。
