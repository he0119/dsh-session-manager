# Agent Note: 子智能体折在父会话下面，条数也只数顶层会话

Status: implemented

## Problem

「会话」页是平铺表格，子智能体与它派它们的主会话平起平坐地各占一行。一条长会话派出十几条子智能体
之后，列表里它们与主会话混在一起排（按时间从新到旧），想找"最近那条主会话"得在一屏幕子行里翻。

卡头的「显示 210 / 1476 条」把子智能体也算进了分母：1476 读起来像"库里有这么多会话要收拾"，可其中
一大截是跟着父会话走、本来就不能单独操作的东西（勾不动、删不掉、迁不动）。分母虚高，那个数就没法
用来判断"还有多少要收拾"。

## Decision

列表把子智能体折到父会话下面（`logic/manageRows.ts` 的 `foldSubagents()`）：

- 父行标题前面挂一枚折叠标记（尖角 + 条数），**默认收起**；点它展开，子行在父行下面按层级缩进一级
  （16px）列出来，再点收起。父子那条边仍按「族」的判据走（`origin === "subagent"` 加 `parentSession`），
  分叉（有父指针、没有 origin）不折。
- **只有"父在这份清单里、而且同一个项目"才折**。父在别的项目、或者父不在这份清单里（被筛掉、被搜掉）
  时，子智能体自己当顶层：它照旧挂「子智能体」标签，父在别的项目时再挂「父在别处」的备注。这一页是
  唯一能收拾子智能体的地方（侧边栏不显示它们），折起来等于让它消失。
- **计数只数顶层会话**：左栏每个项目的条数、「全部项目」的条数、「显示 X / Y 条」的 X 与 Y、底部
  状态栏的「N 个会话」，都按顶层行数（子智能体折在父会话下面不进去；父在别处、或父不在这份清单里
  的子智能体自己占一行，照旧算）。操作面本来就只到顶层会话——子智能体勾不动、删不掉、迁不动——数字
  跟得上能操作的东西才有意义。
  当这一份全是子智能体（筛「子智能体」那一类时就是这样）改成「显示 N 条子智能体」，不拿顶层总数当分母。
  卡头不为折叠另写一句说明：那几条挂在父行的标记上，数字上少一条就是少一条，多一句话只是噪音。
- 勾选、全选、整组勾选的作用面跟着顶层行走；子智能体本来就跟着父会话走（行上的勾选框是禁用的），
  折起来不丢信息：勾父会话就等于勾它。
- 缩进只改画法：行里的勾选框、项目、大小、时间还是同一套格子，缩进挂在标题那一格上，各列对齐不变。

## Alternatives considered

**干脆把子智能体从列表里藏掉**，只在筛选条里留「子智能体」那一类。它们侧边栏不显示，这一页是唯一
点得到它们的地方；藏掉之后"这条日志出错了想单独看一眼"就只能靠搜索，等于把入口藏进一扇暗门。

**默认展开、谁嫌吵谁去收**。长会话的子智能体动辄十几条，默认展开就是本 note 开头那个问题本身。

**折叠但计数照旧**（分母仍是全库条数）。数字对不上"能单独操作的有多少条"，正是这次要修的那件事。

**只缩进、不折叠**（旧的做法，见
[子智能体缩进到父会话的下一级](../architecture/2026-09-30-subagents-indent-under-their-parent.md)）。那时列表按目录
分组，缩进只在组内生效；现在列表是平铺的，父会话可能根本不在这份清单里，缩进无处可挂。

## Consequences

- 列表一眼能看出"这棵树下还有几条"，条数也只数能单独操作的那些。
- 四个边界各有确定画法：父在别的项目（不折，挂「父在别处」）、父不在当前视图（自己当顶层）、
  孙辈（挂在子会话下面，展开父会话之后才轮到它）、分叉（普通会话，不折）。
- 折叠状态只活在这一次渲染里（换项目、改筛选不保留），不写盘：它不是设置，是"我现在想看这一棵"。
- 子智能体的日志照样在库里、照样参与同步与备份，这次只动列表怎么画、计数怎么报。
