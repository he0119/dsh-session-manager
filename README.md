# dsh-session-manager

[![](https://img.shields.io/badge/powered_by-dsh-4D6BFE?style=flat-square&logo=deepseek&logoColor=white)](https://github.com/deepseek-ai/deepseek-harness)

</div>

DSH 的会话管理插件：在侧栏的「会话管理」页里统一打理会话——搬到别的目录、导出 / 导入成 `.dshsess`
包、删除与归档，以及用 WebDAV 在多台机器之间同步。每个会写盘的动作都先给一份计划，按确认才动，动完
留一份能回退的备份。

[中文](README.md) | [English](README.en.md)

为什么要插件来做：在 DSH 里「会话属于哪个工作区」由会话日志里的工作目录（`cwd`）决定，宿主没有改
这个字段的接口，也不接受日志目录与 `cwd` 对不上的会话。手工把文件夹搬走，轻则会话掉进「未分组」，
重则加载时报 `corrupt session log`。本插件把改 `cwd`、搬目录、让宿主认下新归属这几步一起做，所以搬
完侧边栏的归属立刻是对的。

## 安装

从 npm 装（推荐）：

```bash
npx @deepseek-ai/dsh@next plugin --profile desktop add @he0119/dsh-session-manager
# 然后重启 DSH
```

开发时从本目录装（`lib/` 不入库，先构建）：

```bash
pnpm install && pnpm run build
npx @deepseek-ai/dsh@next plugin --profile desktop add /path/to/dsh-session-manager
# 然后重启 DSH
```

重启后侧栏多一枚「会话管理」图标，点开占满主栏。

本包**不支持** `github:` 形式的安装：构建放在 `prepublishOnly`，`lib/` 又不入库，git 装法拿不到
产物。宿主版本要求 0.2.x（`engines.dsh` 与两个 DSH peer 都是 `^0.2.0-rc.1`）；换到 0.3 线时要一起
改这几行。

## 打开后有哪几处入口

| 入口 | 用来做什么 |
|---|---|
| 侧栏「会话管理」 | 日常都在这里：整库一张表，勾上会话就能归档、重算名称、迁移、导出、删除；导入与备份在底部状态栏，同步在页头那枚状态按钮上 |
| 插件页的「同步」一节 | 配置 WebDAV：远端地址、机器名、账号密码、路径映射、自动同步（页头右边的「插件设置」直接跳过去） |
| 6 个模型工具 | 直接跟会话说「把这个项目的会话搬到 `~/dev/xxx`」，模型先看计划再落盘 |

页面分三块：左边是项目栏（点项目名只看它，鼠标停在项目行上会出现整组勾选，栏底是筛选胶囊），
中间是整库的平铺表格（上方是标题 / id 搜索框），右边是选中那条的详情。导入与备份在底部状态栏，
同步在页头那枚状态按钮上。

页头的「?」（说明）解释了各类会话（可见 / 子智能体 / 空白 / 已归档 / 活动中 / 未分组）和常见
疑问，看那一处就够。下面只讲最常用的几件事。

## 把会话搬到新目录

1. 在「会话管理」页勾上要搬的会话。它们可以散在不同目录里；原项目文件夹已经被删掉也没关系，勾的就是
   列表上那几条。
2. 点动作行的「迁移」，在弹窗里选目标目录。目标必须已存在，能在候选里挑，也能手输路径或去文件系统
   里选。
3. 看一眼计划：搬哪几条、落到哪个项目目录、工作区注册表会怎么变、备份落在哪里。
4. 点「确认迁移」。改写日志里的 `cwd` → 搬走会话目录 → 更新注册表并交给宿主接手，侧边栏立刻按新
   归属显示，通常不用重启。

两个限制值得先知道：

- **宿主正在用的会话搬不动**（行上带「活动中」标签）。重启 DSH 之后再迁一次，就能把剩下那几条收
  进来。
- **侧边栏看不见的会话搬不走**：空白、已归档、子智能体会被摘出去，弹窗里会说还剩几条。已归档的先
  取消归档，空白的直接删掉；子智能体跟着父会话一起迁，不能单独勾。

## 导出与导入

- **导出**：勾上会话，点「导出所选」，浏览器直接下载一个 `.dshsess`。包里是日志的原始字节，以及日志
  里引用的图片与文件对象（不带上的话换台机器打开会发现图全挂了）。勾父会话时，它下面的子智能体一起
  装进包里。
- **导入**：底部状态栏的「导入…」，选包、选目标目录，先看一份只读计划，确认才落盘；也可以直接把
  `.dshsess` 拖到页面上。导入**不覆盖**：库里已有同一个 id 的会话只跳过并列出来。

## 归档、重算名称、删除

勾上会话后，动作行里一键就能做这几件事：

- **归档 / 取消归档**：走宿主自己的归档能力，侧边栏马上跟着变，不必重启。
- **重新生成名称**：按整段对话重算标题。你手动改过名的、子智能体的、还没聊过一句话的、从没有过
  模型请求的会话会跳过，算完按「改了 / 没变 / 跳过 / 失败」分类报给你。
- **删除**：先把整个会话目录备份，再删。删错了点成功提示里的「撤销」，或者去底部状态栏的
  「备份与回滚」里恢复。还活在宿主内存里的会话要先重启 DSH 才能删。

## 多台机器之间同步

远端只放 `.dshsess` 包，拉取时把 `cwd` 改写成这台机器的路径，所以同一个项目在两台机器上装在不同
目录也能同步。配置在插件页 `dsh-session-manager` 的「同步」一节里填，也能直接写进插件配置：

```yaml
sync:
  url: https://dav.example.com/dsh        # WebDAV 地址（服务器根也行）；插件在它下面自建一层目录
  machineId: robot-a                      # 可选，缺省取主机名；两台机器别用同一个 id
  username: alice                         # 可选（Basic 认证）
  passwordRef: DSH_DAV_PASSWORD           # 可选：凭据引用名（环境变量名）
  mapping:                                # 可选：远端记下的目录 → 这台机器的目录
    /home/alice/dev/proj: /opt/work/proj
  timeoutMs: 30000                        # 可选
  autoPush: true                          # 可选：自动同步里「只推送」那一档
# autoSync: true                          # 双向那一档；与 autoPush 二选一，两个都写着按这个走
```

- **密码在表单里直接填**：存进 DSH 的凭据文件，配置文件里始终只有引用名，界面只报「已配置 /
  未配置」。
- **先点「测试连接」**：它只读探一次远端，不改远端任何东西，回一句连得上、认证过没过、地址对不对。
- **手动同步**：点页头的同步状态按钮，先看一份只读计划（会拉几条、会推几条、两边都有的那几张），
  确认才动手。远端那份更新时，先备份本机这份再替换，旧的在「备份与回滚」里能退回。
- **跑完能查到"哪条没做到"**：页头那枚状态变黄时，鼠标停上去会直接列出前几条（哪条会话、为什么），
  点开弹窗顶部那块「上次同步」能看到全部；带会话的那几条各有一枚「只看这一条」，一点就把列表筛到它。
  这份记录存在 `$DSH_HOME/dsh-session-manager/state.json` 里，重启之后还在。
- **自动同步**分三档，在表单里一行选：关闭 / 只推送 / 双向。后台那一趟在本机停手 5 分钟之后才跑，
  正在写的时候不会打断你；「只推送」一个字都不拉，要收别人的改动就手动同步或选「双向」。
- **路径不用手抄**：有 git remote 的项目靠仓库身份自动对得上，两台机器用同一份配置也行；`mapping`
  是给非 git 目录或想强制落到别处的情形用的，配了就优先按它落。

## 配置一览

| 字段 | 说明 |
|---|---|
| `sessionsRoot` / `registryPath` / `backupRoot` | 覆盖默认的会话库、工作区注册表与备份目录 |
| `sync.*` | WebDAV 同步，见上一节 |
| `tools.*` | 逐个关掉模型工具：`plan` / `migrate` / `rollback` / `verify` / `sync` / `repair`，显式写 `false` 才算关 |

`sync` 改完不用重启；`tools` 改完要重启 DSH，因为工具注册发生在插件加载那一刻。

## 模型工具

| 工具 | 写盘 | 说明 |
|---|---|---|
| `plan_session_migration` | 否 | 只读计划：会话与文件条数、目标目录、注册表变更、阻塞问题 |
| `migrate_sessions` | 需 `apply:true` | 默认预演；执行前备份，执行后自动复核 |
| `rollback_session_migration` | 是 | 按备份目录逐字节回滚 |
| `verify_workspace_sessions` | 否 | 复核某个项目目录里的日志与 header 是否一致 |
| `repair_session_paths` | 需 `apply:true` | 修日志里别的机器留下的路径（默认预演） |
| `sync_sessions` | 需 `apply:true` | 与远端同步，默认预演 |

## 还需要知道的

- 每个写盘的动作都会先留一份能逐字节还原的备份，入口在底部状态栏的「备份与回滚」。迁移留下的那份
  点「回滚」，连工作区注册表一起还原；删除与同步覆盖留下的点「恢复」。
- 迁移只改日志 header 那一帧，其余字节原样保留；会话 id 全程不变；侧边栏的标题、空白判定等元数据
  在落地之后顺手补上。
- **从另一台机器（尤其是另一种系统）搬来的会话**，落地时还会把 `working-directory/change` 里那些
  本机不认的路径跟着会话根一起改——不改的话宿主读不出来，对话页会报「历史加载失败」。已经落了地的
  那几条用模型工具 `repair_session_paths` 修（默认只预演，落地前先留字节级备份）。
- 会话删掉之后，侧边栏要等宿主重新扫描才会少掉那几行。
- 宿主没有界面（只用工具的前端）时这一页不出现，工具照常可用。
- 页面右下角写着当前是哪个构建：发布版只有版本号，本地构建多一个短 commit。
